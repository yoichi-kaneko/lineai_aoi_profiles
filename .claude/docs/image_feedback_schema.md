# 画像生成フィードバック（image_feedback）スキーマ

ユーザーが LINE 返信で寄せた画像生成へのフィードバックを、Firestore の **専用コレクション `image_feedback`** に1件ずつ蓄積します。`receiveLineMessage` Webhook が入方向テキストを振り分け、`評価` / `傾向` で始まるものをこのコレクションへ保存します。蓄積されたフィードバックは、2〜3週間サイクルのレビュー（`review_image_feedback`、柱C）でのみ読まれます。

> **なぜ専用コレクションか**: `notes` は `get_firestore_docs` が日付範囲だけで `type` 無差別に全件返すため、暁・望・小夜・帰灯・調べの各モードが毎日読み込みます。フィードバックを `notes`（`line_text`）に入れると、その夜の小夜モードがフィードバック文を「ユーザーの言葉」として画像・本文へ誤取込する副作用が出ます。読み手はレビュースキル1つだけなので、`image_feedback` に隔離します（柱A の [image_logs](image_log_schema.md) と同じ思想）。

## 振り分けと EC2 トリガーの関係

`receiveLineMessage`（`functions/src/receiveLineMessage/index.ts`）の振り分けロジック:

- テキストが `評価` / `傾向` で始まる → `image_feedback` に保存し、**`line_text` には保存しない／EC2 トリガー（`execEc2Command`）も発火させない**。
- 既存トリガー語（`下山` / `登山開始`）とは前方一致が衝突しないため安全。
- それ以外のテキストは従来どおり `line_text` として `notes` に保存し、必要に応じて EC2 トリガーを発火。

## ドキュメント形状

`notes` / `image_logs` と同じ `{ date, description, type, createdAt }` 形状を踏襲します。構造化データは **`description` に JSON 文字列**で格納します。

| フィールド    | 型        | 内容                                                                                   |
|-------------|-----------|----------------------------------------------------------------------------------------|
| date        | Timestamp | 評価対象画像の日付。`評価 <YYYY-MM-DD> ...` で明示された日付、省略時は投稿日（`startOfJstDay(event.timestamp)`）。1日1枚運用のため日付が画像との紐付け鍵。`傾向` は期間が対象のため投稿日。 |
| description | string    | 下記スキーマの JSON 文字列                                                               |
| type        | string    | `"image_feedback"` 固定（コレクション内識別用。`notes` の NOTE_TYPE とは別系統）         |
| createdAt   | Timestamp | 登録日時                                                                                |

## `description` の JSON スキーマ

```json
{
  "kind": "rating",
  "score": 4,
  "comment": "構図は好き。背景が少し寂しい",
  "target_date": "2026-06-12"
}
```

| キー          | 内容                                                                                      |
|---------------|-------------------------------------------------------------------------------------------|
| `kind`        | `"rating"`（個別評価＝`評価`）/ `"trend"`（傾向FB＝`傾向`）                                  |
| `score`       | 1〜5 の整数（`kind=rating` で抽出できたときのみ）。抽出不能や `trend` のときは `null`         |
| `comment`     | 自由コメント（先頭の日付・スコアを取り除いた残り）                                           |
| `target_date` | 評価対象画像の日付 `YYYY-MM-DD`（明示時のみ）。省略時・`trend` は `null`（`date` 側は投稿日） |

## LINE 返信フォーマット & パース仕様

パースの実体は `functions/src/receiveLineMessage/parseImageFeedback.ts`（純粋関数 `parseImageFeedback`）が正です。本ドキュメントはその仕様の要約です。

| 用途       | 書式                              | 例                                       |
|------------|-----------------------------------|------------------------------------------|
| 個別評価   | `評価 <1-5> <コメント>`            | `評価 4 構図は好き。背景が少し寂しい`      |
| 日付指定   | `評価 <YYYY-MM-DD> <1-5> <コメント>` | `評価 2026-06-12 5 ルリが可愛い`          |
| 傾向FB     | `傾向 <コメント>`                  | `傾向 最近バストアップ正面が続いている`    |

パースの方針（**寛容に扱う**）:

- 前方一致で `評価` / `傾向` を判定。トークンの区切りは**半角・全角空白いずれも可**（JS の `\s` が U+3000 を含む）。
- `評価` の場合、先頭に日付トークン（`YYYY-MM-DD`）があれば `target_date` として取り出す（任意）。続く先頭トークンが `1`〜`5` ならスコアとして取り出す（任意）。残りを `comment` とする。
- スコアが 1〜5 として解釈できないときは `score=null` とし、その文字列はコメント側に残す（フィードバックを失わない）。
- 日付省略時は投稿日に紐付け。遅延返信時のずれは既知の近似で、日付を明記すれば補正できる。

### パース例（実装の出力）

| 入力                              | kind   | score | target_date  | comment                          |
|-----------------------------------|--------|-------|--------------|----------------------------------|
| `評価 4 構図は好き。背景が少し寂しい` | rating | 4     | null         | 構図は好き。背景が少し寂しい      |
| `評価 2026-06-12 5 ルリが可愛い`   | rating | 5     | 2026-06-12   | ルリが可愛い                      |
| `傾向 最近バストアップ正面が続いている` | trend  | null  | null         | 最近バストアップ正面が続いている  |
| `評価 構図がいい`（スコア無し）    | rating | null  | null         | 構図がいい                        |
| `評価 6 範囲外スコア`（1-5外）     | rating | null  | null         | 6 範囲外スコア                    |

## デプロイ

Webhook を改修したら再デプロイが必要です（`functions/` ディレクトリで実行）。

```bash
cd functions
./deploy.sh receiveLineMessage
```

デプロイ後、実機で LINE から `評価 ...` / `傾向 ...` を返信し、`image_feedback` コレクションに1件保存されること（および `notes` の `line_text` には入らないこと）を確認してください。
