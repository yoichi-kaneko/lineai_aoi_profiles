# 画像生成フィードバック（image_feedback）スキーマ

ユーザーが LINE 返信で寄せた画像生成へのフィードバックを、Firestore の **専用コレクション `image_feedback`** に1件ずつ蓄積します。`receiveLineMessage` Webhook が入方向テキストを振り分け、`評価` / `傾向` で始まるものをこのコレクションへ保存します。蓄積されたフィードバックは、1〜3週間サイクルのレビュー（`review_image_feedback`、柱C）でのみ読まれます。

> **なぜ専用コレクションか**: `notes` は `get_firestore_docs` が日付範囲だけで `type` 無差別に全件返すため、暁・望・小夜・帰灯・調べ・響の各モードが毎日読み込みます。フィードバックを `notes`（`line_text`）に入れると、その夜の小夜モードがフィードバック文を「ユーザーの言葉」として画像・本文へ誤取込する副作用が出ます。読み手はレビュースキル1つだけなので、`image_feedback` に隔離します（柱A の [image_logs](image_log_schema.md) と同じ思想）。

## 振り分けと EC2 トリガーの関係

`receiveLineMessage`（`functions/src/receiveLineMessage/index.ts`）の振り分けロジック:

- テキストが `評価` / `傾向` で始まる → `image_feedback` に保存し、**`line_text` には保存しない／EC2 トリガー（`execEc2Command`）も発火させない**。
- テキストが `楽曲評価` / `音楽評価` で始まる → 楽曲フィードバックとして `song_feedback` に保存（同様に隔離。[song_feedback_schema.md](song_feedback_schema.md) を参照）。
- 既存トリガー語（`下山` / `登山開始` / `山小屋` / `碧衣`）とは前方一致が衝突しないため安全。
- それ以外のテキストは通常どおり `line_text` として `notes` に保存し、必要に応じて EC2 トリガーを発火。

## ドキュメント形状

`notes` / `image_logs` と同じ `{ date, description, type, createdAt }` 形状を踏襲します。構造化データは **`description` に JSON 文字列**で格納します。

| フィールド    | 型        | 内容                                                                                   |
|-------------|-----------|----------------------------------------------------------------------------------------|
| date        | Timestamp | 評価対象画像の日付。`評価 <YYYY-MM-DD> ...` で明示された日付、省略時は投稿日（`startOfJstDay(event.timestamp)`）。同じ日に複数枚ある場合の特定は `target_image_id` で行う。`傾向` は期間が対象のため投稿日。 |
| description | string    | 下記スキーマの JSON 文字列                                                               |
| type        | string    | `"image_feedback"` 固定（コレクション内識別用。`notes` の NOTE_TYPE とは別系統）         |
| createdAt   | Timestamp | 登録日時                                                                                |

## `description` の JSON スキーマ

```json
{
  "kind": "rating",
  "score": 4,
  "comment": "構図は好き。背景が少し寂しい",
  "target_date": "2026-06-12",
  "target_image_id": "night-2210"
}
```

| キー              | 内容                                                                                      |
|-------------------|-------------------------------------------------------------------------------------------|
| `kind`            | `"rating"`（個別評価＝`評価`）/ `"trend"`（傾向FB＝`傾向`）                                  |
| `score`           | 1〜5 の整数（`kind=rating` で抽出できたときのみ）。抽出不能や `trend` のときは `null`         |
| `comment`         | 自由コメント（先頭の日付・画像ID・スコアを取り除いた残り）                                    |
| `target_date`     | 評価対象画像の日付 `YYYY-MM-DD`（明示時のみ）。省略時・`trend` は `null`（`date` 側は投稿日） |
| `target_image_id` | 評価対象画像の識別子（[image_logs](image_log_schema.md) の `image_id`）。明示時のみ、省略時・`trend` は `null` |

> **楽曲フィードバックとの違い**: `target_image_id` は画像フィードバック（`image_feedback`）にだけ現れるキーです。楽曲フィードバック（`song_feedback`）の保存形式は従来どおり `kind` / `score` / `comment` / `target_date` の4キーで、`#<ID>` を書いてもコメントの一部として保存されます（[song_feedback スキーマ](song_feedback_schema.md)）。

## LINE 返信フォーマット & パース仕様

パースの実体は `functions/src/receiveLineMessage/parseImageFeedback.ts`（純粋関数 `parseImageFeedback`）が正です。本ドキュメントはその仕様の要約です。

| 用途       | 書式                                      | 例                                       |
|------------|-------------------------------------------|------------------------------------------|
| 個別評価   | `評価 <1-5> <コメント>`                    | `評価 4 構図は好き。背景が少し寂しい`      |
| 日付指定   | `評価 <YYYY-MM-DD> <1-5> <コメント>`        | `評価 2026-06-12 5 ルリが可愛い`          |
| 画像指定   | `評価 #<画像ID> <1-5> <コメント>`           | `評価 #talk-2135 5 ルリが可愛い`          |
| 日付＋画像 | `評価 <YYYY-MM-DD> #<画像ID> <1-5> <コメント>` | `評価 2026-06-12 #night-2210 4 夜がよい`  |
| 傾向FB     | `傾向 <コメント>`                          | `傾向 最近バストアップ正面が続いている`    |

パースの方針（**寛容に扱う**）:

- 前方一致で `評価` / `傾向` を判定。トークンの区切りは**半角・全角空白いずれも可**（JS の `\s` が U+3000 を含む）。
- `評価` の場合、先頭から順に、日付トークン（`YYYY-MM-DD`）を `target_date`、`#` で始まるトークンを `target_image_id`、`1`〜`5` のトークンをスコアとして取り出す（いずれも任意）。残りを `comment` とする。
- **日付と画像IDの順序は問いません**（`評価 2026-06-12 #talk-2135 4 ...` も `評価 #talk-2135 2026-06-12 4 ...` も同じ結果）。ただしどちらも**スコアより前**に置く必要があります。スコアの後に現れた `#...` はコメントの一部として残ります。
- 画像IDとして解釈するのは `#`（全角 `＃` も可）に続く英数字・ハイフン・アンダースコア1〜64文字です。日本語などを含むトークンは識別子とみなさず、コメント側に残ります。
- スコアが 1〜5 として解釈できないときは `score=null` とし、その文字列はコメント側に残す（フィードバックを失わない）。
- 日付省略時は投稿日に紐付け。遅延返信時のずれは既知の近似で、日付を明記すれば補正できる。
- **`傾向` は画像IDを取りません**（一定期間の傾向が対象のため）。`傾向 #...` と書いた場合、`#...` はコメントの一部になります。

## デプロイ

Webhook を改修したら再デプロイが必要です（`functions/` ディレクトリで実行）。

```bash
cd functions
./deploy.sh receiveLineMessage
```

デプロイ後、実機で LINE から `評価 ...` / `傾向 ...` を返信し、`image_feedback` コレクションに1件保存されること（および `notes` の `line_text` には入らないこと）を確認してください。画像IDを付けた `評価 #<画像ID> ...` についても、`target_image_id` が保存されることを確認してください。
