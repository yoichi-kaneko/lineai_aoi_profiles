# 長時間処理の実行方法（sleep・タイムアウト）

エージェント実行環境（Claude Code ハーネス等）では、長時間かかる処理を Bash ツールでフォアグラウンド実行するとブロックされることがあります。本ドキュメントは次の2つを扱います。

- **意図的な待機**（`sleep 300` など）→ 下の「長時間 sleep の実行方法」
- **意図せず時間切れになったコマンド**（Bashツールのタイムアウトでバックグラウンドへ回された）→ 末尾の「タイムアウトでバックグラウンドへ回されたコマンドの扱い」

## 長時間 sleep の実行方法

長時間（おおむね2分以上）の `sleep` が必要な場合は、以下のいずれかの方法で実行してください。

## ⚠️ 最重要：headless 実行（`claude -p`）では「背景 sleep + ウェイクアップ待ち」を使わないこと

下記「推奨：バックグラウンド実行 + 完了待ち」は、**バックグラウンド完了時にエージェントを再起動（ウェイクアップ）する対話型ハーネス**を前提とした手法です。`send_daily_line.sh` などから `claude -p` で起動される **headless モードにはウェイクアップ（再呼び出し）機構が存在しません**。

headless で「背景に `sleep` を投げてから最終テキストを出力してターンを終える」と、`claude -p` は **正常終了（exit 0）** してしまい、待機後に行うはずだったダウンロードや送信が実行されないまま **silent failure**（黙って成功扱い）に陥ります。

したがって headless 実行では、以下を厳守してください。

- **エージェント内で長時間待機しない**。長時間の待機が必要な処理は、待機をエージェントの外（呼び出し元シェルの純粋な `sleep`）へ出し、処理を「待機前」と「待機後」のフェーズに分割する設計にする。
  - 実装例: 調べモード（`modes/song.md`）は楽曲生成の完了待ちを `send_daily_line.sh` の bash `sleep` に委譲し、フェーズA（生成開始）→ シェル待機 → フェーズB（送信）の2段で実行している。
- どうしてもエージェント内で短い待機が必要な場合は、**1回のツール呼び出しで待ち切る**（背景に投げてターンを終えない）。

## 推奨：バックグラウンド実行 + 完了待ち（※対話型ハーネス限定）

> **この手法は対話型（ウェイクアップ機構あり）でのみ有効**。headless（`claude -p`）では上記のとおり使用しないこと。

- Bash ツールを `run_in_background: true` で起動し、`sleep 300` を投入する
- 返却された `bash_id` に対して `BashOutput` ツールを呼び出し、`status` が `completed` になるまでポーリングする（数十秒間隔で十分）

## 代替：until ループで分割スリープ

どうしてもフォアグラウンドで待ちたい場合は、`sleep 60` を5回ループする等、1回あたり2分未満に分割する。**この場合も背景に投げず、ツール呼び出しの中で待ち切ること。**

## 注意

**直接 `sleep 300` をフォアグラウンドで実行しないこと。**

## タイムアウトでバックグラウンドへ回されたコマンドの扱い

Bash ツールには実行時間の上限があり、超えたコマンドはバックグラウンドへ回されます。これは意図した待機ではなく事故ですが、**構造的には上の「背景 sleep + ターン終了」とまったく同じ silent failure を引き起こします**。

### 厳守事項

- **バックグラウンドへ回されたコマンドを抱えたままターンを終えないこと。** 特に headless（`claude -p`）ではウェイクアップ機構がないため、プロセス終了とともに実行中の子プロセスごと失われます。書き込みや送信であれば、完了したかどうか分からないまま記録が消えます。
- 必ず完了を確認してから次へ進んでください。対話モードでは `BashOutput` でポーリングし、`status` が `completed` になるまで待ちます。
- **時間切れを「失敗」とみなして安易に再実行しないこと。** 副作用のある操作（Firestoreへの書き込み・LINE送信・SNS投稿）では二重実行になります。種別ごとの判断は [aoi_constraints.md の「タイムアウトの扱い」](../rules/aoi_constraints.md) を正とします。

### あらかじめ長めのタイムアウトを指定する

時間がかかると分かっているコマンドは、Bash ツールの `timeout` パラメータを明示的に長めに指定してから実行してください（バックグラウンドへ回してから慌てるより確実です）。目安は次のとおりです。

| 処理 | 目安 |
|---|---|
| 画像生成（`generate_gpt_image`） | 5分 |
| `crop_yamap_report`（OCR） | 5分 |
| 楽曲・歌詞生成（`generate_mureka_*`） | 5分 |
| Firestore・各種API呼び出し | 既定のままで足りる |

なお Firestore の CLI（`get_firestore_docs` / `put_firestore_doc`）は、詰まった場合に自前で打ち切って終了コード `124` と `[TIMEOUT]` 表示を返します。この場合はバックグラウンドへは回らないため、上の確認手順ではなく `aoi_constraints.md` の分岐に従ってください。
