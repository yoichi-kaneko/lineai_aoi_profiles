# 登山予定の予報地点の決め方と引き継ぎ

予定や登山計画書から登山地点を推定して天気予報を取得するときの、**地点の決め方**と、決めた地点の**モード間での引き継ぎ**を定めます。暁・望・門灯・小夜のいずれから呼ばれる場合も本ドキュメントに従います（響モードで、依頼に地点が無く予定から推定する場合も同じです）。

同じ山の同じ日について取得地点がモードごとに揺れると、食い違う気温を伝えることになり、ユーザーに「予報が大きく変わった」と誤読されます。本ドキュメントの手順は、どのモードが実行しても同じ地点に行き着くためのものです。

依頼で地点が明示されている場合（「〇〇登山口の天気」など）は本ドキュメントを使わず、[get_openweather_forecast の SKILL.md](../skills/get_openweather_forecast/SKILL.md) の 1-0' に従ってください。ジオコーディングの実行、候補の選び方（1-1）、引き直し（1-2）、座標を得られない場合（1-4）、予報の取得と読み方は、同 SKILL.md を正とします。

## 1. 手順の全体

1. 先行モードの記録を確かめる（セクション2）。記録があれば、その座標で予報を取得します。
2. 代表とする山を決める（セクション3）。
3. 代表とした山の山名でジオコーディングする（セクション4）。
4. 特定できなければ、取得地点を切り替える（セクション5）。
5. 迷わずに決められた場合を除き、決めた地点を記録する（セクション6）。
6. 報告では、代表とした山以外の地点で取得した場合にその地点名を添える（セクション7）。

## 2. 先行モードの記録の確認（最初に行う）

地点を決める前に、同じ山行の予報地点が先行モードによって記録されていないかを、**`get_firestore_docs` スキル**で確かめます。

```bash
pnpm exec tsx src/firebase/get_docs.ts "{入山予定日}" "{入山予定日}" --type forecast_point
```

- `{入山予定日}` は、その山行の初日です（カレンダーの終日予定の `start.date`、または計画書の入山予定日）。複数日の山行の2日目以降を予報する場合も、入山予定日で引きます。
- 記録の「山行」（計画書URL、無ければ予定タイトル）が今回の山行と一致すれば、記録の「座標」でそのまま予報を取得してください（同 SKILL.md のステップ2）。ジオコーディングはやり直しません。
- 同じ山行の記録が複数ある場合は、最も早く記録されたもの（`createdAt` が最も古いもの）を採ります。
- 一致する記録が無ければ、セクション3へ進みます。計画書が差し替えられて計画書URLが変わった場合も、記録は無いものとして扱います。

## 3. 代表とする山の決め方

1. 予定や登山計画書のタイトルにピークが明記されていれば、その山です。
2. 縦走など複数の山を繋ぐ行程で、タイトルに明確なピークの記述が無い場合（複数の山が並んでいて一つに絞れない場合を含む）は、**登山計画書の移動計画（[fetch_yamap_plan](../skills/fetch_yamap_plan/SKILL.md) のチェックポイント）に並ぶ山のうち、通過順で中ほどにある山**を代表とします。
   - 数えるのは、「〜山」「〜岳」のように**名称から山と分かる地点**だけです。「白クラノ頭」のように名称だけでは山と判じにくい地点は数えません。山かどうかを厳密に判定する必要はありません。
   - 計画書の「地図」欄に並ぶ山名は、行程の順を表しません。代表は移動計画の通過順で選んでください。
   - 山が偶数個で中ほどが2つに分かれる場合は、先に通過する方を採ります。

## 4. 代表とした山のジオコーディング

- 代表とした山の山名（または山域）でジオコーディングします。これが第一候補です。カレンダーの予定（説明欄など）や登山計画書に入山口の緯度・経度が併記されていても、**それを理由に山名での検索を省かないでください**。
- 候補の選び方と引き直しは、同 SKILL.md の 1-1・1-2 に従います。登山予定の地点では、1-1 の**位置**の確認（入山口の座標・移動計画の通過順との照合）を必ず行ってください。
- 引き直しても代表とした山を特定できない場合、または代表とする山名そのものが分からない場合は、セクション5へ進みます。

## 5. 取得地点の切り替え

代表とした山を特定できない場合は、**予報を取得する地点（ランドマーク）を切り替えます**。予定や計画書のタイトルから目指すピークが分かっている場合も、同じように切り替えて構いません。

- **計画書の移動ルート上で、代表とした山に近い地点を優先します**。移動計画のチェックポイントに並ぶほかの山・峠などを、1-1・1-2 と同じ要領でジオコーディングしてください。
- **ルート上に引ける地名が見つからない場合は、山中でない地点も許容します**。入山口・下山口の駅名やバス停名などがこれに当たります。カレンダーの予定に入山口の座標が書かれていれば（書式は同 SKILL.md の 1-1）、その座標を用いて構いません。
- 切り替え先の座標も得られない場合は、同 SKILL.md の 1-4 に従ってください。

## 6. 決めた地点の記録

**代表とする山を迷わず決められ、その山名そのままのジオコーディングで目当ての山を採れた場合を除き**、決めた地点を記録してください。引き直し（1-2）や切り替え（セクション5）を経た地点は、モードごとの判断で揺れやすいためです。後続のモードはセクション2でこの記録を引き、同じ座標で予報を取得します。

- **記録の時機**: 予報を取得した直後に、**`put_firestore_doc` スキル**で記録します。手順は [aoi.md の「共通ステップ：Firestoreへの記録」](../../aoi.md) に従ってください。
- **日付**: その山行の入山予定日（セクション2と同じ）
- **type**: `forecast_point`（[noteTypes.ts](../../src/firebase/noteTypes.ts) の `NOTE_TYPE.FORECAST_POINT` と同値）
- **記録内容**: 次の形で書いてください。

```text
【予報地点】
山行: {予定タイトル}（{計画書URL。無ければ省略}）
代表とした山: {山名}
取得地点: {地点名}（{採った候補の formatted_address}）
座標: {緯度}, {経度}
経緯: {試したキーワードと、採らなかった候補の理由を簡潔に}
記録したモード: {モード名}（{実行日}）
```

- セクション2で記録を見つけて再利用した場合は、記録し直しません。
- この記録は予報地点を揃えるためだけのものです。各モードの報告や画像生成の素材にはしないでください。

## 7. 報告での地点名

**代表とした山以外の地点で取得した場合は、報告の中でその地点名を添えてください**（例:「籠坂峠の予報です」「熊渡登山口の予報です」）。山頂と峠・登山口・駅では標高差の分だけ気温が異なるため、どの地点の予報なのかが読み手に分かる必要があります。代表とした山（または山域）の座標で取得できた場合、この断りは不要です。

セクション2の記録を再利用した場合も同じです。記録の「取得地点」が「代表とした山」と異なれば、その地点名を添えてください。
