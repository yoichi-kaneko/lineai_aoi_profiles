# 小夜モードの画像テーマ抽選

小夜（`night`）モードのステップ2で、その日の画像の**主題（テーマ）＝何を描くか**を決めるための手順です。作者の自己選択による偏りを機械的に打ち消すため、候補が複数あるときは `random_choice` の抽選で決めます。

構図軸（`shot_size` / `camera_direction`）の抽選、衣装・舞台の選び方、プロンプトの書き方は [image_guideline.md](../../assets/image_guideline.md) を正とします。本ドキュメントが扱うのは**主題の選定だけ**です。

## 1. テーマ候補の作り方

その日の収集情報（写真・チェックイン・予定・Firestore記録・完了タスク）から、絵にできる情景を候補として並べます。

**候補に含めるもの**

- ユーザーから届いた `line_text` / `line_image` のうち、情景の連想が働く内容（訪れた場所・口にしたもの・目にした風景・心が動いた出来事など）。写真の無い `line_text` だけでも構いません。
- 本日の行動に紐づく素材（食事・移動・チェックイン・山行など）
- 碧衣自身のオフの日の情景（[image_guideline.md](../../assets/image_guideline.md) セクション3-1 の **活動追従しないオフ日の表現**）
- 下記セクション2の条件付き候補（綴葉代筆日／碧衣への更新があった日）

**候補に含めないもの**

- **技術・運用連絡**に当たる `line_text` / `line_image`（プロファイル修正・実装・設定変更などの連絡）。見分け方は [aoi_messaging.md の「技術・運用連絡の語り方」](../rules/aoi_messaging.md) を正とします。
- **絵にできる情景を持たない便り**（予定の変更・段取りの連絡・短い返答など）。無理に情景へ翻訳すると碧衣側の創作が主になり、ユーザー提供素材を主題に据えやすくする重み付けの趣旨から外れます。

判断基準は「情景の有無」であり「画像の有無」ではありません。候補から外した便りは、**ステップ3の報告本文で独立した話題として正面から受け取ってください**（セクション5と同じ扱い方です）。

## 2. 重みの表

候補が複数あるときは `random_choice` の **`--weighted` モード**で抽選します。重みは次のとおりで、表にない候補はすべて重み `1` として扱ってください。

| 候補の種別 | 重み | 補足 |
|---|---|---|
| `line_text` / `line_image` 由来のユーザー提供素材 | **2** | 該当する候補が複数あれば、そのそれぞれに `2` を与える |
| 綴葉代筆日の「自室で当日の登山レポートを読み解く振り返り」 | **2** | `scribe_handover` がある日のみ候補に加わる。描き方はセクション4-2 |
| 碧衣自身への更新があった日の「更新直後の兆候」 | 1 | ステップ1-2 手順5で「技術・運用連絡」に分類した完了タスクのうち、碧衣が登録したフィードバックへの対応・ユーザーの自主的なプロファイル更新などに当たるものがあった日。複数あった日も候補としては1つに束ねる。描き方はセクション4-3 |
| その他（本日の行動・オフの日の情景など） | 1 | |

- ユーザー提供素材に重み `2` を与えるのは、ユーザーが自ら寄せてくださった素材を主題に据えやすくしつつ、作者の自己選択による偏りを機械的に打ち消す抽選の仕組みも保つための配分です。
- **重み `0` は使いません**。どの候補も引かれ得る状態を保ちます。重み `2` の候補が自動的に主題に決まるわけでもありません。

## 3. 抽選の実行

選択肢の文字列に `:` を含めないでください（`:` は選択肢と重みの区切り記号です。詳細は [random_choice](../skills/random_choice/SKILL.md)）。

```bash
cd {プロジェクトルートの絶対パス}
pnpm exec tsx src/util/random_choice.ts --weighted 花の写真:2 昼のカレー:1 夜のビール:1
```

（ユーザーの花の写真・昼の食事・夜の一杯、の3候補を引く例）

## 4. 当選後の扱い

### 4-1. 時間帯・舞台は主題に従う

当選した主題が特定の時刻・場所を伴う場合（夜の店での一献、日中の外出先など）は、**その主題が示す時間帯・舞台をそのまま採ってください**。直近の日と `scene_category` / `time_of_day` が重なっても、散らすためにテーマを引き直したり時間帯をずらしたりする必要はありません。時間帯を意図的に散らすのは、主題が時刻・場所を決めない場合（碧衣自身のオフの日の情景など）に限られます（[image_guideline.md](../../assets/image_guideline.md) セクション8④の **時間帯**）。

前日の引き継ぎに情景の連続を指摘する申し送りがあった場合も、行うのは改めての抽選までで、その結果が同じ時間帯・場所になったならそのまま採用してください。

### 4-2. 綴葉代筆日の候補が当選した場合

舞台は碧衣の自室に置き、レポートの情景はホログラム・ディスプレイ・投影といった「碧衣が読み解いている表示物」として描きます。碧衣を現地（レポートの山）へ立たせないこと——縛っているのは**舞台と描き方の形式**であり、画面上の占有面積ではありません。

- 投影されたレポートの情景が画面の大きな面積を占めること自体は妨げません。碧衣を小さく配置して余白を取る構図（`wide_shot` / `full_body` を引いた場合など）も、立体地図ホログラムを大きく展開する見せ方も、[image_guideline.md](../../assets/image_guideline.md) セクション8③の **主役モチーフと碧衣の主従** / **情報表示の密度調整**（表示面は絞りつつ、主役となる一面は大きく見せてよい）に従って構いません。
- 抽選した構図軸を、この候補のために選び直す必要はありません。

### 4-3. 碧衣への更新の候補が当選した場合

「更新を受けた碧衣の身体に、一時的な変化が現れている情景」（輪郭が淡く光る／不意に身体の周辺へホログラムが浮かぶ。[aoi_character.md の「更新直後の兆候」](../rules/aoi_character.md)）を描きます。技術・運用連絡を画像の素材にしない原則（[aoi_messaging.md](../rules/aoi_messaging.md)）の唯一の例外で、連絡の**内容**ではなく**碧衣自身に起きた現象**を描くために認められるものです。

- **描くのは現象であって更新の中身ではありません**。何がどう変わったかという技術詳細は、プロンプトにも報告本文にも出しません。この候補が主題に選ばれた日の「今日の一枚」の説明も、現象の描写と「どなたかの手が入った気配」程度の言い方に留めてください。
- 舞台は碧衣の自室に置き、現象は碧衣本人に現れるものとして描いてください（`scene_category` は `home` が基本になります）。

## 5. 抽選に漏れた候補への言及

ステップ2の**テーマ選定**、またはステップ1-2の**写真の選定**で `random_choice` による抽選を行った場合は、選ばれなかった候補にもステップ3の報告本文のいずれかの箇所で軽く触れてください（例：「〜の様子とどちらを描くか、しばらく迷いました」「〜のひとときと並べて眺めていました」）。

- 目的は、ユーザーが「抽選の候補に何が挙がっていたか」を把握できるようにすることです。触れるのは候補の内容が伝わる程度の一言で足り、抽選という仕組み自体の説明や、選定理由の詳細な開示は不要です。
- **ユーザーから届いた写真・言葉（`line_text` / `line_image`）が抽選に漏れた場合**は、この軽い言及だけで済ませず、報告本文の中で独立した話題として正面から受け取ってください。
- 抽選を行わなかった場合（候補が1つしかない、主題が明らかで迷いがない場合）は、この言及は不要です。
