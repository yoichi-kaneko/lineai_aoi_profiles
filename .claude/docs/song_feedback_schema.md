# 楽曲フィードバック（song_feedback）スキーマ

ユーザーが LINE 返信で寄せた楽曲生成へのフィードバックを、Firestore の **専用コレクション `song_feedback`** に1件ずつ蓄積します。`receiveLineMessage` Webhook が入方向テキストを振り分け、`楽曲評価` / `音楽評価` で始まるものをこのコレクションへ保存します。蓄積されたフィードバックは、月次程度のサイクルのレビュー（`review_song_feedback`）でのみ読まれます。issue #71 の楽曲版フィードバック機構（柱B相当）です。

> **なぜ専用コレクションか**: `notes` は `get_firestore_docs` が日付範囲だけで `type` 無差別に全件返すため、暁・望・小夜・帰灯・調べの各モードが毎日読み込みます。フィードバックを `notes`（`line_text`）に入れると、日々のモードがフィードバック文を「ユーザーの言葉」として画像・本文へ誤取込する副作用が出ます。読み手はレビュースキル1つだけなので、`song_feedback` に隔離します（[image_feedback](image_feedback_schema.md) と同じ思想）。
>
> **トリガー語について**: `楽曲` / `音楽` 単独の前方一致では、日常の便り（例：「音楽フェスに行ってきた」）まで振り分けてしまい `line_text` から失われるため、日常文と衝突しにくい複合語 `楽曲評価` / `音楽評価` を採用しています。

## 画像側（image_feedback）との違い

- **傾向フィードバックは扱いません**（`kind` は常に `"rating"`）。楽曲側の傾向分析は、`song_logs` の機械集計（`review_song_feedback` スキル）が担います。
- 楽曲は週1生成（調べモード）のため、`date` の紐付け対象は「その曲が生成された日（= `song_logs` の `date`）」です。届いた日の翌日以降に感想を返すことも多い想定のため、レビュー時は `target_date` 明示があればその日付の `song_logs` と、なければ**投稿日以前の直近の `song_logs`** と突き合わせて解釈します。

## 振り分けと EC2 トリガーの関係

`receiveLineMessage`（`functions/src/receiveLineMessage/index.ts`）の振り分けロジック:

- テキストが `評価` / `傾向` で始まる → `image_feedback` に保存（画像側が先に判定）。
- テキストが `楽曲評価` / `音楽評価` で始まる → `song_feedback` に保存し、**`line_text` には保存しない／EC2 トリガー（`execEc2Command`）も発火させない**。
- 既存トリガー語（`下山` / `登山開始` / `山小屋`）や画像側（`評価` / `傾向`）とは前方一致が衝突しないため安全。
- それ以外のテキストは通常どおり `line_text` として `notes` に保存し、必要に応じて EC2 トリガーを発火。

## ドキュメント形状

`notes` / `image_feedback` と同じ `{ date, description, type, createdAt }` 形状を踏襲します。構造化データは **`description` に JSON 文字列**で格納します。

| フィールド    | 型        | 内容                                                                                   |
|-------------|-----------|----------------------------------------------------------------------------------------|
| date        | Timestamp | 評価対象楽曲の日付。`楽曲評価 <YYYY-MM-DD> ...` で明示された日付、省略時は投稿日（`startOfJstDay(event.timestamp)`）。 |
| description | string    | 下記スキーマの JSON 文字列                                                               |
| type        | string    | `"song_feedback"` 固定（コレクション内識別用。`notes` の NOTE_TYPE とは別系統）           |
| createdAt   | Timestamp | 登録日時                                                                                |

## `description` の JSON スキーマ

```json
{
  "kind": "rating",
  "score": 4,
  "comment": "歌詞の余韻が好き",
  "target_date": "2026-07-05"
}
```

| キー          | 内容                                                                                      |
|---------------|-------------------------------------------------------------------------------------------|
| `kind`        | `"rating"` 固定（image_feedback と形状を揃えるために保持。楽曲側に `trend` はない）          |
| `score`       | 1〜5 の整数（抽出できたときのみ）。抽出不能のときは `null`                                   |
| `comment`     | 自由コメント（先頭の日付・スコアを取り除いた残り）                                           |
| `target_date` | 評価対象楽曲の日付 `YYYY-MM-DD`（明示時のみ）。省略時は `null`（`date` 側は投稿日）          |

## LINE 返信フォーマット & パース仕様

パースの実体は `functions/src/receiveLineMessage/parseSongFeedback.ts`（純粋関数 `parseSongFeedback`。日付・スコアの抽出は `parseRating.ts` を画像側と共用）が正です。本ドキュメントはその仕様の要約です。

| 用途       | 書式                                  | 例                                         |
|------------|---------------------------------------|--------------------------------------------|
| 個別評価   | `楽曲評価 <1-5> <コメント>`             | `楽曲評価 4 歌詞の余韻が好き`                |
| 日付指定   | `楽曲評価 <YYYY-MM-DD> <1-5> <コメント>` | `楽曲評価 2026-07-05 5 サビの解放感がよい`   |

- `音楽評価` も `楽曲評価` と同義のプレフィックスとして受け付けます。

パースの方針（**寛容に扱う**）:

- 前方一致で `楽曲評価` / `音楽評価` を判定。トークンの区切りは**半角・全角空白いずれも可**（JS の `\s` が U+3000 を含む）。
- 先頭に日付トークン（`YYYY-MM-DD`）があれば `target_date` として取り出す（任意）。続く先頭トークンが `1`〜`5` ならスコアとして取り出す（任意）。残りを `comment` とする。
- スコアが 1〜5 として解釈できないときは `score=null` とし、その文字列はコメント側に残す（フィードバックを失わない）。
- 日付省略時は投稿日に紐付け。楽曲は週1生成のため投稿日と楽曲の日付はずれやすく、レビュー側で「投稿日以前の直近の `song_logs`」に紐付けて補正する。確実に紐付けたい場合は日付を明記する。

### パース例（実装の出力）

| 入力                                   | kind   | score | target_date  | comment                |
|----------------------------------------|--------|-------|--------------|------------------------|
| `楽曲評価 4 歌詞の余韻が好き`            | rating | 4     | null         | 歌詞の余韻が好き        |
| `音楽評価 2026-07-05 5 サビの解放感がよい` | rating | 5     | 2026-07-05   | サビの解放感がよい      |
| `楽曲評価 静かな曲調が沁みた`（スコア無し） | rating | null  | null         | 静かな曲調が沁みた      |
| `楽曲評価 6 範囲外スコア`（1-5外）        | rating | null  | null         | 6 範囲外スコア          |
| `音楽フェスに行ってきた`                 | （振り分けない → 通常の `line_text`） | | | |

## デプロイ

Webhook を改修したら再デプロイが必要です（`functions/` ディレクトリで実行）。

```bash
cd functions
./deploy.sh receiveLineMessage
```

デプロイ後、実機で LINE から `楽曲評価 ...` を返信し、`song_feedback` コレクションに1件保存されること（および `notes` の `line_text` には入らないこと）を確認してください。
