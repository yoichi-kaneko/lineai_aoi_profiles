# YAMAP 活動記録レポート 重点チェックガイド

## 背景

YAMAP の活動記録ページは Next.js 製で、記録データ一式がページに埋め込まれた JSON
（`__NEXT_DATA__`）として配信されています。[fetch_yamap_activity](../skills/fetch_yamap_activity/SKILL.md)
スキルは、活動記録の URL からこの埋め込みデータを読み取り、整形したテキストとして返します。

※ 以前は「ユーザーがページ全体のスクリーンショットを撮って Todoist に添付し、OCR で主要ブロックへ
切り出してから読む」運用でしたが、埋め込み JSON からの直接取得へ移行しました。
スクリーンショットの添付・OCR による切り出しはいずれも不要です。

このガイドは [綴葉モード（modes/scribe.md）](../../modes/scribe.md) のステップ3（活動記録の読み解き）から参照されます。以前は小夜モード（`modes/night.md`）から参照されていましたが、YAMAPレポートの読解は綴葉モードへ移設されました。小夜モードは、綴葉モードが `scribe_handover` として引き継いだ感想を受け取ります。

## 前提（決定済みの運用ルール）

- 活動記録は **URL から取得**する。ユーザーが Todoist のタスクに記載した
  `https://yamap.com/activities/{ID}` を `fetch_yamap_activity` へ渡す。
- Todoist への添付は **代表写真の1枚のみ**。その山行で最も印象的だった一枚を、ユーザーが高解像度で共有するもの。
- **代表写真の別送は必須**。綴葉モードのSNS投稿画像（ガイドラインは [scribe_image_guideline.md](../../assets/scribe_image_guideline.md)）は、代表写真をレポート風レイアウトの写真エリアへそのまま組み込む方式のため、代表写真が無いと画像を構成できない（欠落時は綴葉モードのステップ2で中断される）。視覚素材は**代表写真を正**とし、活動記録ページの写真で代替しない。

## 取得結果の読み方

`fetch_yamap_activity` の出力は `--------` 区切りの4ブロックです。
以下の優先順位で読みます。**優先度1・2は精読、3は大づかみ、4は確認用**。

### 優先度1：活動詳細（本文）— 最重要

ユーザー自身が毎回綴る文章で、もっとも個性（固有色）の出る部分。
山行の流れ・心情・ハイライトはここから読み取り、SNSへの代筆投稿本文と、小夜モードへの感想引き継ぎ（`scribe_handover` → 「登山レポートへの想い」）の主たる素材とする。

出力の末尾に全文がそのまま入る（OCR を経ないため、誤認識や欠落は起きない）。

**取得失敗時**: スキルの実行に失敗し本文が得られなかった場合は、代筆の核となる素材が無いため**処理を中断**する。SNS への代筆投稿と `scribe_handover` の双方を行わず、中断理由を報告して終了すること（[run_aoi_scribe](../skills/run_aoi_scribe/SKILL.md) / [modes/scribe.md](../../modes/scribe.md) の契約と一致させる）。

### 優先度2：活動データ

タイム・距離・のぼり／くだりなどの記録数値に加え、**コース定数**・**平均ペース**のラベルが含まれる。
どれくらいの負荷だったかを推し量る材料（詳細は次節「活動データの評価」）。

**登頂した山**の行は、実際に山頂を踏んだチェックポイントから組み立てられている。SNS 投稿本文の冒頭「登った主要な山の紹介」に使える。

### 優先度3：チェックポイント

実際の山行の区間データ。チェックポイント間の所要時間や休憩の長短から、ペースや停滞を大づかみに読む。
複数日の山行では `1日目` `2日目` … と日ごとに分かれ、それぞれ合計時間・休憩時間・距離・標高差が付く。

### 優先度4：概要

タイトル・山域・都道府県・活動日・日程（日帰り／N泊N日）。山名・日付の確認に用いる。

**日程はここを正とする。** YAMAP のタグは実態と食い違うことがある（1泊2日の記録に「日帰り」タグが付いている実例がある）ため、そもそもタグは取得していない。

### 取得対象外（原則参照不要）

以下はページに存在するが取得しない。補完のために別途取りに行く必要はない。

- **ヘッダ画像・写真ギャラリー** — 枚数が多く、重要な一枚を機械的に選べない。画像判断は代表写真を正とする。
- **タグ** — ユーザーの設定に依存し、実態と合わないことがある。
- **装備** — 参考として記載されているが、特別な情報ではない。
- **すれ違った他ユーザー** — 参照不要。

## 活動データの評価（負荷・コンディションの読み取り）

活動データは「どれくらいの負荷の山行だったか」を推し量る材料。基礎として、**出力に含まれる YAMAP のラベル**を足がかりにする。

- **コース定数（ルートの難度）** — 距離と標高差から算出される客観的な難易度。ラベル（例: `きつい`）と数値が併記される。**ルートそのものの厳しさ**の目安。
- **平均ペース（当日の調子・余裕）** — 標準タイムに対する実績の速さ（例: `187% (速い)`）。**ユーザーがどれだけ快調に・余裕をもって歩けたか**の目安。

### 碧衣の5段階「手応え」評価

上記ラベルを元に、碧衣が山行の手応えを **5段階** で内的に位置づける。メッセージの温度・言葉選びを決めるための目安であり、**厳密な指標ではなく、運用しながら継続的に調整していく**前提のもの。

**軸①：ルートの手応え（コース定数ラベルが土台）**

| 段階 | 呼び名 | 目安ラベル | イメージ |
|---|---|---|---|
| Lv.1 | おだやか | やさしい | 軽やかな散策に近い |
| Lv.2 | ほどよい | ふつう | 標準的な里山歩き |
| Lv.3 | 歩きごたえ | きつい（数値が低め） | 手応えの出てくる行程 |
| Lv.4 | 力のいる | きつい | しっかりした登りごたえ |
| Lv.5 | 重厚 | きつい（数値が突出） | 大きな挑戦と呼べる一日 |

※ ラベルの語は YAMAP の表記（`やさしい` / `ふつう` / `きつい` の3種）をそのまま使う。`きつい` の幅が広いため、Lv.3〜5 はコース定数の数値も併せて見る（目安: 25〜40 が Lv.3、40〜70 が Lv.4、70 以上が Lv.5）。厳密な閾値は設けない。

**軸②：当日の調子（平均ペースラベルで補正）** — 同じ段階でも語り口を寄せる。

- `速い` / `やや速い` → 「余裕をもって」「快調に」歩き切った寄り
- `標準` → 「着実に」歩き通した寄り
- `ゆっくり` / `ややゆっくり` → 「じっくり」「慎重に」進んだ寄り（疲労や難所の気配も汲む）

ラベルが出力されない（YAMAP 側で非公開）場合は、タイム・距離・のぼり/くだり、チェックポイント間の所要時間（休憩の長短、区間での停滞）から大づかみに段階を当てる。最終的には **本文の記述と矛盾しない**ことを優先する。

例:「`きつい`（44） × `速い`（187%） ＝ Lv.4 を快調に」→「力のいる道のりを、危なげなく歩き通された一日」

## 読み解いた内容の使いどころ（綴葉モード）

- **活動詳細（本文）** → 綴葉モードでの読み解きの主素材。SNSへの代筆投稿本文の核にするとともに、`scribe_handover`（小夜モードへの引き継ぎ）に碧衣→ユーザー視点の感想・無事の帰着を祝う言葉として残す。小夜モードはこれを「登山レポートへの想い」で用いる。**取得できない場合は SNS 投稿も `scribe_handover` も行わず中断する**（優先度1の「取得失敗時」を参照）。
- **代表写真（必須）** → 綴葉モードのSNS投稿画像の生成（ガイドラインは [scribe_image_guideline.md](../../assets/scribe_image_guideline.md)）の主素材。レポート風レイアウトの写真エリアへそのまま組み込まれる。活動記録ページの写真で代替しない。
- **活動データの評価** → 負荷・コンディションを一言添える材料（例:「手応えのある道のりを、快調に歩き通された様子が伝わってきます」）。SNS本文や小夜への引き継ぎに反映する。
