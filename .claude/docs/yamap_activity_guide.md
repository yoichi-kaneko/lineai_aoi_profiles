# YAMAP 活動記録レポート 重点チェックガイド

## 背景

YAMAP 側の仕様変更により、活動記録ページのスクレイピング（旧 `fetch_yamap_activity` スキル）が
利用できなくなりました。現在は、ユーザーが活動記録ページのスクリーンショット（PNG 画像）を Todoist に添付し、
[download_todoist_attachment](../skills/download_todoist_attachment/SKILL.md) で取得したレポート画像を
[crop_yamap_report](../skills/crop_yamap_report/SKILL.md) スキルで主要ブロックに切り出してから、
碧衣が読み解く運用です。

※ 以前は「PDF 添付 + `pdftoppm` による画像化」の運用でしたが、スクリーンショット画像 + crop 切り出しへ移行済みです。

このガイドは [綴葉モード（modes/scribe.md）](../../modes/scribe.md) のステップ3（レポート画像の読み解き）から参照されます。以前は小夜モード（`modes/night.md`）から参照されていましたが、YAMAPレポートの読解は綴葉モードへ移設されました。小夜モードは、綴葉モードが `scribe_handover` として引き継いだ感想を受け取ります。

## 前提（決定済みの運用ルール）

- 活動記録レポートは **画像形式（PNG。活動記録ページ全体の縦長スクリーンショット）** で添付される。
- 添付画像の役割は **添付の順序で判定**する。
  - **1枚目の画像 = 活動記録レポート**（縦長スクリーンショット）
  - **2枚目の画像（ある場合）= レポートとは別の代表的な写真**。その山行で最も印象的だった一枚を、ユーザーが高解像度で共有するもの。
- **代表写真の別送は任意**。crop によりレポートのヘッダ画像（実写）を素材として扱いやすくなったため、レポート単独でも画像素材は確保できる。
  - **代表写真がある場合（レポート + 代表写真）**: 綴葉モードのSNS投稿画像の生成（ガイドラインは [scribe_image_guideline.md](../../assets/scribe_image_guideline.md)）の視覚素材は**代表写真を正**とする。
  - **代表写真がない場合（レポートのみ）**: crop で切り出した **`header`（ヘッダ画像）** を視覚素材として用いてよい。

## レポートの解析手順（crop_yamap_report で切り出してから読む）

レポート画像は縦に非常に長く、そのまま Read ツールで読むと縮小されて文字が判読しづらくなります。
**必ず [crop_yamap_report](../skills/crop_yamap_report/SKILL.md) スキルで主要4ブロックに切り出してから、ブロックごとに Read ツールで読み取ってください。**

1. **切り出し**: `crop_yamap_report` スキルを実行する。入力はダウンロード済みのレポート画像パス、出力プレフィックスは `yamap_{YYYYMMDD}_001` のような形式でよい。
2. **読み取り**: 出力 JSON の `results` から `status: "OK"` のブロックを、下記「重要度マップ」の優先順位で Read ツールで読み取る。
3. **失敗ブロックの扱い**: `status: "FAILED"` のブロックはスキップし、成功したブロックだけで読み取りを進める。どうしても必要な情報が欠ける場合のみ、元のレポート画像を Read で直接読んで補完する（縮小されるため判読性は落ちる。深追いしない）。

## 重要度マップ（重点チェックの本体）

crop が切り出す4ブロックを、以下の優先順位で読む。**優先度1・2は精読、3は大づかみ、4は素材・確認用**。

### 優先度1：activity_detail（活動詳細・本文）— 最重要

ユーザー自身が毎回綴る文章で、もっとも個性（固有色）の出る部分。
山行の流れ・心情・ハイライトはここから読み取り、SNSへの代筆投稿本文と、小夜モードへの感想引き継ぎ（`scribe_handover` → 「登山レポートへの想い」）の主たる素材とする。

### 優先度2：activity_data（活動データ）

タイム・距離・のぼり／くだりなどの記録数値に加え、**コース定数**・**平均ペース**のラベルが含まれる。
どれくらいの負荷だったかを推し量る材料（詳細は次節「活動データの評価」）。

- ブロック内の**標高グラフ**は、適切な解釈が難しいため、急登・急下降の区間があった、といった大まかな把握に留める。
- **山の情報・タグ**（天候・交通手段・難易度など）が読み取れれば、山行の背景を掴む補助に使ってよい。

### 優先度3：checkpoints（チェックポイント通過時間）

実際の山行の区間データ。チェックポイント間の所要時間や休憩の長短から、ペースや停滞を大づかみに読む。

### 優先度4：header（ヘッダ画像）

ページ最上部の実写ヘッダ画像（山名・タイトルの帯を含む）。役割は次の2つ。

- **山名・タイトルの確認**（山名は Todoist タスクや本文からも推察できるため、補助程度）
- **代表写真がない場合の画像生成素材**（前節「前提」参照）

### 切り出し対象外（原則参照不要）

以下はレポート画像内に存在するが crop の切り出し対象外であり、原則読まない。

- **写真ギャラリー** — サムネイルのリストで判読性が低い。画像判断は代表写真（または header）を正とする。
- **装備** — 参考として記載されているが、特別な情報ではない。
- **他ユーザーの同山記録・フッター** — スクリーンショットに写り込んでいるだけで、参照不要。

## 活動データの評価（負荷・コンディションの読み取り）

活動データは「どれくらいの負荷の山行だったか」を推し量る材料。基礎として、**activity_data ブロックに表示される YAMAP のラベル**を足がかりにする。

- **コース定数（ルートの難度）** — 距離と標高差から算出される客観的な難易度。ラベル（例: `きつい`）と数値が併記される。**ルートそのものの厳しさ**の目安。
- **平均ペース（当日の調子・余裕）** — 標準タイムに対する実績の速さ（例: ラベル `速い` ／ `170〜190%`）。**ユーザーがどれだけ快調に・余裕をもって歩けたか**の目安。

### 碧衣の5段階「手応え」評価

上記ラベルを元に、碧衣が山行の手応えを **5段階** で内的に位置づける。メッセージの温度・言葉選びを決めるための目安であり、**厳密な指標ではなく、運用しながら継続的に調整していく**前提のもの。

**軸①：ルートの手応え（コース定数ラベルが土台）**

| 段階 | 呼び名 | 目安ラベル | イメージ |
|---|---|---|---|
| Lv.1 | おだやか | やさしい | 軽やかな散策に近い |
| Lv.2 | ほどよい | ふつう／一般的 | 標準的な里山歩き |
| Lv.3 | 歩きごたえ | ややきつい | 手応えの出てくる行程 |
| Lv.4 | 力のいる | きつい | しっかりした登りごたえ |
| Lv.5 | 重厚 | とてもきつい〜 | 大きな挑戦と呼べる一日 |

※ ラベルの語は YAMAP の表記（レポート画像の表示）をそのまま使う。上表の対応はおおよその目安で、厳密な閾値は設けない。

**軸②：当日の調子（平均ペースラベルで補正）** — 同じ段階でも語り口を寄せる。

- `速い` → 「余裕をもって」「快調に」歩き切った寄り
- `標準` → 「着実に」歩き通した寄り
- `ゆっくり` → 「じっくり」「慎重に」進んだ寄り（疲労や難所の気配も汲む）

ラベルが読み取れない・判断に迷う場合は、タイム・距離・のぼり/くだり、チェックポイント間の所要時間（休憩の長短、区間での停滞）から大づかみに段階を当てる。最終的には **本文の記述と矛盾しない**ことを優先する。

例:「`きつい` × `速い` ＝ Lv.4 を快調に」→「力のいる道のりを、危なげなく歩き切られた一日」

## 読み解いた内容の使いどころ（綴葉モード）

- **activity_detail（本文）** → 綴葉モードでの読み解きの主素材。SNSへの代筆投稿本文の核にするとともに、`scribe_handover`（小夜モードへの引き継ぎ）に碧衣→ユーザー視点の感想・無事の帰着を祝う言葉として残す。小夜モードはこれを「登山レポートへの想い」で用いる。
- **代表写真（2枚目・任意）** → 綴葉モードのSNS投稿画像の生成（ガイドラインは [scribe_image_guideline.md](../../assets/scribe_image_guideline.md)）の主素材。ない場合は **header** を代わりに用いる。レポート内の写真ギャラリーは画像判断に用いない。
- **活動データの評価** → 負荷・コンディションを一言添える材料（例:「手応えのある道のりを、快調に歩き通された様子が伝わってきます」）。SNS本文や小夜への引き継ぎに反映する。
