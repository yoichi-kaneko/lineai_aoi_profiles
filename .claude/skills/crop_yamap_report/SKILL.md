# crop_yamap_report

YAMAPレポート（活動記録）画面のスクリーンショットは縦に非常に長く、そのままReadツールで読み取ると縮小されて文字が判読しづらくなります。
このスキルは画像をOCRで解析し、重要度の高い4ブロックを個別のPNGに切り出すことで、各ブロックを高い解像度のまま読み取れるようにします。

## 切り出されるブロック

| ブロック | 内容 |
| --- | --- |
| `header` | ページ最上部の実写ヘッダ画像（山名・タイトルを含む帯） |
| `activity_data` | 「活動データ」見出し〜「チェックポイント」直前（タイム・距離・上り/下りなど） |
| `checkpoints` | 「チェックポイント」見出し〜「活動詳細」直前（通過地点と時刻） |
| `activity_detail` | 「活動詳細」見出し〜写真一覧（または本文終端）直前（本文の感想・記録） |

※ YAMAPレポート画面のフォーマットに依存します。フォーマットが異なる画像では一部または全部のブロックの切り出しに失敗することがあります。

## 事前準備

依存パッケージはルートディレクトリで一元管理しています。
初回のみ、プロジェクトルートで以下を実行してください。

```bash
cd {プロジェクトルートの絶対パス}
pnpm install
```

- OCRには tesseract.js を使用します。初回実行時に日本語の学習データ（`jpn.traineddata`）を自動ダウンロードするため、ネットワーク接続が必要です（2回目以降はプロジェクトルートに保存されたキャッシュを使用します）。

## Claudeへの指示

YAMAPレポートのスクリーンショット画像を取得したあと（通常は `download_todoist_attachment` スキルで `tmp/` にダウンロード済み）、以下の手順で実行してください。

### 手順

1. 以下のコマンドをプロジェクトルートから実行してください。

```bash
cd {プロジェクトルートの絶対パス}
pnpm exec tsx src/yamap/crop_activity_detail.ts "{入力画像パス}" "{出力プレフィックス}" [--debug]
```

- `入力画像パス`: 切り出し対象のスクリーンショット画像（必須）。絶対パスまたはプロジェクトルートからの相対パスで指定する。
- `出力プレフィックス`: 出力ファイル名の接頭辞（必須）。英数字・ハイフン・アンダースコアのみ使用可（パス区切りは不可）。例: `yamap_20260716_001`
- `--debug`（任意）: 全ブロック成功時にも診断情報を出力する。**失敗ブロックがある場合は指定なしでも自動的に出力される**ため、通常このオプションを指定する必要はない。

OCRと画像解析を行うため、縦長の大きな画像では実行に時間がかかることがあります。タイムアウトは長め（5分程度）に設定してください。

2. 標準出力のJSONを確認してください。切り出された画像は `tmp/{出力プレフィックス}_{ブロック名}.png` として保存されます。

```json
{
  "inputPath": "入力画像の絶対パス",
  "outputPrefix": "yamap_20260716_001",
  "imageSize": { "width": 1080, "height": 24000 },
  "ocrScale": 1.11,
  "savedPaths": ["{プロジェクトルート}/tmp/yamap_20260716_001_header.png", "..."],
  "results": [
    { "section": "header", "status": "OK", "outputPath": "...", "crop": { "left": 0, "top": 0, "width": 1080, "height": 600 } },
    { "section": "activity_data", "status": "FAILED", "reason": "「活動データ」見出し（白背景の本文側）を特定できませんでした" }
  ]
}
```

**失敗理由の読み方**: `reason` に「〜による連鎖」とある場合、そのブロック自体ではなく**別のブロックの見出し検出失敗に巻き込まれた**ことを示します。各ブロックの下端は次のブロックの見出しで決まるため、見出し1つの検出漏れが2ブロックを失敗させます。この場合、大元の失敗ブロックを先に見てください。

3. `results` のうち `status: "OK"` のブロックの `outputPath` をReadツールで読み取り、内容を把握してください。

4. `results` に `status: "FAILED"` が**1つでもあれば切り出しは失敗**です。下記「切り出しに失敗した場合の手順」に従ってください。

碧衣のデイリーモード（夜モードなど）で登山レポートとして読み解く場合、各ブロックの読み取り優先度（activity_detail が最重要）や重点チェックの観点は [yamap_activity_guide.md](../../docs/yamap_activity_guide.md) に従ってください。

## 切り出しに失敗した場合の手順

### 成否の判定

**4ブロック（`header` / `activity_data` / `checkpoints` / `activity_detail`）のうち1つでも `FAILED` なら、切り出し全体を失敗として扱います。**

> **なぜ1ブロックの失敗でも全体を失敗とみなすのか**
>
> `header` は読み取り優先度としては補助的ですが、それでも例外にしません。理由は3つあります。
>
> - 各ブロックの下端は次のブロックの見出しで決まるため、**部分失敗の多くは根が同じ**です（見出し1つの検出漏れが2ブロックを失敗させる）。「1つだけ失敗」に見えても、原因は共通していることがほとんどです。
> - `header` が取れないということは、**レイアウトの認識が根本から崩れている**サインです。この状態では他ブロックの切り出し位置も信用できません。
> - ブロックごとに扱いを変えないことで、判断が実行ごとにぶれなくなります。
>
> なお **exit code では判定しないでください**。一部失敗は exit 0（正常終了）で返ります。判定は必ず `results` で行います。

### 手順

**1. 予備フローで代用を試みる**

[crop_image_region](../crop_image_region/SKILL.md) スキルで、失敗したブロックを手動で切り出します。

- 出力JSONの `debug.headingCandidates` に目的の見出しがあれば、その `imageY.y0` が**切り出しの上端**です
- 下端は、次のブロックの見出しの `imageY.y0`（`activity_detail` の場合は本文の終わり）です
- 位置が分からない場合は、`slice_region` で範囲を帯状に分割して読み、位置を突き止めます
- 位置が決まったら `crop_region` で切り出します

**2. 全ブロックが揃えば、切り出し成功として処理を続行する**

予備フローで残りのブロックを取得できた場合は、通常どおり読み取りを進めてください。呼び出し元のモードを中断する必要はありません。

**3. 揃わなければ処理を中断する**

予備フローでも必要なブロックを取得できなかった場合は、呼び出し元のモードの中断条件に従って処理を中断し、理由を報告して終了してください。

**4. 成否に関わらず、Todoist へ報告する**

予備フローで代用できた場合であっても、**検出ロジックの修正は必要**です。`put_todoist_task` スキルで、以下を含めて報告してください（[aoi.md](../../../aoi.md) の「共通ステップ：要望のフィードバック」に準じます）。

- 失敗したブロックと、その `reason`
- `debug.headingCandidates` の内容（特に `accepted` 以外になった候補の `text` / `status` / `imageY`）
- 予備フローで代用できたかどうか。代用した場合は、実際に使った切り出し座標
- 元画像のサイズと `debug.ocr`（`lineCount` / `ocrScale`）

この報告が、失敗パターンをテストケースとして追加する（`test/README.md` の「フィクスチャの追加手順」）ための材料になります。

## 診断情報（`debug` フィールド）

失敗ブロックがある場合、出力JSONに `debug` フィールドが自動的に追加されます（全ブロック成功時は `--debug` 指定時のみ）。
切り出しがなぜ失敗したのかを判断し、必要なら**切り出し位置を自分で決める**ための材料です。

```json
{
  "debug": {
    "ocr": { "lineCount": 253, "ocrScale": 0.61 },
    "headingCandidates": [
      {
        "label": "活動詳細",
        "text": "活動 詳細 ーー",
        "confidence": 79,
        "ocrY": { "y0": 2412, "y1": 2438 },
        "imageY": { "y0": 3950, "y1": 3992 },
        "status": "not_heading"
      }
    ],
    "activityDetailBottomSteps": [
      { "method": "photo_label", "found": false },
      { "method": "grid_detection", "found": true, "bottom": 6282 }
    ]
  }
}
```

### headingCandidates

見出しラベルを含む行を、採否つきで列挙します。**`imageY` は元画像座標**なので、そのまま切り出し位置として使えます。

| `status` | 意味 |
| --- | --- |
| `accepted` | 見出しとして採用された |
| `not_heading` | ラベルは含むが見出し行とみなされなかった（本文中の言及、または併記されたリンク・罫線が読めずノイズ化した場合） |
| `out_of_range` | 探索範囲の外にあった（他ブロックの見出し位置により範囲が絞られている） |
| `red_button` | ヘッダ画像直下の赤背景ボタンと判定して除外した（`活動データ` のみ） |

**あるラベルの候補が1件も出ていない場合**、OCR がその見出しをまったく読めていません。この場合は座標の手がかりが無いため、元画像を範囲指定でスライスして位置を探す必要があります。

### activityDetailBottomSteps

`activity_detail` の下端を決めるために試した手段と、その結果を順に記録します。`photo_label`（「写真」見出し）→ `grid_detection`（写真サムネイルのグリッド検知）→ `text_end_heuristic`（本文終端の推定）の順で試します。

「写真」見出しはレポートによって存在しないため、`photo_label` が `found: false` になるのは異常ではありません。実質的には `grid_detection` が主役です。

`activity_detail` の見出し自体が取れなかった場合は `null` になります（下端解決まで到達していないため）。

## 注意事項

- **成否の判定は `results` で行い、終了コードでは判定しないでください。** 一部のブロックのみ失敗した場合、コマンドは終了コード0で正常終了します（成功分だけが `savedPaths` に含まれます）。終了コード1になるのは4ブロックすべてに失敗した場合だけです。
- **終了コードに関わらず、結果JSONは標準出力に出力されます**（全滅時ほど診断情報が必要なため）。
- 同名の出力ファイルが存在する場合は上書きします。
