# get_checkins

ユーザーが外出先からチェックイン用の LINE 公式アカウント（碧衣の世界観の上では観測ドローン「地写」）へ送った記録を、Firestore の `checkin_logs` から取得するスタンドアロン CLI スクリプトです。

## 概要

- **記録の中身**: ユーザーは位置情報メッセージで場所を、テキストと写真でその場所での一言・様子を送ります。1メッセージが1件の記録として残っています（形は [functions/README.md の「`checkin_logs` の形」](../../../functions/README.md)）
- **まとめ方**: 位置情報1件を1件のチェックインとし、次の規則でテキスト（コメント）と写真をそこへ紐づけて返します
  1. 位置情報メッセージへの**引用返信**のテキストは、時間によらず引用元の位置情報に紐づける
  2. それ以外は、**直前の位置情報から10分以内**に届いたテキスト・写真を、その位置情報に紐づける
  3. 複数枚をまとめて送った写真は、組の最初の1枚と同じ位置情報にそろえる
- **時刻**: 記録される時刻は、ユーザーが**送った時刻**です。山中で電波が無いときは、電波が戻ってからまとめて送られるため、実際にその場所にいた時刻より遅くなることがあります
- **引数**: `start_date` / `end_date`（`YYYY-MM-DD`、日本時間）。`end_date` は当日の終わりまで含みます
- **認証**: `get_firestore_docs` と同じく、環境変数 `FIREBASE_CONFIG_PATH`（または `FIREBASE_CONFIG_JSON`）のサービスアカウントを使います

## 事前準備

依存パッケージはルートディレクトリで一元管理しています。
初回のみ、プロジェクトルートで以下を実行してください。

```bash
cd {プロジェクトルートの絶対パス}
pnpm install
```

プロジェクトルートの `.env` に以下の環境変数が必要です。

```
FIREBASE_CONFIG_PATH="/path/to/serviceaccount.json"
```

## 実行方法

```bash
cd {プロジェクトルートの絶対パス}
pnpm exec tsx src/checkin/get_checkins.ts "{start_date}" "{end_date}"
```

## 出力

```json
{
  "date_range": "2026-10-11 to 2026-10-11",
  "count": 1,
  "checkins": [
    {
      "message_id": "600000000000000001",
      "posted_at": "2026-10-11T09:12:03+09:00",
      "title": "高尾山口駅",
      "address": "東京都八王子市高尾町",
      "latitude": 35.632,
      "longitude": 139.27,
      "comments": [
        { "message_id": "600000000000000002", "posted_at": "2026-10-11T09:13:40+09:00", "text": "これから登ります" }
      ],
      "photos": [
        { "message_id": "600000000000000003", "posted_at": "2026-10-11T09:14:05+09:00" }
      ]
    }
  ],
  "unlinked": [
    { "type": "image", "message_id": "600000000000000010", "posted_at": "2026-10-11T15:40:22+09:00" }
  ]
}
```

| 項目 | 内容 |
|---|---|
| `count` | `checkins` の件数（位置情報の件数） |
| `checkins` | 範囲内に送られた位置情報。時刻の古い順 |
| `title` / `address` | 場所名・住所。**どちらも付いていないことがあります**（付いていない項目は出力しません） |
| `latitude` / `longitude` | 緯度・経度。必ず付いています |
| `comments` | その場所に紐づいたテキスト。その場での一言です |
| `photos` | その場所に紐づいた写真。`message_id` で写真を取得します。複数枚をまとめて送ったものには `image_set` が付きます |
| `unlinked` | 範囲内に送られ、どの位置情報にも紐づかなかったテキスト（`type: text`）・写真（`type: image`）。時刻の古い順 |

- 範囲の終わり（`end_date` の 24:00）をまたいで送られたテキスト・写真も、範囲内の位置情報に紐づいていれば `comments` / `photos` に入ります
- 位置情報には施設のカテゴリがありません。駅・バス停・山頂・山小屋といった場所の種類は、場所名と住所から読み取ってください
- 形式を読めない記録があった場合は、件数だけが標準エラーに出ます

## Claudeへの指示

ARGUMENTS として渡された `start_date` と `end_date` をそのまま引数に使い、上記のコマンドを実行してください。

### 結果の読み方

- **行動の記録として読む**: `checkins` は、ユーザーが実際に立ち寄った場所の記録です。`comments` はその場での一言、`unlinked` は場所と結びつかなかったその時刻の記録として、いずれもその日の行動を推察する材料にしてください。
- **碧衣への言葉ではありません**: 地写へ送られたテキストは、碧衣へ宛てた便り（`line_text`）とは別のものです。依頼や質問として応答する対象にはしないでください。
- **場所名・住所が無い場合**: 座標だけの記録は、前後のチェックインやカレンダーの予定と照らして、どのあたりにいたかを推察する程度に留めてください。座標から場所を割り出すために外部の地図サービスを呼ぶことはしないでください。
- **写真の取得**: `photos` / `unlinked` の写真は、**`download_line_image` スキル**に `message_id` と `--channel checkin` を渡して取得・解析します（[download_line_image](../download_line_image/SKILL.md)）。何枚まで解析するかは、呼び出し元のモードの手順に従ってください。
- **0件の場合**: `checkins` と `unlinked` がどちらも空なら、その期間にチェックインの記録は無かったものとして扱ってください。失敗ではありません。
- **SNS へ載せない**: 取得した記録（座標・場所名・住所・コメント・写真）は、LINE の外へ公開しないでください。綴葉モードの SNS 投稿などの素材には使いません。

## タイムアウト

Firestore の取得が30秒（`FIRESTORE_TIMEOUT_MS` で変更可）を超えた場合は、標準エラーに `[TIMEOUT]` を出力して終了コード `124` で終わります。

本スキルは**読み取り専用**のため、タイムアウトした場合はそのまま1回だけ再試行して構いません。
