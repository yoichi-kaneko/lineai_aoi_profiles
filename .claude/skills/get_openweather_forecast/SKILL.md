# get_openweather_forecast

住所・地点名からジオロケーションを行い、OpenWeatherMap API から天気予報を取得するスキルです。

## 概要

以下の情報を取得して標準出力に返します。

- **現在の天気**: 気温・天気・湿度・風速・気圧・雲量・日の出/日の入り
- **時間別予報**: 今後 24 時間の気温・天気・風速・雲量・降水確率
- **日別予報**: 今後 8 日間の天気サマリー

## 事前準備

依存パッケージはルートディレクトリで一元管理しています。
初回のみ、プロジェクトルートで以下を実行してください。

```bash
cd {プロジェクトルートの絶対パス}
pnpm install
```

プロジェクトルートの `.env` に以下の環境変数が必要です。

```
GOOGLE_MAPS_API_KEY="your_api_key"
OPEN_WEATHER_APP_ID="your_api_key"
```

## Claudeへの指示

以下の手順で天気予報を取得してください。

### ステップ1：地点の確定とジオロケーション

以下のコマンドでジオロケーションを行い、緯度・経度を取得してください。

```bash
cd {プロジェクトルートの絶対パス}
pnpm exec tsx src/google_map/geocode.ts "{住所または地点名}"
```

登山以外の地点（打ち合わせ先・宿泊先・デフォルト天気予報地点など）については、緯度・経度が既に分かっていればこのステップを飛ばしてステップ2へ進んで構いません。**予定から登山地点を推定する場合は、次の 1-0 の順序に従ってください。**

#### 1-0'. 対象地点が依頼で明示されている場合（推定より優先）

ユーザーが依頼の中で地点を明示している場合（響モードで「〇〇の天気を教えて」と尋ねられた場合など）は、**その地点をそのままジオコーディングしてください**。下記 1-0 は、予定や計画書から**登山地点を推定する**ための手順であり、明示された地点を置き換えるためのものではありません。

- 「〇〇登山口の天気」と指定されたなら、**登山口の座標で取得します**。山名・山域へ読み替えないでください（標高差の分だけ気温が変わり、尋ねられた地点とは別の予報になります）。
- 明示された地点でも、候補の選定（1-1）と引き直し（1-2）は同じように行ってください。地名が曖昧な場合は、依頼の文脈（県名・山域など）を手掛かりに候補を選びます。
- どの候補が目当てかを決めきれない場合は、推測でひとつに決めず、**呼び元のモード手順に従ってユーザーへ確認**してください（響モードは [talk.md](../../../modes/talk.md) ステップ4の「情報が足りない場合」）。引き直しても特定できない場合も同じです。1-3 の取得地点の切り替えは、明示された地点を別の地点へ置き換えることになるため行いません。

#### 1-0. 登山予定の地点の決め方（予定から推定する場合・モード共通）

予定や計画書から登山地点を推定する場合、その予報は**どのモードから呼ばれても同じ地点で取得します**（暁・望・門灯・小夜のいずれも本項に従います）。取得地点がモードごとに揺れると、同じ山の同じ日について食い違う気温を伝えることになり、ユーザーに「予報が大きく変わった」と誤読されます。次の順で地点を決めてください。

1. **代表とする山（ピーク）を決める。** 予定や登山計画書のタイトルにピークが明記されていれば、その山です。縦走など複数の山を繋ぐ行程で、タイトルに明確なピークの記述が無い場合（複数の山が並んでいて一つに絞れない場合を含む）は、**登山計画書の移動計画（[fetch_yamap_plan](../fetch_yamap_plan/SKILL.md) のチェックポイント）に並ぶ山のうち、通過順で中ほどにある山**を代表とします。
   - 計画書の「地図」欄に並ぶ山名は、行程の順を表しません。代表は移動計画の通過順で選んでください。
   - 山が偶数個で中ほどが2つに分かれる場合は、先に通過する方を採ります。
2. **代表とした山の山名（または山域）でジオコーディングする。** これが第一候補です。カレンダーの予定（`location` 欄など）や登山計画書に入山口の緯度・経度が併記されていても、**それを理由に山名での検索を省かないでください**。座標が既知ならこのステップを飛ばしてよいのは、登山以外の地点だけです。
3. **山名で特定できない場合は、1-2 の引き直しを行います。** 引き直しても特定できない場合、または代表とする山名そのものが分からない場合は、1-3 に従って取得地点を切り替えます。
4. 切り替え先の座標も得られない場合は 1-4 に従ってください。

**代表とした山以外の地点で取得した場合は、報告の中でその地点名を添えてください**（例:「籠坂峠の予報です」「熊渡登山口の予報です」）。山頂と峠・登山口・駅では標高差の分だけ気温が異なるため、どの地点の予報なのかが読み手に分かる必要があります。代表とした山（または山域）の座標で取得できた場合、この断りは不要です。

#### 1-1. 候補の選定

結果は `results` に**候補の配列**で返ります。**1件目が目当ての地点とは限りません。** 同名の山・地名は各地にあるため、次の材料を照らし合わせて、どの候補を採るかを必ず判断してください。

- **`formatted_address`**: 日本語で返ります。**県名**が、カレンダーの予定・登山計画書・山域の情報から想定される場所と一致するかを確認してください。
- **`types`**: 山を狙って検索した場合、目当ての候補には通常 `natural_feature` が含まれます。`political` / `sublocality` だけの候補は、同名の**町丁名**を指しています。
- **`partial_match`**: `true` の候補は Google が完全一致とみなさなかったもので、山ではなく県全体を指すなど、大きく外れている兆候です。

選んだ候補の `location`（`lat` / `lng`）をステップ2へ渡してください。

#### 1-2. どの候補も合致しない場合の引き直し

候補がすべて想定と食い違う場合、または `count` が 0（`results` が空）の場合は、**次の順で引き直してください**。目当ての候補が見つかった時点で止めます。

1. **県名を添える**: まず県名で絞り込みます。山名だけでは引けない山域名や、各地にある一般的な山名で有効です（`丹沢` は福島県の地名に化け、`二子山` は0件になります）。

   ```bash
   pnpm exec tsx src/google_map/geocode.ts "神奈川県 丹沢"
   ```

   山名が地名としても使われている場合は、`丹沢` → `丹沢山` のように「山」を補うほうが当たることもあります。
2. **隣接する地名を添える**: 県名を添えても目当ての山が見つからない場合は、山のふもとの湖・町村など、**その山に隣接する地名**を添えて引き直します。`三国山` は京都府の町丁名に化け、`静岡県 三国山` は静岡県全体しか返りませんが、`山中湖 三国山` なら山梨県山中湖村の山として引けます。添える地名は、計画書の山域や移動計画、カレンダーの予定の住所などから拾ってください。

引き直した結果も 1-1 の基準で選んでください。県名や地名を添えると、県全体や市域を指す候補が上位に来ることがあります（`types` が `administrative_area_level_1` や `locality` のみ、`partial_match` が `true`）。そうした候補は採らず、**目当ての山が2件目以降に含まれていないか**を確かめてください。

#### 1-3. 引き直しても特定できない場合（取得地点の切り替え）

登山予定の地点で、1-2 の引き直しでも代表の山を特定できない場合は、**予報を取得する地点（ランドマーク）を切り替えます**。予定や計画書のタイトルから目指すピークが分かっている場合も、同じように切り替えて構いません。

- **計画書の移動ルート上で、代表の山に近い地点を優先します**。移動計画のチェックポイントに並ぶほかの山・峠などを、1-1・1-2 と同じ要領でジオコーディングしてください。
- **ルート上に引ける地名が見つからない場合は、山中でない地点も許容します**。入山口・下山口の駅名やバス停名などがこれに当たります。カレンダーの予定や登山計画書に入山口の緯度・経度が記載されていれば、その座標を用いて構いません。
- 切り替えた地点で取得した場合は、1-0 のとおり、報告の中でその地点名を添えてください。

この切り替えは、予定から登山地点を推定する場合（1-0）のための手順です。依頼で明示された地点（1-0'）には適用しません。

#### 1-4. 座標を得られない場合

切り替え先の座標も得られない場合（登山以外の地点で、1-2 の引き直しでも特定できない場合も同様）は、**put_todoist_task** スキルで「要望のフィードバック」として登録してください（[aoi.md](../../../aoi.md) の「共通ステップ：要望のフィードバック」に従います）。

- **content**: どの山・地点の座標を取得できなかったかが分かるタイトルにしてください。
- **description**: **試したキーワードをすべて**列挙し、それぞれ何が返ったか（0件だったか、どの地名に化けたか）を添えてください。詳細は `tmp/todoist_task.txt` に保存して `--description-file` で渡します（[put_todoist_task](../put_todoist_task/SKILL.md) 参照）。

登録したうえで、その地点の予報取得は諦めて次の手順へ進んでください。処理は止めず、取得できた情報で報告を組み立てます。

### ステップ2：天気予報の取得

取得した（または既知の）緯度・経度を使って、以下のコマンドで天気予報を取得してください。

```bash
cd {プロジェクトルートの絶対パス}
pnpm exec tsx src/openweather/forecast.ts {緯度} {経度}
```

コマンドの実行結果を、そのままユーザーに提示してください。

### ステップ3：予報の読み方（日別と時間別の使い分け）

取得結果には「今後24時間の予報（時間別）」と「今後8日間の予報（日別）」が含まれます。**当日の天候を判断する際は、実行時刻以降の時間別予報を主として読んでください。**

- **日別予報の降水確率・雨量は、その日1日分の集計値です**。その日の0時からの分を含むため、**実行時刻より前にすでに降り終えた雨**も反映されます。朝・日中に実行されるモード（暁・望など）で日別の値だけを拾うと、「今日は一日雨、降水確率100%」のように実態と真逆の判断になり得ます。
- **日別と時間別が食い違う場合**（例：日別は降水確率100%だが、時間別は日中ずっと0%）は、日別予報の **概要**（`summary`。英文で返ることがあります）で降雨の時間帯を確認してください。`There will be rain until morning, then partly cloudy` のような記述があれば、その雨は実行時刻より前に降り終えた分です。
- **時間別予報は取得時点の直近の時刻から並ぶ**ため、そのまま「これから」の推移として読めます。降り出しの時刻、気温が下がる時間帯、風の強まる時間帯は、この並びから読み取ってください。
- **日別予報を主に使う場面**は、翌日以降の傾向、当日の気温の幅（最低・最高）、複数日の山行における後半の見通しなど、**時間別予報（24時間）の範囲外**を掴むときです。
