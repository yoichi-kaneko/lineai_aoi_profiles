# review_with_codex

碧衣が生成した成果物を、外部のレビュアーである **Codex CLI** へ渡し、**一往復だけ**レビューを受け取るスタンドアロン CLI スクリプトです。

レビュー依頼文は引数で直接渡さず、**一時ファイル `tmp/codex_review_input.md` に保存してそのパスを渡す方式**です（`generate_gpt_image` / `send_line_*` と同じ作法）。改行はそのまま改行として書けばよく、`\n` への置換やクォート処理は不要です。

**依頼文に何を書くか、返ってきた指摘をどう扱うかは [codex レビュー：依頼文の組み立てと反映の作法](../../docs/codex_review.md) を正とします。** 本ファイルは実行の手順だけを扱います。

## 概要

- レビュー依頼文を保存した一時ファイルのパスを受け取り、`codex exec` へ標準入力で流し込みます
- レビュー結果（レビュアーの最終応答）を `tmp/codex_review_result.md` に書き出します
- codex は**読み取り専用**（`--sandbox read-only`）・**セッションを残さない**（`--ephemeral`）設定で起動します
- codex の作業ディレクトリは OS の一時領域に置き、リポジトリの外で動かします。渡す環境変数も必要最小限に絞ります（`.env` の認証情報を引き渡さないため）
- **終了コードは常に 0** です。codex が未導入でも、認証が切れていても、時間切れでも、`status` を返して正常終了します

## 事前準備

依存パッケージはルートディレクトリで一元管理しています。初回のみ、プロジェクトルートで `pnpm install` を実行してください。

加えて、**Codex CLI がインストールされ、認証済みであること**が前提です。

```bash
npm install -g @openai/codex
codex login --with-api-key   # または codex login
codex --version              # 動作確認
```

未導入・未認証でもこのスキルは失敗しません（レビューがスキップされるだけです）。

プロジェクトルートの `.env` で、次の環境変数を任意に設定できます（すべて省略可）。

```dotenv
# false にするとレビューを常にスキップする（既定: true）
CODEX_REVIEW_ENABLED="true"

# レビューの打ち切り時間（秒・既定: 240）。Bash ツール既定の 300 秒の内側に収める
CODEX_REVIEW_TIMEOUT_SEC="240"

# 使用するモデル（既定: codex 側の設定に従う）
CODEX_REVIEW_MODEL=""

# 推論強度 none / minimal / low / medium / high / xhigh（既定: codex 側の設定に従う）
CODEX_REVIEW_EFFORT=""
```

## Claudeへの指示

画像生成プロンプトや SNS 投稿本文を生成し、実行（画像生成・投稿）へ進む前にレビューを挟むとき、このスキルを使用してください。

### 手順

1. **レビュー依頼文の保存**: [codex レビュー](../../docs/codex_review.md) のセクション2の骨格に従って依頼文を組み立て、`tmp/codex_review_input.md` に保存してください（Write ツールで書き込み）。観点セット（`image_prompt` / `scribe_image_prompt` / `scribe_post`）は呼び出し元の手順が指定します。

2. **レビューの実行**: 以下をプロジェクトルートから実行してください。

```bash
cd {プロジェクトルートの絶対パス}
pnpm exec tsx src/codex/review.ts "tmp/codex_review_input.md"
```

   - 出力先を変えたい場合のみ `--out tmp/{任意の名前}.md` を添えます。省略時は `tmp/codex_review_result.md` です。
   - このコマンドは**数十秒〜数分かかります**。完了を待ってから次へ進んでください。

3. **結果の確認**: 出力された JSON の `status` を見て分岐してください。

   | `status` | 意味 | 次の行動 |
   |---|---|---|
   | `ok` | レビュー結果が得られた | `outputPath` を Read ツールで読み、手順4へ進む |
   | `skipped` | `CODEX_REVIEW_ENABLED` が false | レビューを行わず、呼び出し元の次の手順へ進む |
   | `unavailable` | codex コマンドが実行できない | 同上 |
   | `timeout` | 制限時間内に終わらなかった | 同上 |
   | `error` | codex の実行が失敗した | 同上 |

4. **指摘の反映**: 読み取った指摘のうち、妥当なものを成果物へ反映してください。採否の判断基準・反映後に確かめること・ログへ残す値は [codex レビュー](../../docs/codex_review.md) のセクション6に従います。

### 失敗時の扱い

**本節は [aoi_constraints.md](../../rules/aoi_constraints.md) の汎用ルール「1回だけ再試行 → スキップ」に優先します。**

- **再試行しません**。`status` が `ok` 以外だった場合は、その場でレビューを諦め、**レビュー前の成果物のまま**呼び出し元の次の手順へ進んでください。レビューは補助工程であり、日次モードの実行時間を再試行で圧迫することの方が損失が大きいためです。
- **中断条件にしません**。綴葉モードでも同様です。レビューの失敗は、画像生成そのものの失敗とは別に扱います。
- **再レビューしません**。指摘を反映したあと、もう一度このスキルへ回さないでください。
- **フィードバック登録は不要です**。レビューのスキップは想定内の挙動であり、「要望のフィードバック」として Todoist へ登録する必要はありません。ただし `status` が `error` で `stderr` に認証切れなど**運用者の対処を要する原因**が示されていた場合に限り、[aoi.md](../../../aoi.md) の共通ステップに従って登録して構いません。

### 報告の作法

ユーザーへ送るメッセージ本文で、このレビュー工程に触れる必要はありません。報告の主役はユーザーの一日であり、レビューは碧衣の内部工程です。触れる場合も [aoi_messaging.md](../../rules/aoi_messaging.md) の「技術・運用連絡の語り方」に従い、技術詳細には踏み込まないでください。
