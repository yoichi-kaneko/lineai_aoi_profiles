# run_aoi_scribe

対話モードの Claude 上で、`aoi.md` に定義された **綴葉（つづりは / scribe）モード**を実行するためのスキルです。

綴葉モードは、ユーザーが綴った YAMAP の登山レポートを碧衣が読み解き、その内容を SNS へ代筆投稿し、同日の小夜モードへ引き継ぐモードです。**このスキル経由での手動起動のみ**を起点とし、時間帯による自動判定や `send_daily_line.sh` からの自動トリガーはありません（想定タイミングは同日の小夜モードの実行前）。

## 概要

- **実行対象**: `aoi.md` の綴葉モード（`modes/scribe.md`）
- **モード**: `scribe` 固定（`run_aoi_daily` のような時間帯自動判定は行わない）
- **日付**: 実行環境の日本標準時（JST）現在日を使用
- **実行形態**: 対話モードの Claude 内で実行
- **tmp 掃除**: 処理の最初に `refresh_tmp.sh` で `tmp/` をクリーンアップする
- **ログ保存**: モード処理がすべて完了したあと、Firestore の `run_logs` コレクションに実行ログを保存する

## Claudeへの指示

1. プロジェクトルートで `refresh_tmp.sh` を実行し、`tmp/` をクリーンアップしてください。前回実行の残骸を参照せず、処理開始時に一度だけ行います。

```bash
cd {プロジェクトルートの絶対パス}
bash refresh_tmp.sh
```

2. `aoi.md` を読み込み、「モード概要」の表で綴葉（`scribe`）モードの入力トリガー形式を確認してください。

3. 実行環境の日本標準時（JST）で当日の日付を取得してください。

   注: POSIX TZ 形式の `JST-9` を使用します（一部環境で `Asia/Tokyo` が効かないため）。

```bash
TZ='JST-9' date +%Y-%m-%d
```

4. `aoi.md` の「モード概要」に従い、標準モードキー `scribe` と日付から入力トリガーを組み立ててください。

   例: 日付が `2026-07-21` の場合は、`daily message (綴葉): 2026-07-21`

5. 組み立てた入力トリガーを、この対話セッション内の実行指示として扱い、`aoi.md` の綴葉モードの実行フロー（`modes/scribe.md`）に従って処理してください。

   - このスキル内から `claude` や `claude -p` を起動しないでください。
   - 綴葉モードの詳細手順は `modes/scribe.md` を読み込んで確認してください。
   - 中断条件（対象レポートの完了タスクが 0件 / 2件以上、レポート URL・レポート画像・代表写真の欠落、**予備フローでもレポート画像の4ブロックを揃えられない**、SNS 投稿画像の生成失敗など）に該当した場合は、SNS 投稿・引き継ぎを行わず、中断理由をユーザーへ報告して終了してください。この場合は手順6のログ保存も行いません。
   - 切り出しの失敗は、それ自体が直ちに中断条件になるわけではありません。`crop_image_region` スキルでの代用を試み、4ブロックが揃えば処理を続行します（手順は [crop_yamap_report](../crop_yamap_report/SKILL.md) の「切り出しに失敗した場合の手順」）。
   - 同一日付の再実行による二重投稿・二重送信の防止は、システム機構（実行前チェック・原子的予約・排他ロック等）ではなく運用者の判断に委ねます（方針は [README.md](../../../README.md) の「二重実行防止」を参照）。

6. **上記のモード処理がすべて完了したあと**（中断せずステップ8の引き継ぎまで到達した場合）、実行ログを Firestore の `run_logs` コレクションに保存してください。

```bash
cd {プロジェクトルートの絶対パス}
pnpm exec tsx src/firebase/put_log.ts "{date}" "scribe"
```

- `{date}`: 手順3で取得した日付（YYYY-MM-DD）
- `mode` は `scribe` 固定です。

許可される `mode` の値は [src/firebase/runLogModes.ts](../../../src/firebase/runLogModes.ts) を参照してください。

コマンドが成功したら、追加したドキュメントのIDをユーザーに報告してください。モード処理の途中で失敗・中断した場合は、ログ保存の前にその内容を報告してください。

## run_logs のドキュメント構造

| フィールド  | 型        | 内容                                   |
| ----------- | --------- | -------------------------------------- |
| date        | Timestamp | 実行対象日（引数の日付）               |
| mode        | string    | 実行した標準モードキー（`scribe`）     |
| createdAt   | Timestamp | ログ保存日時                           |
