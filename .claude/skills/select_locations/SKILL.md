# select_locations

一週間分の訪問地点のような多数の緯度経度から、点描画（[plot_locations](../plot_locations/SKILL.md)）で描く点を最大12点に絞り込むスタンドアロン CLI スクリプトです。
結星（weekly）モードの座標図で、候補が12件を超える週や、東京の生活圏と遠征先が混在して点が重なる週を扱うことを想定した選択・集約の部品です。

## 現在の位置づけ（先行実装）

- **スキルと選択・集約のアルゴリズムを先行して実装したもので、現在このスキルを呼ぶモード・フローはありません**。碧衣の各モードの実行中に、このスキルを自発的に使わないでください。
- Swarm（Foursquare）の API から取得したデータを使って生成した画像は、Foursquare の規約上保持できません。描画の前段である本スキルにも、**`get_swarm_checkins` で取得したチェックイン座標を入力にしないでください**。動作確認には、`test/fixtures/geo/select_locations/` にある架空の座標を使います。
- **今後の利用の目処**: [plot_locations](../plot_locations/SKILL.md) と同じく、Swarm を置き換える LINE ベースのチェックイン記録（[issue #247](https://github.com/yoichi-kaneko/lineai_aoi_profiles/issues/247)）の座標で、結星モードの座標図を作る際に再利用する見込みです（同 issue の手順4）。②の中心の決め方（`--center` に渡す座標の出どころ）も、その段階で改めて定めます。

## 概要

- 入力は `{ "lat": 数値, "lng": 数値, "placeId": 文字列（任意） }` の配列を書いた JSON ファイル、出力は `tmp/` 配下の JSON ファイルです
- 出力 JSON は `lat` / `lng` を持つ点の配列で、**そのまま plot_locations の入力に使えます**（plot_locations は `lat` / `lng` 以外を無視します）
- 成功時は、採用した方式・評価値・件数をまとめた要約 JSON を標準出力へ返します。要約には座標も placeId も含めません
- 外部 API を呼ばないため、環境変数の設定は不要です

## 選び方

### 前処理: 同じ地点をまとめる

- `placeId` が同じ入力、`placeId` が無く緯度経度が完全に一致する入力を1地点にまとめ、入力件数を訪問回数として持ち回ります
- 距離・重心・評価はすべて**異なる地点の数**で扱い（1地点を1として数える）、訪問回数では重み付けしません。同じ施設へ何度も通った週でも、生活圏へ重心や点が偏らないようにするためです。反復は出力の `visits` に残ります
- 地点を緯度・経度・placeId の順に並べてから計算するため、入力の順番を入れ替えても結果は変わりません

### ③ 集合化（第一候補）

- 各地点を1集合として始め、**代表地点どうしが最も近い2集合**を統合し続けます
- 集合が12以下になり、かつ全代表地点が描画後に 16px（点の直径 8px ＋同じ幅の隙間）以上離れたら止めます。12以下でも重なる点は統合し、12を超える間は重ならなくても統合します
- 代表地点は、集合の重心（地点ごとに重み1）に**最も近い実在の地点**です。重心そのものは湾の上や山腹など未訪問の位置に来ることがあるため、描画には使いません
- 重なりは全地点を自動フィットした倍率で判定します。代表地点は全地点の一部なので、描画時の倍率はそれ以上になり、選んだ点は描画後も重なりません（再フィットを繰り返す処理はしません）
- 全地点がいずれかの点に対応づくため、週全体の訪問範囲を要約する表現になります

### ② 中心近傍選択（第二候補）

- **中心は `--center 緯度,経度` で指定できます**。その週の重要な出来事の場所など、焦点を当てたい位置を渡します。入力にある地点である必要はなく、チェックインの無い山頂なども指定できます
- `--center` を省略した場合は、**地点が最も集まっている場所の実在の地点**を中心にします。各地点について、半径 30km 以内の地点を距離に応じて重み付けした密度を求め、最も高い地点を選びます（全地点の平均のような、どちらの地域でもない位置は中心にしません）
- 中心から半径 30km 以内の地点を近い順に、最大12点選びます。**点が足りなくても半径は広げません**。指定した中心の半径内に地点が1件も無ければ、②は0点になります
- 描く点は常に入力にある実在の地点です。指定した中心の座標そのものは点として描きません
- 既に選んだ点と描画後に重なる地点は選ばず、その点に代表させます（吸収）
- 特定の地域へ焦点を当てる表現になり、半径外の地域は描かれません

### 評価と採否

両方式の結果を、plot_locations と同じ条件（選んだ点だけで自動フィット）で配置して評価します。

| 指標 | 意味 |
|---|---|
| `represented`（代表性） | 描画後、地点の本来の位置から 24px 以内に点がある地点の割合。どの点へ集約したかではなく見た目で判定するため、③と②を同じ物差しで比べられる |
| `detail`（細かさ） | 点の数 ÷ 描ける点の数（上限と地点数の小さいほう） |
| `legibility`（見やすさ） | 他の点と 16px 未満で重なっていない点の割合（両方式とも構造上1になる） |
| `score`（評価値） | 代表性 × √細かさ × 見やすさ（0〜1） |

**②の評価値が③を 0.05 以上上回ったときだけ②を採用し、それ以外は③を採用します**。第一候補の③を優先し、僅差で方式が入れ替わらないようにするためです。`--method` で方式を指定した場合は、評価によらずその方式を採ります（両方式の評価は要約に残ります）。

## 事前準備

依存パッケージはルートディレクトリで一元管理しています。
初回のみ、プロジェクトルートで以下を実行してください。

```bash
cd {プロジェクトルートの絶対パス}
pnpm install
```

## Claudeへの指示

描画する地点の選択・集約を依頼されたとき、このスキルを使用してください（上記「現在の位置づけ」の制約に従うこと）。

### 手順

1. **入力ファイルの作成**: 候補の地点を、次の形式で `tmp/select_locations_input.json` に保存してください（Write ツールで書き込み）。同じ施設への訪問は、1件ずつ別の要素として並べます。

```json
[
  { "lat": 35.0, "lng": 139.0, "placeId": "place-a" },
  { "lat": 35.0, "lng": 139.0, "placeId": "place-a" },
  { "lat": 35.1, "lng": 139.2 }
]
```

2. **コマンドの実行**: 以下をプロジェクトルートから実行してください。

```bash
cd {プロジェクトルートの絶対パス}
pnpm exec tsx src/geo/select_locations.ts "tmp/select_locations_input.json" "tmp/plot_locations.json"
```

   - **第1引数**: 入力 JSON のパス（必須）。プロジェクトルートからの相対パス、またはプロジェクトルート内を指す絶対パス。プロジェクトルート外や、シンボリックリンク経由で外へ出るパスは指定できません
   - **第2引数**: 出力 JSON のパス（必須）。`tmp/` 配下で、拡張子は `.json` に限ります。同名のファイルがあれば上書きします
   - **`--method auto|cluster|nearest`**（任意）: 既定は `auto`（評価で選ぶ）。`cluster` は③、`nearest` は②に固定します
   - **`--max-points 1〜12`**（任意）: 描く点の上限。既定は 12 で、plot_locations の上限と同じです
   - **`--center 緯度,経度`**（任意）: ②の中心に据える座標（例: `--center 35.6586,139.7454`）。10進数の度で、緯度は ±85.05112878°、経度は ±180° の範囲に限ります。省略時は自動判定です。③の結果には影響しません

   ②の中心を指定して、②の結果を描く場合の例です。

```bash
pnpm exec tsx src/geo/select_locations.ts "tmp/select_locations_input.json" "tmp/plot_nearest.json" --method nearest --center "35.6586,139.7454"
```

   架空の座標で動作を確かめる場合は、入力にフィクスチャを指定します。

```bash
pnpm exec tsx src/geo/select_locations.ts "test/fixtures/geo/select_locations/single_outlier.json" "tmp/plot_locations.json"
```

3. 標準出力の要約 JSON を読み、`pointCount` を確認してください。
   - **`pointCount` が1以上**: 出力 JSON をそのまま plot_locations の入力に渡せます（`pnpm exec tsx src/image/plot_locations.ts "tmp/plot_locations.json" "tmp/location_plot.png"`）
   - **`pointCount` が0**: 描ける地点がありません。出力 JSON は空の配列で、plot_locations は空の配列を受け付けないため、描画の工程は飛ばしてください。次の2通りがあります
     - `method` が `none`: 入力に有効な地点がありません
     - `method` が `nearest`: `--method nearest` と `--center` を指定し、その中心から半径 30km 以内に地点がありませんでした（`nearest.outsideRadius` が地点数と一致します）

### 代表的な分布と結果

フィクスチャ（いずれも架空の座標）に対する結果です。評価値は要約の `cluster.score` / `nearest.score` です。

| フィクスチャ | 分布 | 採用 | 結果 |
|---|---|---|---|
| `tokyo_wide.json` | 都内だけで広く移動（24地点） | ③ | 12点へ集約。②と同点のため第一候補の③ |
| `tokyo_repeats.json` | 同一施設・隣接施設への反復（6地点） | ③ | 重なる地点をまとめて3点。②も3点で同点のため第一候補の③ |
| `tokyo_many_far_few.json` | 東京に多数、遠征先に少数 | ③ | 東京10点＋遠征先1点。②は遠征先が範囲外になる |
| `tokyo_few_far_many.json` | 東京に少数、遠征先に多数 | ③ | 遠征先4点＋東京1点。②は遠征先12点だが東京が範囲外になる |
| `multi_regions.json` | 東京＋遠方の3地域 | ③ | 4地域すべてが残る9点 |
| `rail_line.json` | 路線沿いに約2km間隔で26駅 | ③ | 全線を等間隔に12点。②は中央部だけになる |
| `bay_split.json` | 湾を挟む2地域（12地点） | ③ | 重ならないため全地点をそのまま描く |
| `single_outlier.json` | 都内多数＋遠方の単独1点 | ② | ③は都内が1点に潰れて2点だけになるため、都内を12点で描く②を採る |
| `invalid_entries.json` | 座標の欠落・型違いなどを含む8件 | ③ | 不正な5件を除いた3点 |

### 入力の制約

次の入力はエラーになります（標準エラーへ内容を出し、終了コード1で終わります）。エラー文に座標の値は含まれません。

| ケース | 扱い |
|---|---|
| 配列でない、1001件以上 | エラー |
| 有効な地点の経度の最大値−最小値が 180° を超える（日付変更線をまたぐ） | エラー |
| JSON として解釈できない | エラー |

次の要素はエラーにせず除外し、要約の `input.invalid` に件数を数えます。

| ケース | 扱い |
|---|---|
| オブジェクトでない（`null`・配列など） | 除外 |
| `lat` / `lng` の欠落、数値型以外（文字列の `"35.0"` を含む）、非有限値 | 除外 |
| 経度が ±180° の範囲外、緯度が ±85.05112878° の範囲外 | 除外 |
| `placeId` が空文字、または文字列以外 | 除外 |

0件の配列、すべての要素が除外された配列はエラーにせず、`method: "none"`・空の出力で正常終了します。`lat` / `lng` / `placeId` 以外のプロパティは無視します。

## 出力例

標準出力（要約）:

```json
{
  "method": "nearest",
  "reason": "評価値は集合化（③）0.408、中心近傍選択（②）0.520で、②が③を0.05以上上回ったため②を採用しました",
  "pointCount": 12,
  "input": { "entries": 37, "invalid": 0, "places": 25 },
  "cluster": { "pointCount": 2, "represented": 1, "detail": 0.167, "legibility": 1, "minSpacingPx": 551.6, "score": 0.408, "merged": 23 },
  "nearest": { "pointCount": 12, "represented": 0.52, "detail": 1, "legibility": 1, "minSpacingPx": 29.3, "score": 0.52, "centerSource": "auto", "radiusKm": 30, "outsideRadius": 1, "absorbed": 1, "cut": 11 },
  "outputPath": "/Users/xxx/lineai_aoi_profiles/tmp/plot_locations.json"
}
```

| 項目 | 内容 |
|---|---|
| `method` | 採用した方式。`cluster`（③）/ `nearest`（②）/ `none`（描ける地点なし） |
| `input` | 入力件数（`entries`）、除外した件数（`invalid`）、同じ地点をまとめた後の地点数（`places`） |
| `cluster.merged` | ③で他の点へまとめた地点の数 |
| `nearest.centerSource` | ②の中心の決め方。`specified`（`--center` の指定）/ `auto`（自動判定）。中心の座標そのものは要約に含めません |
| `nearest.outsideRadius` | ②の半径外で描かなかった地点の数 |
| `nearest.absorbed` | ②で近くの点に代表させた地点の数 |
| `nearest.cut` | ②の半径内だが、上限に達して描かなかった地点の数 |

出力 JSON（plot_locations の入力。上の要約と同じ実行結果の12点から2点を抜粋）:

```json
[
  { "lat": 35.6316, "lng": 139.6963, "placeId": "tokyo-20", "places": 1, "visits": 2 },
  { "lat": 35.6789, "lng": 139.7074, "placeId": "tokyo-05", "places": 2, "visits": 3 }
]
```

| 項目 | 内容 |
|---|---|
| `lat` / `lng` | 描く点の位置。常に入力にあった実在の地点の座標 |
| `placeId` | その地点の placeId（入力にあった場合のみ） |
| `places` | この点が代表する地点の数。1なら実地点そのもの、2以上なら周辺の地点をまとめた点 |
| `visits` | この点が代表する地点への入力件数の合計（反復訪問を含む） |

## 注意事項

- **改善できないケース**: 全地点を1枚に同じ縮尺で収める限り、遠方の地点が混じると近場の点は少数にまとまり、細部は失われます（③）。細部を残すと別の地域が範囲外になります（②）。どちらの方式も、東京と遠征先の両方を細部まで描くことはできません
- **② の結果は週全体ではない**: ② を採用した場合、半径外の地域（`nearest.outsideRadius`）は描かれていません。画像を週全体の訪問履歴として扱わないでください
- **点の意味**: 出力する点はすべて実在の訪問地点ですが、`places` が2以上の点は周辺の地点をまとめたものです。点だけでは、他の地点も代表していることは伝わりません
- **取得が不完全な入力**: 取得件数の上限などで候補が欠けている場合、結果もその範囲の要約にすぎません。週全体として扱わないでください
- **位置情報の扱い**: 入力・出力の座標と `--center` に渡す座標は位置情報です。入力 JSON・出力 JSON の中身や中心の座標を、報告本文や Firestore の記録へ転記しないでください
- **計算時間**: すべて別の地点からなる 1,000 件でも、選択・評価の計算は 0.2 秒程度です（ローカル環境での目安。保証値ではありません）
