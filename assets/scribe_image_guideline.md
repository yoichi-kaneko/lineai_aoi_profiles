# SNS投稿画像ガイドライン（綴葉モード用）

> **このファイルの位置づけ**
> 綴葉（scribe）モードが SNS（Twitter / X ほか）へ代筆投稿する際に添える画像の生成ガイドラインです。
> 不特定多数へ向けた発信という性質上、碧衣個人・家族へ届けるデイリーモードの肖像ガイドライン [image_guideline.md](image_guideline.md) とは狙い・構図・被写体の考え方が大きく異なります。両者を混同しないよう、SNS 投稿画像については **本ファイルを正**とし、`image_guideline.md` の枠組みはそのまま流用しません（必要に応じて参照はしてよい）。

## 1. このガイドラインの目的と対象

* **何を作るか**: ユーザーの登山レポートの概要を、**1枚のレポート風レイアウト画像**（インフォグラフィック）としてまとめます。生成した画像は SNS 投稿（`post_twitter`）に添付され、読み手が本文を読まなくても「いつ・どの山・どんな山行だったか」がひと目で伝わることをゴールにします。
* **誰に向けた画像か**: フォロワーを含む**不特定多数**です。ユーザー個人へ向けた私的な演出（労いの眼差し・二人だけに通じる文脈など）ではなく、公開されたレポートの紹介物として単体で成立させます。
* **代筆としての立場**: 画像も SNS 本文と同じく「ユーザー本人のレポートの紹介」です。碧衣とルリはテンプレート内の**案内役（ナビゲーター）**として登場しますが、画像の主役はあくまでレポートの情報です。
* **テキストの描画**: デイリーモードの画像生成とは異なり、**画像内に日本語テキストを積極的に描画します**（登山日・山名・記録数値・紹介文など）。これが本ガイドライン最大の特徴であり、生成後の品質チェック（セクション6）の主対象です。

## 2. デイリーモード肖像ガイドラインとの違い

| 観点 | デイリーモード（image_guideline.md） | SNS投稿画像（本ガイドライン） |
|---|---|---|
| 主役 | 碧衣の肖像・情景 | レポートの情報（碧衣とルリは案内役） |
| 構図 | 毎回ばらつかせる（`random_choice` で抽選） | **report_template.png のレイアウトに固定**。抽選しない |
| 画像内テキスト | 描き込まない（末尾の注意文で抑制） | **積極的に描画する**（確定した文字列を明示指示） |
| 添付資料 | シーンに応じて選定（base.png 必須ほか） | **固定セット**（セクション4参照） |
| ユーザー提供画像 | 素材・着想として参照（忠実な再現に縛られない） | **代表写真をそのままレイアウトに組み込む**（改変しない） |
| 世界観表現 | ホログラム・蛍・オペレーションウェアなど可 | **画像内テキストでは使わない**（公開発信。[aoi_messaging.md](../.claude/rules/aoi_messaging.md) の SNS 宛節と同じ基準） |
| 創作上の飛躍 | 歓迎（架空の情景・描き足し） | **抑制**（レポートに書かれた事実の範囲で構成） |

* デイリーモードの二層モデル（核と彩り）はそのまま流用しません。この画像では「テンプレートのレイアウト・差し込みテキストの正確さ・碧衣とルリの意匠」が核に相当し、自由度は「チップの選び方」「碧衣・ルリの表情」程度の小さな範囲に限られます。

## 3. 生成対象・被写体の方針

### 3-1. レイアウトの各領域と差し込む内容

`report_template.png` のレイアウトを踏襲し、各領域へレポートから読み解いた内容を差し込みます。テンプレートのプレースホルダ（「〇〇山」「20XX年」「仮のテキストです。」「代表的な写真をここに配置」のカメラアイコン、ヘッダ天候欄の仮アイコンなど）は**すべて実際の内容へ置き換え**、置き換え漏れを残さないでください。

| テンプレートの領域 | 差し込む内容 | 主な情報源 |
|---|---|---|
| タイトル帯「登山レポート」 | テンプレートのまま | - |
| 登山日（ヘッダ） | 「YYYY年M月D日（曜）」。複数日の行程は期間で表記 | ステップ3の読み解き（activity_data / header） |
| 山名（ヘッダ） | 主要な山を1つ（例: 「鐘撞堂山」）。1つに絞れない場合は後述の「山名欄の決め方」に従う。**標高は記載しない** | header / activity_detail / Todoist タスク |
| 天候（ヘッダ） | テンプレートの仮アイコンを、`report_designs_2.png` の天候アイコンチップから**山行当日の天候に合うもの**へ置き換え、**アイコンと天候名の文字をセットで描く**（例: 晴れのアイコン＋「晴れ時々曇り」） | activity_detail / header / 代表写真 |
| 代表写真エリア | **添付した代表写真をそのまま配置** | ユーザーの代表写真 |
| 見出し吹き出し | 「〇〇山に行ってきました」（**「！」は付けない**） | 山名 |
| 紹介文（吹き出し内） | 山行の要約を1行あたり短めの文で4〜6行。**「天候」「険しさの度合い」「眺望」を優先**（SNS 本文と同じ観点） | activity_detail |
| コース概要 | 距離／標高差（のぼり）／行動時間 | activity_data |
| 見どころ | 2〜3項目。各項目は15字前後の短い語句・体言止め | activity_detail / checkpoints |
| ひとことメモ | 1〜3行の短い感想・気づき | activity_detail |

#### 山名欄の決め方

ヘッダの山名欄は、読み手が「どこを歩いた記録か」をひと目で掴むための欄です。以下の順で判断してください。

1. **原則は主要な山を1つ**: 山行の中心となった山が明確なら、それだけを記載します（例: 「鐘撞堂山」）。
2. **1つに特定できない場合は2つまで**: 山行の主題が2つに割れており、片方を落とすとレポートの核が伝わらなくなる場合に限り、**中黒でつないで2つまで**併記して構いません（例: 「立山・五色ヶ原」）。3つ以上は併記しません。
3. **主題が3つ以上に及ぶ場合**: 縦走などで主要な対象が3つ以上になるときは、個々の山名を並べず、**それらを包含する山域名・エリア名**を1つ記載します（例: 「北アルプス表銀座」「奥多摩三山」）。
4. **明確な山頂を持たない場所が主題の場合**: 無理に近くの山頂名を当てはめず、**その一帯を指すエリア名・高原名など**をそのまま記載します（例: 「五色ヶ原」「尾瀬ヶ原」）。
5. **目標の山へ届かず撤退・引き返した場合**: 「目指した山」と「実際の最高到達点」が異なるときは、**中黒でつないで併記**します。このとき、**先に置くのは常に「目指した山」**です（例: 「木曽駒ヶ岳・中岳」）。
   - **「最高到達点」と「撤退を判断した地点」は別の事実です**: 山名欄に併記するのは**最高到達点**だけです。撤退を判断した地点は山名欄へ入れず、記録がある場合に紹介文で別に説明してください。両者が同じ地点である山行も多くありますが、同一視して括弧書きにしないでください。
   - **「目指した山」を優先する理由**: このレポートは「その山に登ることを計画し、途中で引き返した」という一続きの物語です。山頂を踏んでいなくても、山行の主目的であった山名を山名欄に置くことに問題はありません。実際に踏んだ最高到達点を併記するのは、読み手へ「どこを目指し、どこまで行った記録か」を誠実に伝えるためです。
   - **併記しない場合**: 併記すると山名欄がヘッダに収まらないほど長くなるとき、または最高到達点の名称が不明確なとき（明確な地点名を持たない登山道の途中まで達した場合など）は、**「目指した山」のみを記載**してください。上記3のように山域名へ寄せる必要はありません。撤退を判断した地点が不明でも、**記録済みの最高到達点は省略しない**でください（最高到達点が分かれば併記し、撤退判断地点だけ紹介文側で一般的な表現に留めます）。
   - **併記した場合も、しなかった場合も**、撤退・引き返しの事実は必ず紹介文の中で明記し、山頂を踏んだかのような誤解を残さないでください（例: 「混雑を見て、中岳で引き返しています」）。見出し吹き出しも、目標の山へ到達したと読める表現は避け、撤退の結果が見出し単体で伝わるようにしてください（例: 「木曽駒ヶ岳を目指し、中岳で引き返した山行」）。

* 山域名・エリア名は、読み手が場所を思い浮かべられる粒度を選びます（「日本アルプス」のように広すぎる呼称は避ける）。
* いずれの場合も標高は記載せず、ヘッダに収まる長さに留めてください。長くなる場合は、より短い呼称を選びます。

#### 目標未達（撤退・引き返し）の山行の雰囲気

撤退・引き返した山行をどういう筆致で扱うか（達成できなかった悔しさを静かに滲ませる／無事の下山をもって手早く前向きに畳まない／悲壮感も煽らない）は、[aoi_messaging.md](../.claude/rules/aoi_messaging.md) の SNS 宛節を正とします。画像全体の雰囲気もそれに揃えたうえで、以下に配慮してください。

* **紹介文・ひとことメモ**: 撤退を判断した地点や理由がレポートに記録されている場合のみ、どこで・なぜ引き返したのかを事実として記します（山名欄の最高到達点と地点が異なる場合も、撤退判断地点はこちらで説明します）。記録が無い場合は推測せず、「途中で引き返した」などの一般的な表現に留めます。そのうえで、心残りや再訪への思いを一言添えます（例: 「山頂を目前に引き返す判断となりました」「次はあの稜線の先まで」）。
* **碧衣の表情・ポーズ**: セクション3-3の指針に従い、達成感や満面の笑みは避け、`report_designs_1.png` の中から**惜しむような・気遣うような表情**、あるいは落ち着いた案内・説明のポーズを選んでください。

### 3-2. 内容の制約（SNS 本文と同じ基準）

* レポートに無い情報を推測で加筆しない（公開されているレポートの範囲で構成する）
* YAMAP バッジの進行状況は含めない
* 「！」を使わない
* 個人・家族が特定される情報や、レポートに公開されていない予定・位置情報を描かない
* ホログラム・ルリの固有名・蛍・ルミナス・ログなどの世界観固有の語彙を**テキストとして描かない**（ルリは絵として登場するが、名前や設定の説明文は入れない）

### 3-3. 碧衣とルリの扱い

* テンプレート通り、画面右側に碧衣（チビ頭身の立ち絵）、傍らにルリを配置します。意匠（碧衣の水色の髪・星のモチーフ・登山装備、ルリのゴーグル・ショルダーバッグ・輝く尾羽）は崩さないでください。
* 表情・仕草は、レポートの手応えや空気に合わせて微調整して構いません。`report_designs_1.png` に碧衣の**ポーズバリエーション**（達成した・余裕がある・案内・説明・疲れている・休憩中 など）と**表情バリエーション**（笑顔・やる気・達成感 など）が用意されているので、山行の空気に合うものを選んでプロンプトで指定してください（例: 重厚な山行なら達成感のあるポーズ・表情、のどかな里山なら案内ポーズに穏やかな笑顔）。この2点が、この画像で許される数少ない「彩り」です。
* 目標の山へ届かず撤退・引き返した山行では、表情・ポーズの選び方に別途の配慮が要ります。セクション3-1の「目標未達（撤退・引き返し）の山行の雰囲気」に従ってください。

## 4. 運用上の前提条件

* **実行条件（代表写真の必須化）**: この画像は代表写真をレイアウトに組み込む方式のため、**ユーザーがアップロードした代表写真が必須**です。欠落時の中断判定は綴葉モード（[modes/scribe.md](../modes/scribe.md)）のステップ2で行われるため、本ガイドライン参照時点では代表写真が `tmp/scribe_featured.{拡張子}` として保存済みであることが前提です。
* **生成手段**: 画像生成は `generate_gpt_image` スキルで行います。プロンプトは `tmp/gpt_image_prompt.txt` 経由で受け渡します。
* **添付ファイルの固定セット**: 以下の4点を固定で添付します（デイリーモードのようなシーン別選定は行いません）。
  1. `report_template.png` — レイアウト・配色・作画スタイルの正
  2. `report_designs_1.png` — チップデザイン集(1)：キャラクター・道具類（碧衣の立ち絵・ポーズバリエーション・表情バリエーション、ルリの立ち絵、登山道具・小物類、ドローン）
  3. `report_designs_2.png` — チップデザイン集(2)：情景・記号類（登山道の地形・オブジェクト、天候アイコンチップ、季節装飾チップ）
  4. `tmp/scribe_featured.{拡張子}` — ユーザーの代表写真
  * `generate_gpt_image` の第二引数は、`assets/images/` 配下のファイル名に加えて **`tmp/` で始まる相対パス**を受け付けます。指定例: `"report_template.png,report_designs_1.png,report_designs_2.png,tmp/scribe_featured.jpg"`
* **キャラクター資料の追加添付（条件付き）**: 通常は上記4点で足ります（テンプレートとチップ集の双方に碧衣・ルリの立ち絵が含まれるため）。**生成結果で碧衣の意匠が明らかに崩れた場合の再生成時に限り**、`outfit_b.png`（登山装備の設定資料）を5点目として追加して構いません。その際は「頭身・作画スタイルは report_template.png の立ち絵を正とし、outfit_b.png は色・装備の意匠の参照に限る」旨をプロンプトへ明記してください（等身の高い作画へ引っ張られるのを防ぐため）。base.png は基本衣装（非登山装備）へ引っ張られる恐れがあるため用いません。
* **プロンプト構成前の画像確認**: プロンプトを構成する前に、`report_template.png`・`report_designs_1.png`・`report_designs_2.png`・代表写真の4点を Read ツールで読み込み、内容を確認してください。テンプレートは領域構成の把握のため、チップ集2枚は散りばめる候補（ポーズ・表情、道具、地形、天候アイコン、季節装飾）の把握のため、代表写真は内容（山容・天候・時間帯）を把握し、紹介文・見どころと矛盾しない画面になるかを確かめるためです。
* **成果物の約束**: 最終的に「画像生成プロンプト本文」と「添付する画像ファイルリスト（カンマ区切り）」の**2点をセット**で用意し、呼び元（綴葉モードのステップ4）が `generate_gpt_image` へ渡します（image_guideline.md と同じ約束事）。
* **生成後の QR コード埋め込み**: 生成・品質チェックを終えた画像には、綴葉モードのステップ4の手順6で **YAMAP レポート URL の QR コード**が後付けで重ねられます（`embed_qr_code` スキル）。QR コードは白い角丸カードごと**画像の右下隅（碧衣の足元のあたり）**へ貼られます。既定では QR 本体が 190px、それを載せる白いカードが 218px 四方です。この工程はプロンプトの外側で行われるため、**プロンプトに QR コードを描くよう指示してはいけません**（画像生成モデルが描いた QR は読み取れません）。プロンプト側で行うのは、次のセクション5⑤の「右下隅の余白の確保」だけです。
* **資料の不足を感じたとき**: 「テンプレートにこの領域が欲しい」「こういうチップがあると表現が広がる」と感じた場合は、`aoi.md` の**共通ステップ：要望のフィードバック**に従って登録してください。

## 5. プロンプト構成フレームワーク

プロンプトは以下の5つのセクションで構成してください。デイリーモードと異なり構図の抽選は行わず、**テンプレートの再現性とテキストの正確さ**を最優先します。

### ① [レイアウトの踏襲]

* プロンプトの冒頭で「添付した report_template.png のレイアウト・配色・作画スタイルを忠実に踏襲してください」と宣言してください（添付資料の見落とし防止。デイリーモードの「冒頭の参照誘導」に相当）。
* あわせて「テンプレート内のプレースホルダのテキスト・カメラアイコン・ヘッダ天候欄の仮アイコンは、後述の指定内容へすべて置き換える」ことを明示してください。

### ② [差し込みテキスト]

* セクション3-1の表に従って確定した文字列を、**領域ごとに全文列挙**してください。画像生成モデルに文章を考えさせず、「以下の文字列を一字一句そのまま描画してください」と指示します。
* 描画する文字はすべて日本語で、フォントの雰囲気はテンプレートを踏襲するよう添えてください。
* 数値（距離・標高差・行動時間）と山名・日付は、ステップ3の読み解き結果と一致していることをプロンプト保存前に見直してください（画像内テキストの誤りは公開後に訂正できません）。

### ③ [代表写真の配置]

* 「添付ファイルリストの最後にある代表写真（tmp/scribe_featured.{拡張子}）を、テンプレートの写真エリアにそのまま配置してください」と指示してください。
* 写真の内容は改変しないことを明示します（フレームに合わせたトリミング・軽微な色調整のみ許容。被写体の描き足し・置き換え・イラスト化はしない）。デイリーモードの「創作上の飛躍」はこの画像には適用しません。

### ④ [チップの散りばめ]

* 「添付した report_designs_1.png / report_designs_2.png のチップ（登山道具・地形オブジェクト・天候アイコン・季節装飾など）を、レイアウトの余白や見出し脇に装飾として散りばめてください」と指示してください。細かい配置指定は不要で、おおよその方向付けで構いません。
* **天候アイコンチップ（ヘッダの天候欄・必須）**: 「天候」はSNS本文・画像の双方で優先的に伝える観点です。テンプレートのヘッダは「登山日｜山名｜天候」の3枠で、天候欄には仮のアイコンが置かれています。`report_designs_2.png` の天候アイコンチップ（晴れ・曇り・雨・雪・風・霧 など）から**山行当日の天候に合うもの**を選び、この仮アイコンを置き換えるよう指示してください（セクション3-1の表参照。散りばめではなく必須の差し込みです）。余白の装飾として天候アイコンを追加で使うのは構いません。
