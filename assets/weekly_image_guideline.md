# 画像生成ガイドライン：結星（天縫が投影する一週間の星座）

> **このファイルの位置づけ**
> 結星（weekly）モードで、プラネタリウム装置「天縫（あまぬい）」が一週間を星座として投影する一枚を生成するためのガイドラインです。結星モードは実装中であり、呼び元は [modes/weekly.md](../modes/weekly.md) のステップ4です。
> 画のタッチと碧衣・ルリの同一性は、日々の肖像ガイドライン [image_guideline.md](image_guideline.md) の**核**を引き継ぎます。それ以外（構図・衣装・登場人物・添付ファイルの選び方）は本ファイルを正とし、`image_guideline.md` の抽選や選定の規則は適用しません（セクション2）。

## 1. 目的と対象

* **何を作るか**: 天縫の専用ドームの中で、碧衣が天縫の投影を見上げている一枚です。天縫は、ドームの中央に**主役の星座を1つ**、その周辺に**その週の思い出のホログラムをいくつか**投影しています。主役の星座は、碧衣がまとめた一週間の出来事（週の要約）から、**画像生成モデルが自由に着想して**作ります。
* **誰に向けた画像か**: ユーザー個人です（`destination: user`）。週が明けた深夜に、前週の一週間をひとつの星座として結んで届けます。
* **このモードの核**: 「週の要約を着想の種として、その週らしい星座を生み出すこと」です。星座の姿はプロンプトで指定しません（セクション5）。

| 観点 | 日々の肖像（image_guideline.md） | 結星（本ガイドライン） |
|---|---|---|
| 主題 | その日の情景（テーマ抽選） | 一週間を象徴する星座（モチーフは画像生成モデルに委ねる）と、その週の思い出のホログラム |
| 構図 | ショットサイズ・カメラ方向を抽選 | **背中越しに下から見上げる構図に固定** |
| 衣装 | シーンに合わせて outfit を選ぶ | **outfit_a（オペレーションウェア）に固定** |
| 登場人物 | ルリ・蛍・漆を抽選 | **ルリは必ず登場、蛍・漆はドームに登場しない**（週の要約に関わる出来事があれば、思い出のホログラムの中にだけ映る） |
| 添付資料 | シーンに合わせて選定 | **固定の4点**と、週の要約に応じた蛍・漆の設定資料（セクション7）。今日の一枚は添付しない |
| 変化の付け方 | 構図・情景・時間帯など | **碧衣の姿勢・ルリの位置・天縫の演出効果の3軸を抽選**（セクション4）と、星座そのもの |
| 画像生成ログ | `image_logs` に記録する | **記録しない**（セクション7） |

## 2. image_guideline.md から引き継ぐもの・引き継がないもの

次の要素は `image_guideline.md` の核（セクション1-1）をそのまま守ります。該当箇所を参照してください。

| 要素 | 参照先 |
|---|---|
| キャラクター同一性（base.png の必須添付、水色の長い髪・水色の瞳、星のモチーフ） | `image_guideline.md` セクション2・セクション8①② |
| 冒頭の参照誘導（base.png を参照させる導入指示） | `image_guideline.md` セクション8① |
| ルリの同一性（ゴーグル・ショルダーバッグ・輝く尾羽）と、ゴーグルの扱い | `image_guideline.md` セクション6 |
| 品質の指示（高品質なアニメスタイル・すっきりとした細い線画・フラットなアニメカラーリング） | `image_guideline.md` セクション8⑤ |
| 末尾の注意文（設定資料の文字・ラベル・注釈を描き込ませない） | `image_guideline.md` セクション8⑤。本ガイドラインでは追記して使う（セクション8⑤） |
| 顔の見え方の確認（目元が中途半端に覗く角度を避ける） | `image_guideline.md` セクション8③ |

キャラクター同一性とルリの同一性は、ドームの中にいる碧衣とルリに適用します。思い出のホログラムの中に映る姿には適用しません（セクション5-3）。

### 2-2. 引き継がないもの

次の規則は結星では使いません。

* 構図2軸（ショットサイズ・カメラ方向）の抽選、重みテーブル、2軸の成立チェック、構図軸の再抽選ログ（セクション8③）
* ルリの登場抽選（セクション6）、蛍・漆の登場抽選（セクション7）
* 添付ファイルの選定ルール（セクション2）、衣装の使い分け（セクション3-1）
* 時間帯・天候・季節を散らす指示（セクション8④）
* 明示指定と抽選の優先順位（セクション3-2）、碧衣の肖像以外を求められた場合（セクション3-3）
* `image_logs` への記録

## 3. 固定する構成要素

### 3-1. 舞台と天縫

* **舞台**: 天縫の専用ドーム（可搬式のドーム）の内部です。ドームの内側全体がスクリーンになり、天縫が全天に星を投影しています。座席や足元を照らすランタンなど、ドーム内部の様子は `amanui.png` の「ドーム内部（投影イメージ）」を参照します。
* **天縫**: 投影展開状態（プラネタリウムモード）で画面に描きます。球体の本体と星のエンブレム、可動アーム（展開パネル）、星光リング（補助投影ユニット）、三脚ベースが意匠の要素です（`amanui.png` の「天縫 本体詳細」「投影展開状態」）。投影レンズからドームの天井へ光が伸び、星座を映し出している様子を描きます。

### 3-2. カメラと画面の配置

* **カメラ**: 碧衣の**背後のやや低い位置**に置き、碧衣の背中越しに、ドームの天井に投影された星座を**下から見上げる**角度で捉えます。`amanui.png` の「ドーム内部（投影イメージ）」と同じ方向の構図です。
* **画面の配置**: 出力は 1536×1024 の横長です。
  * 画面の上部（おおよそ上の3分の2）をドームの星空に充て、**主役の星座を画面上部の中央**に大きく置きます。
  * 思い出のホログラムは、主役の星座の周辺に、主役を遮らないよう置きます（セクション5-3）。
  * 碧衣は画面下部の左右どちらかに寄せ、主役の星座を遮らないようにします。
  * 天縫は画面下部の、碧衣と重ならない位置に置きます。
* **顔の見え方**: 見上げる姿を背後から捉えるため、顔はほとんど写りません。顔を見せない後ろ姿として構成するか、頬から目元まで十分な面積が写る程度に振り向かせるかのどちらかに寄せてください（2-1 の「顔の見え方の確認」）。

### 3-3. 碧衣

* **衣装**: `outfit_a.png` のオペレーションウェアの「ベーススタイル（サイバーデータオペレーター）」に固定します（白いロングコート、黒のインナー、白のサイハイソックスとブーツ、グローブ）。衣装の正は `outfit_a.png` です。`amanui.png` にも同じ装いの碧衣が描かれていますが、衣装の細部は `outfit_a.png` に従います。
* **後ろ姿で同一性を担う要素**: 背面からの構図では、水色の長いポニーテール、髪に留めた星のヘアクリップ、コートの星のパッチが碧衣の同一性を担います。プロンプトで名指ししてください。
* **バックパック**: 背中を覆って後ろ姿が見えにくくなるため、背負わせず、座席の傍らや足元に下ろした状態にしてください。
* **姿勢**: セクション4の抽選で決めます。

### 3-4. ルリと登場人物

* **ルリは必ず登場させます**。登場の抽選は行いません。どこにいるかはセクション4の抽選で決めます。
* ルリのゴーグルは、ドームの中では**額へ掛けたままの状態**を既定とします（`image_guideline.md` セクション6の **ゴーグルの扱い**）。
* **ドームの中にいる人物は碧衣1人です**（ルリは人数に数えません）。蛍・漆はドームには登場しません。
* 週の要約（セクション6）に蛍・漆が関わる出来事がある場合に限り、その出来事を映した思い出のホログラムの中にだけ、蛍・漆を映して構いません。設定資料の添付はセクション7に従います。

## 4. 毎週の変化（3軸の抽選）

構図・衣装・登場人物を固定するため、毎週の一枚に幅を持たせるのは、星座そのものと次の3軸です。**3軸とも、`random_choice` で毎回それぞれ抽選してください**（作者の自己選択で同じ組み合わせに偏るのを防ぐためです）。選択肢は下表の正規化値で渡します。

| 軸 | 値 | 描き方 |
|---|---|---|
| 碧衣の姿勢 | `seated` | ドームの座席に腰掛け、背もたれ越しに天井を見上げる |
| | `standing` | 天縫の傍らに立ち、天井を見上げる |
| | `operating` | 天縫の操作タブレットを手に、投影を整えながら見上げる |
| | `reaching` | 立ったまま、主役の星座へ片手を伸ばす |
| ルリの位置 | `shoulder` | 碧衣の肩に止まり、碧衣と同じ星座を見上げる |
| | `amanui` | 天縫の本体（投影レンズの傍らや可動アームの上）に止まり、星座を見上げる |
| | `flying` | ドームの中を、主役の星座のほうへ飛んでいる |
| 天縫の演出効果 | `shooting_stars` | ドームの星空に流れ星がいくつか走る |
| | `aurora` | ドームの縁に、オーロラの光の帯が揺れる |
| | `nebula` | 星光リング（補助投影ユニット）から、淡い星雲がドームへ広がる |
| | `milky_way` | 天の川が帯となってドームを横切る |

```bash
cd {プロジェクトルートの絶対パス}
pnpm exec tsx src/util/random_choice.ts seated standing operating reaching
pnpm exec tsx src/util/random_choice.ts shoulder amanui flying
pnpm exec tsx src/util/random_choice.ts shooting_stars aurora nebula milky_way
```

* 3軸の抽選は互いに独立です。片方の結果を見て、もう片方の抽選を省略しないでください。
* **演出効果は脇役**です。主役の星座より目立たせず、星空を彩る程度に留めてください。
* 抽選した組み合わせが一枚の絵として成立しないと判断した場合に限り、成立しない軸だけを引き直して構いません。その場合は、引いた組み合わせと成立しないと感じた理由を、`aoi.md` の **共通ステップ：要望のフィードバック** に登録してください（語彙の見直しは開発側で判断します）。「その絵にしたくない」という理由での引き直しはしないでください。

## 5. 星座の作り方

**主役の星座が何の姿かは、プロンプトで指定しません。** 一週間の出来事（セクション6の週の要約）を渡し、画像生成モデルに自由な着想で選ばせます。プロンプトでは、星座の**作り方と画面での見せ方**だけを指示します。作中では、碧衣から一週間の話を聞いた天縫が星座とホログラムを紡ぎ出すもので、何が映るかは碧衣も投影されるまで知りません（生成後の本文の書き方は [modes/weekly.md](../modes/weekly.md) ステップ5）。

### 5-1. 星座の着想の種

* 週の要約（セクション6）を、**主役の星座の着想の種**として渡します。
* 星と星を線で結んで架空の星座を作り、それが何の姿かを、要約の出来事から画像生成モデルに選ばせてください。星の数や配置も画像生成モデルに委ねます。

### 5-2. 主役の星座と幻影

* 画面上部の中央に、**主役の星座を1つ**、ひときわ明るく大きく投影させます。
* 主役の星座は、星を線で結んだ形に、その星座が表す姿の**淡く光る幻影**を重ねて投影させます（何の姿の星座かが一目で分かるようにするためです）。
* 主役の星座の星は、周囲の星より一段明るく、大きく描かせます。

### 5-3. 思い出のホログラムと細かな星

* 主役の星座の周辺に、**その週の思い出のホログラムをいくつか**投影させます。ホログラムは、その週の出来事の情景を映した、淡く光る小さな映像です。主役よりも控えめに描き、主役が一目で分かる強弱を保ちます。
* ホログラムに映す情景は、週の要約（セクション6）の文章だけから描かせます。モード手順で選んだ今日の一枚は添付しません（セクション7）。
* ホログラムの見え方は、`amanui.png` の「ドーム内部（投影イメージ）」を参照します。見本のホログラムに映っている場面は流用しません（セクション5-4）。
* **ホログラムの中の同一性**: ホログラムは、碧衣から一週間の話を聞いた天縫が自動的に描き起こした像です。そのため、ホログラムの中に映る碧衣・ルリ・蛍・漆は、本来の姿と一致しなくても構いません（髪型・衣装・色味などの違い）。同一性の核（セクション2-1）を守るのはドームの中にいる碧衣とルリで、この許容はホログラムの中に限ります。
* 主役の星座の星のほかに、**細かな星をドーム全体へ散りばめ**させます。プラネタリウムの星空としての密度を出すためです。

> **注記（ホログラムの見せ方）**: ホログラムの数（モード手順で選んだ今日の一枚の枚数と揃えるか）、週の要約のうちどの出来事を映すか（選んだ今日の一枚に当たる出来事に絞るか）、主役の星座との強弱と配置の細部は未決定です。

### 5-4. amanui.png のサンプル星座・ホログラムの扱い

`amanui.png` には、投影される星座のサンプル（「投影される星図のサンプル」の6点：灯獣のランタン・銀羽のトリ・渦角のシカ・リボンのクジラ・結晶のカメ・天秤のネコ、および「ドーム内部（投影イメージ）」の中央に描かれたシカの星座）が載っています。

* これらは、**星を線で結んだ形に淡く光る幻影を重ねる、という描き方の参照**に限ります。
* **モチーフとしては流用しません**。サンプルと同じ姿の星座を使わないよう、プロンプトで明示してください。

「ドーム内部（投影イメージ）」には、主役の星座の周辺に浮かぶ思い出のホログラムの見本も描かれています（碧衣とルリ、碧衣と蛍などが映った場面）。

* これらは、**主役の星座の周辺に、淡く光る小さな映像を浮かべる、という見せ方の参照**に限ります。
* **映っている場面は流用しません**。ホログラムに映すのはその週の思い出です（セクション5-3）。見本と同じ場面を映さないよう、また週の要約に関わりの無い人物（見本に映っている蛍など）を描き加えないよう、プロンプトで明示してください。

### 5-5. 前週の主役の星座の扱い

呼び元のモード手順（[modes/weekly.md](../modes/weekly.md) ステップ4）から前週の主役の星座の姿を渡された場合は、毎週同じ星座が続かないよう、**その姿を避ける対象**としてプロンプトに書きます。

* 「前週は〜の姿の星座でした。今週の主役の星座は、それとは別の姿にしてください」のように、**除外として**書いてください。今週の星座の姿を指定することにはならず、モチーフを画像生成モデルに委ねる方針（セクション5の冒頭）はそのままです。
* 前週の星座の姿は、週の要約（セクション6）の中には書かず、④の中の独立した一文として置いてください。
* 渡されなかった場合（前週に結星が実行されなかった場合など）は、この一文を書きません。

## 6. 週の要約の書き方

プロンプトに入れる「一週間の出来事」は、碧衣がまとめた**数行の要約**です。どの出来事を選ぶかは呼び元のモード手順（[modes/weekly.md](../modes/weekly.md) ステップ3）に従い、本セクションは書き方だけを定めます。

* **分量**: 3〜5行。1行に1つの出来事を書きます。
* **書く内容**: いつ頃・どこで・何があったか、そのときの空気（天候・季節・気持ち）を、素直な言葉で書きます。画像生成モデルが着想を広げる材料になるよう、具体的な情景を含めてください。
* **星座を示唆しない**: 星座の名前・姿・モチーフ（「〜座」「〜のような形」など）を書かないでください。何の星座にするかは画像生成モデルに委ねます。
* **技術・運用連絡は含めない**: ユーザーが碧衣の作り手として寄せた技術・運用連絡は、画像生成の素材にしません（[aoi_messaging.md](../.claude/rules/aoi_messaging.md) の「技術・運用連絡の語り方」）。
* **今日の一枚に当たる出来事**: モード手順で選んだ今日の一枚に当たる出来事は、その一枚に描かれていた情景（場所・天候・時間帯・その場の様子）を、その行の中で具体的に書きます。今日の一枚は添付しないため（セクション7）、ホログラムはこの文章だけから描かれます。
* **蛍・漆**: 蛍・漆が関わった出来事は、名前を出して書いて構いません。書いた場合は、該当する設定資料を添付します（セクション7）。
* **個人や居場所を特定しうる情報を書かない**: 実在の人物の名前・住所・施設の正確な位置は書かず、地名は山名や地域名の粒度に留めます。
* **語彙**: 世界観の語彙（ルミナス・ログなど）への言い換えは不要です。

## 7. 運用上の前提条件と手順

* **添付ファイル（固定の4点と、条件付きの2点）**: 次の順で添付します。

  | 順 | ファイル | 役割 |
  |---|---|---|
  | 1 | `base.png` | 碧衣の容姿の正（同一性の維持） |
  | 2 | `outfit_a.png` | 衣装（オペレーションウェアのベーススタイル）の正 |
  | 3 | `ruri.png` | ルリの容姿の正（同一性の維持） |
  | 4 | `amanui.png` | 天縫の本体・専用ドーム・投影の描き方の参照。碧衣の衣装、サンプル星座のモチーフ、見本のホログラムに映っている場面は参照しない |
  | 5 | `hotaru.png`（条件付き） | 週の要約に蛍が関わる出来事がある場合だけ添付する。ホログラムの中に映る蛍の容姿の参照 |
  | 6 | `urushi.png`（条件付き） | 週の要約に漆が関わる出来事がある場合だけ添付する。ホログラムの中に映る漆の容姿の参照 |

  指定例: `"base.png,outfit_a.png,ruri.png,amanui.png"`（週の要約に蛍が関わる出来事がある週は `"base.png,outfit_a.png,ruri.png,amanui.png,hotaru.png"`）
* **蛍・漆の設定資料（条件付き）**: 週の要約（セクション6）に蛍・漆が関わる出来事を書いた場合に限り、該当する側の設定資料を添付します。両方が関わる週は2点とも添付します。ホログラムの中の蛍・漆を、それと分かる姿に近づけるための参照です。添付しても細部が崩れることは許容します（セクション5-3）。
* **今日の一枚は添付しません**: モード手順で選んだ今日の一枚は、参考画像として添付しません。今日の一枚は衣装・構図・登場人物が日ごとに異なり、添付すると碧衣の衣装や構図がそれらに引っ張られるためです。選んだ一枚に描かれていた情景は、週の要約（セクション6）の中で文章として伝えます。
* **プロンプト構成前の画像確認**: プロンプトを書く前に、添付するすべての画像を Read ツールで確認してください。
* **手順**: 次の順で進めます。
  1. **抽選**: セクション4の3軸を抽選する。
  2. **プロンプトの構成**: セクション8のフレームワークに従ってプロンプトを構成し、`tmp/gpt_image_prompt.txt` に保存する。
  3. **プロンプトのレビュー**: **`review_with_codex` スキル**でプロンプトの外部レビューを受け、妥当な指摘を反映して `tmp/gpt_image_prompt.txt` を書き直す。依頼文の組み立てと採否の判断は [codexレビュー](../.claude/docs/codex_review.md)（観点セット **`weekly_image_prompt`**）を正とする。レビューが行われなかった場合（codex が使えない・時間切れなど）は、**再試行せず**手順2のプロンプトのまま手順4へ進む。添付ファイルリストはこの手順では変更しない。
  4. **画像の生成**: `generate_gpt_image` スキルへ、プロンプトと添付ファイルリストを渡して画像を生成し、セクション9の品質チェックを行う。
* **成果物の約束**: 呼び元へは「生成した画像のファイルパス」を返します（`image_guideline.md` セクション3と同じく、プロンプト本文と添付ファイルリストの2点をセットで用意してから生成します）。
* **画像生成ログ（`image_logs`）に記録しない**: 構図・衣装・登場人物を固定し、`image_logs` の抽選軸（ショットサイズ・カメラ方向・登場人物）が意味を持たないためです。識別子（`image_id`）も本文へ添えません。理由の詳細は [../.claude/docs/image_log_schema.md](../.claude/docs/image_log_schema.md) の「結星モードの画像を対象外とする理由」を参照してください。
* **資料の不足や改善点を感じたとき**: 本ガイドラインや設定資料への要望は、`aoi.md` の **共通ステップ：要望のフィードバック** に登録してください。`review_image_feedback` の改善サイクルの対象外のため、これが改善の経路です。

## 8. プロンプト構成フレームワーク

プロンプトは次の5つのセクションで構成してください。構図・衣装・登場人物は固定のため、毎週変わるのは③の姿勢とルリの位置、④の星座の素材（週の要約）と演出効果です。

### ① [対象キャラクター]

* **冒頭の参照誘導**: 「添付した base.png を参照し、そこに描かれているキャラクター『碧衣（あおい）』を描写してください」と、base.png への参照を明示してください（`image_guideline.md` セクション8①）。
* 碧衣の名前、水色の長いポニーテール、髪に留めた星のヘアクリップを明示します。「知的」「静か」「落ち着いた」といった内面の形容を添えてください。
* 「添付した ruri.png のルリ（アビエーターゴーグルを額に掛け、茶色の革のショルダーバッグを提げ、輝く尾羽を持つ水色の小鳥）も登場させてください」と併記します。

### ② [衣装]

* 「添付した outfit_a.png のオペレーションウェアから、ベーススタイル（サイバーデータオペレーター）を採用してください」と明示します。
* 後ろ姿で見える要素（白いロングコートとその星のパッチ、ポニーテールの星のヘアクリップ）を名指しします。
* バックパックは背負わず、座席の傍らや足元に下ろした状態と書き添えます（セクション3-3）。

### ③ [舞台と構図]

* 舞台が天縫の専用ドームの内部であることと、`amanui.png` を天縫とドームの参照に使うことを明示します。
* カメラは碧衣の背後のやや低い位置で、背中越しにドームの天井を見上げる構図と書きます。
* 画面の配置（主役の星座は画面上部の中央、思い出のホログラムはその周辺、碧衣は画面下部の左右どちらか、天縫は碧衣と重ならない下部）を書きます（セクション3-2）。
* 抽選した碧衣の姿勢とルリの位置を、セクション4の「描き方」に沿って具体的に書きます。

### ④ [星座の投影]

* 一週間の出来事（セクション6の要約）を、そのまま列挙します。
* セクション5-1〜5-3の指示（星と星を線で結んで架空の星座を作る／主役の星座1つと幻影／周辺の思い出のホログラム／細かな星）を書きます。
* 「何の姿の星座にするかは指定しません。上の出来事から自由に着想し、この一週間を象徴する姿を選んでください」と、モチーフを委ねる旨を明記します。
* 蛍・漆の設定資料を添付した場合は、「添付した hotaru.png の蛍（ライムグリーンの長いツインテールを持つサイバーポップな少女）」「添付した urushi.png の漆（深紅を差した漆黒の長い髪と和モダンの装いを持つ少女）」のように名指しし、ドームの中ではなく、その出来事を映したホログラムの中にだけ映す旨を書きます（セクション3-4）。
* `amanui.png` のサンプル星座と見本のホログラムを描き方の参照に限り、同じ姿の星座や見本と同じ場面を使わず、週の要約に関わりの無い人物を見本から描き加えない旨を書きます（セクション5-4）。
* 前週の主役の星座が渡されている場合は、その姿を避ける旨を書きます（セクション5-5）。
* 抽選した天縫の演出効果を書き、主役の星座より控えめにする旨を添えます。

### ⑤ [スタイルと品質]

* 「高品質なアニメスタイル」「すっきりとした細い線画」「フラットなアニメカラーリング」を固定の品質指示として含めてください（`image_guideline.md` セクション8⑤）。
* 照明は、ドーム内の暗がりに投影の星明かりと、足元のランタンの柔らかな灯りを基本とします。
* **末尾の注意文**: `image_guideline.md` の標準文言に、結星固有の項目を追記して置きます。

  > 注意：添付した設定資料に含まれる文字・ラベル・注釈は、生成画像に一切描き込まないでください。amanui.png の見出し・説明文・星座サンプルの名前も描かないでください。星座の名前や、ホログラムの中の日付・地名などの文字も画像に入れないでください。

## 9. 品質チェックと再生成

生成後、生成画像を Read ツールで読み込み、次を確認してください。

1. **碧衣の同一性**: ドームの中にいる碧衣について、後ろ姿でも、水色の長いポニーテール・星のヘアクリップ・outfit_a の白いロングコートが保たれているか。
2. **ルリ**: ドームの中にルリが描かれており、抽選した位置にいて、ゴーグル・ショルダーバッグ・尾羽の同一性が保たれているか。
3. **主役の星座と思い出のホログラム**: 画面上部の中央に主役の星座が1つあり、星を線で結んだ形と幻影から、何の姿か読み取れるか。その周辺に思い出のホログラムがいくつかあり、主役の星座を遮らず、主役より控えめに描かれているか。
4. **資料の見本・前週の星座との重複**: 主役の星座が、`amanui.png` のサンプル星座と同じ姿になっていないか。思い出のホログラムに、`amanui.png` の見本と同じ場面や、週の要約に関わりの無い人物（見本に映っている蛍など）が描かれていないか。前週の主役の星座が渡されている場合は、今週の主役の星座が同じ姿になっていないか。
5. **文字の写り込み**: 資料のラベル・星座の名前・ホログラムの中の日付や地名などの文字が描き込まれていないか。
6. **構図**: 背中越しに見上げる構図になっており、天縫が描かれているか。

* **再生成のルール**: 上記1〜6で重大な問題を見つけた場合は、プロンプトへ問題点への対策を一言加えて **1回だけ**再生成してください。
* **軽微な乱れの扱い**: 細かな星の散り方や、ホログラムの多少の崩れなど、主役の星座と碧衣・ルリの同一性に影響しない乱れは、再生成せず続行して構いません。ホログラムの中に映る碧衣・ルリ・蛍・漆の姿が本来と違っていても、再生成の理由にしません（セクション5-3）。

[スタイルと品質]
