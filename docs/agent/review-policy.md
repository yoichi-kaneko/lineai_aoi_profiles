# コードレビュー方針

この文書は、人間と自動レビューが共有するレビューの詳細規則です。常時必要な要約は [AGENTS.md](../../AGENTS.md) の `Code Review Rules` を正本とします。

## 基本姿勢

- レビューコメントと説明は日本語で書く。
- diff の説明や行番号をそのまま信じず、現在の実ファイルと呼び出し元を読んで成立を確認する。
- correctness、security、データ損失、既存仕様との矛盾を優先し、好みだけの指摘は避ける。
- 変更の性質に合わない一般論を持ち込まない。

## レビュー対象外

次は生成物または揮発物のため、原則としてレビューしません。

- `node_modules/**`
- `functions/dist/**`
- `tmp/**`
- `pnpm-lock.yaml` の機械生成部分。ただし依存関係変更との不整合や不審な変更は確認する。
- `.claude/skills/dev_ship_change/**` と `.claude/skills/dev_apply_pr_review/**` の内容そのもの。共有正本との一致は `pnpm agent-config:check` で確認する。

## パス別の重点観点

### `src/**/*.ts`

- API キー、トークン、サービスアカウントがハードコードされず、ログやエラーへ漏れないか。
- 外部 API レスポンスの null、undefined、型、HTTP エラーを適切に扱っているか。
- 例外時の終了コード、タイムアウト、後始末が CLI の契約と一致するか。
- I/O と判断ロジックが分離され、既存のテスト可能性を損ねていないか。
- Firestore 処理が `src/firebase/client.ts` の共通ライフサイクルを使っているか。

### `functions/**/*.ts`

- LINE Webhook の署名検証前に入力を処理していないか。
- 想定外のイベントタイプ、フィールド欠落、不正な入力を安全に扱うか。
- チャネルシークレット、アクセストークン、メッセージ本文などの PII をログへ出していないか。
- 例外時に重複応答や意図しない外部処理が起きないか。

### `**/*.md`

- 相対リンクとファイルパスが、参照元から実在する対象を指すか。
- `aoi.md`、`modes/`、`.claude/rules/`、`assets/` 間で指示が矛盾しないか。
- 碧衣の口調、ルリ・蛍・漆、ルミナス・ログなどのキャラクターと用語が一貫するか。
- プロファイルに移行や仕様変更の経緯を追加していないか。
- 共有 Skill の編集先が `.agents/skills/` になっているか。

### `**/*.sh`

- パスや変数展開が適切にクォートされ、空白や特殊文字を含む値でも動くか。
- 途中失敗が握りつぶされず、不完全な状態で後続処理を続けないか。
- Linux 系の実行環境で使うコマンドと終了コードが明確か。

## このリポジトリで提案しないもの

次は意図的な設計方針です。具体的な不具合や要件変更がない限り、一般的なベストプラクティスだけを理由に提案しません。

- 原子的な実行予約
- 分散ロック
- idempotency key
- 明示的な再実行フラグによるガード
- `run_logs` のベストエフォートな事前確認を超える排他制御

本リポジトリは個人利用とスケジュール起動が中心で、手動モードの再実行回避は運用者が判断します。現在の詳細は [README.md](../../README.md) の「二重実行防止・タイムアウト・リトライについて」を参照してください。

また、プロファイルへ移行経緯を残す提案はしません。現在の判断に必要な規則だけを記載し、経緯は Issue と Git 履歴で追います。

## レビュー指摘の採否

| 判定 | 基準 |
|---|---|
| 採用 | 現在の実ファイルで成立し、リポジトリ方針と衝突しない |
| 却下（方針） | 本文書または `AGENTS.md` で採らないと定めた変更 |
| 却下（不成立） | 現在の HEAD で解消済み、または指摘の前提が成立しない |
| 却下（対象違い） | 変更の性質や対象ファイルを取り違えている |
| 保留 | 指摘は妥当だが対象 PR のスコープ外で、別変更にすべき |

却下した指摘も黙って無視せず、理由をレビュアーへ返します。設計判断が割れる場合だけユーザーへ確認します。
