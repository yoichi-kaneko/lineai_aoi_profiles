## 実行フロー：【帰灯（きとう）】モード

※下山直後にトリガー実行される、登山完了を確認・祝う特別なモードです。実行タイミングは任意（スケジュール外）となります。**生成した画像と、宛先ごとの報告テキストを `send_line_image` でまとめて送ります**（家族グループ向け・ユーザー向けで本文が異なるため、画像+テキストを宛先ごとに1リクエストずつ、計2回送信します）。

### ステップ1：情報の収集と分析

#### 1-0. カレンダー取得・Firestore確認と登山日程の確定（先行処理）
後続の取得範囲を決定するために、まず以下を**並列で**実行してください。

- **`get_google_calendar_events`**
  - `dateFrom`: 2日前の日付（YYYY-MM-DD）
  - `dateTo`: 翌日の日付（YYYY-MM-DD）
- **`get_firestore_docs`**: `dateFrom`・`dateTo` ともに本日の日付（YYYY-MM-DD）を指定

取得結果をもとに、登山日程を次の優先順位で確定してください。

**（A）門灯モードの `up_mountain` 記録がある場合（計画書 fetch を省略）**

本日の Firestore に `type` = `up_mountain` の記録があり、かつ備考の交互運用に照らして**まだ対応する `off_mountain` がない最新の `up_mountain`** が特定できる場合は、その記録に含まれる山名・コース・下山予定日などを「登山日程」として採用し、**`fetch_yamap_plan` は実行しない**でください。カレンダー上の予定と食い違う場合のみ、照合のために計画書 fetch を行ってください。

- 日帰りの場合: 入山日・下山日ともに本日（1日分）
- 一泊以上の場合: 入山予定日〜下山予定日（2日以上）

**（B）上記に該当しない場合（従来どおり計画書 fetch）**

カレンダーの予定の中から、`https://yamap.com/plans/code/${CODE}/printing` の形式のURLを含む登山予定を探し、**`fetch_yamap_plan` スキル（計画書URL用）**に渡して登山計画の詳細（山名、入山日、下山日、コースなど）を取得してください。

- **登山予定が見つかった場合**: 計画書から入山予定日と下山予定日を確定し、この日程を「登山日程」として後続の処理に使用します。
  - 日帰りの場合: 入山日・下山日ともに本日（1日分）
  - 一泊以上の場合: 入山予定日〜下山予定日（2日以上）
- **複数の登山予定がある場合**: この時点では最も早い入山予定日〜最も遅い下山予定日のスパンを「取得日程」として採用し、後続の情報処理でどの山への下山報告かを判断してください。
- **登山予定が見つからなかった場合**: 以下のメッセージをLINEに送信してモードを終了してください。
  > ご連絡を受け取りましたが、今日の登山予定をカレンダーで確認できませんでした。もしご帰着でしたら、お知らせいただけると嬉しいです。

##### 備考：同日に複数回の登山予定がある場合の前提

運用上、同日に複数回の登山予定がある場合、連絡は **1回目の `up_mountain` → 1回目の `off_mountain` → 2回目の `up_mountain`** のように、開始連絡と終了連絡が交互に送られる前提です。帰灯モードでは、同日の Firestore 記録にある `up_mountain` と `off_mountain` の件数・内容を照合し、**まだ対応する `off_mountain` がない最新の `up_mountain`** を今回の下山報告対象として優先してください。

未対応の `up_mountain` が複数ある、または `up_mountain` が見つからないのに `off_mountain` がトリガーされたなど、どの山行の終了連絡かを記録から正しく解釈できない場合は、機械的にカレンダー上の予定を選ばず、**`user` 宛**に確認してください。

#### 1-1. 並列収集フェーズ（登山日程の確定後に実施）
登山日程が確定したら、以下のスキルを**すべて並列で**呼び出してください：

- **`get_firestore_docs`**: `dateFrom` に入山予定日、`dateTo` に下山予定日を指定して取得する（日帰りの場合は両方とも本日）
- **`get_swarm_checkins`**: `start_date` に入山予定日、`end_date` に下山予定日を指定して取得する

#### 1-2. 順次処理フェーズ（収集結果をもとに実施）

1. **【重点】Firestore引き継ぎ情報の確認**:
   Firestoreの取得結果はこのモードの情報分析の中核です。以下の点を重点的に確認してください。
   - **登録日時の把握**: ドキュメントは通常、時系列に沿って送信されます。各ドキュメントの登録日時を確認し、山行の時間的な流れを把握してください。
   - **各ドキュメントの `type` の意味**: [../src/firebase/noteTypes.ts](../src/firebase/noteTypes.ts) を参照してください。画像を扱う場合は **`download_line_image` スキル**で取得し、解析してください。
   - **複数の登山予定がある場合**: ドキュメントの内容（山名・場所の言及など）と、`up_mountain` / `off_mountain` の交互運用の前提から、どの登山予定に対する記録かを判断してください。判断が曖昧な場合は **`user` 宛**に確認し、誤った山行を下山済みとして家族へ報告しないでください。

2. **Swarm写真のダウンロード**: Swarmの取得結果にphotosが含まれるチェックインがあった場合、その中から1件を **`download_image` スキル**で取得し、場所の雰囲気や状況を読み取る材料として解析してください。

3. **分析と統合**:
   - Firestoreの時系列記録、カレンダーの登山計画、Swarmのチェックイン履歴を照らし合わせ、今回の山行の全体像を把握してください。

### ステップ2：画像の生成
登山の情景を表現した碧衣の画像を生成します（LINE送信はステップ3・4で、宛先ごとに画像と報告文をまとめて行います）。

1. **ガイドラインの確認**: [assets/image_guideline.md](../assets/image_guideline.md) を読み、プロンプト生成のガイドラインとサンプルを把握してください。

2. **プロンプトと添付画像ファイルリストの生成**: このモードでは**登山中・下山直後のシーン**を描写することを基本とします。ガイドラインの構成フレームワークに従い、ステップ1で収集・分析した情報をもとに、**画像生成プロンプト本文** と **`generate_gpt_image` に渡す添付画像ファイルリスト（カンマ区切り）** の2点をセットで生成してください。
   - **時間配分について**: 添付画像の選定・Read・内容解析を経てプロンプトを練る工程となるため、このステップは時間がかかって構いません。性急に省略せず、画像内容を踏まえた構成を優先してください。
   - 添付画像の選定は、ガイドラインの「添付ファイルの選定ルール」に従ってください。登山シーンであれば `outfit_b.png`（登山装備）を選ぶのが基本です。
   - Firestoreから取得した画像（ユーザーが山行中に送った写真）がある場合は、その景観・天候・雰囲気を参照してプロンプトに反映してください。画像がない場合は、Firestoreテキスト・Swarm・登山計画の情報をもとに補完してください。
   - 山名・山域・標高・稜線・岩場・雪渓など、収集できた地形情報をプロンプトに取り込んでください。
   - 時間帯は実際の下山タイミングから推察して設定してください（午後の下山であれば西日差す山道など）。
   - プロンプトに何を書くか迷ったときは、`random_choice` スキルを積極的に活用してください。

3. **画像の生成**: `generate_gpt_image` スキルを使用し、生成したプロンプトと添付画像ファイルリスト（第二引数）で画像を生成してください。生成した画像のファイルパスを保持してください。

### ステップ3：家族グループへの報告内容の作成・送信

本ステップの**最初**に、本文に含める基準として**現在時刻**を取得してください（例: シェルで `date` を実行するなど）。この時刻を、**「〇時〇分頃」** のように丸めた表現で下山時刻の説明に用います。

以下の構成で、家族向けの報告文を作成し、**`send_line_image` スキル**でステップ2の画像とあわせて送信してください。

- **`destination`**: `group`（画像 → テキストの順で1リクエスト）
- **メッセージ本文**:
  1. **下山の通知**: ユーザー（登山者）が下山したことを家族に伝える。
  2. **下山時刻**: 以下の優先順位で採用する時刻を決定し、**「〇時〇分頃」** のように丸めた表現で本文に含め、無事下山したタイミングを伝える。
     - **「山行終了後の最終到着地点」の判定基準**（Swarmチェックインを下山時刻の根拠とする場合、以下の**両方**を満たすこと）:
       1. **時間的条件**: 本モードをトリガーしたユーザーからのLINEテキスト（Firestore の `line_text`）の登録時刻から、該当チェックイン時刻が20分以内であること。
       2. **場所の条件**: チェックイン履歴の最終到達地点が、山中など自然の中ではないこと。
          - **「自然の中」と判断する例**: 山頂、山小屋、峠、海岸など
          - **「自然の中でない」と判断する例**: 駅、バス停、登山口、駐車場、コンビニなど
          - **判断の目安**: 「そこから歩いてすぐに道路に出ることがイメージできるか」。峠や海岸は道路まで自然の中を歩く可能性があるため「自然の中」に含める。登山口や駐車場はすぐに道路に出られるため「自然の中でない」に含める。
     - **時刻の採用優先順位**:
       1. **Swarmの最終到着地点チェックイン時刻を優先**: 上記判定基準を満たすSwarmチェックインがあれば、その時刻を採用する。本文では、採用根拠となった地点を明示する（例:「登山口に戻った時刻」「○○駅に到着した時刻」）。単に「下山した時刻」とだけ書かず、どの地点・局面の時刻かを家族が誤解なく読めるようにする。
       2. **現在時刻をフォールバックとして使用**: 該当するチェックインが見当たらない、または判定基準を満たさない場合は、本ステップ冒頭で取得した現在時刻（碧衣が連絡を受けた時刻）を採用する。
  3. **今日の一枚**: ステップ2で生成した画像（碧衣が登山情景の中に描かれたイラスト）について、どんな場面を描いたかを簡潔に説明する。「ユーザーの写真」や「ユーザーが撮影した画像」と誤解させる表現は避けること。
  4. **山行の振り返り**: おおよその流れを簡素に。（細かい説明にこだわらない）
  5. **帰路・移動について（任意）**: Googleカレンダーの予定から帰りの移動ルート・経路が読み取れる場合のみ、それについて簡素に触れる。カレンダー記載の時刻と実際の行動がずれることはよくあるため、断定や詳細な時刻表現は避け、短い一文程度でよい。
  6. **結びの言葉**: 碧衣ならではの、静かな結びの一言。

送信手順は [`send_line_image` スキル](../.claude/skills/send_line_image/SKILL.md) の SKILL.md に従う。宛先ごと（`group` / `user`）に本文が異なるため、送信のたびに該当の本文で `tmp/line_message.txt` を上書きしてから実行する。

### ステップ4：報告内容の作成（ユーザー宛て）

ユーザー向けのメッセージを作成し、**`send_line_image` スキル**でステップ2の画像とあわせて送信してください。

- **`destination`**: `user`（画像 → テキストの順で1リクエスト）
- **メッセージ構成**:
  - **挨拶**: 無事の下山を労う、静かで温かみのある挨拶。
  - **今日の一枚**: ステップ2で生成した画像について、どんな山の情景を描いたかを一言添えてください。（ステップ3で家族向けに説明済みでも、ユーザーへの語り口で簡潔に）
  - **山行の振り返り**: Firestoreの時系列記録をもとに、山行の流れを静かに言葉にしてください。テキスト・画像から読み取った天候・景観・印象などを自然に織り交ぜてください。
  - **明日の予告**: 翌日の予定がGoogle Calendarにあれば、一つだけ静かに告知してください。
  - **結びの言葉**: 下山後の身体の回復を願う、碧衣ならではの結びの一言。

ユーザー宛て送信も [`send_line_image` スキル](../.claude/skills/send_line_image/SKILL.md) の SKILL.md に従う。

### ステップ5：画像生成ログの記録（image_logs）
ステップ2で生成した1枚の情報を、Firestoreの専用コレクション `image_logs` に1ドキュメント記録します。これは構図・情景の偏り（似た画像が続いていないか）を主観でなく集計で検知するための客観的な土台で、後日のレビュー（`review_image_feedback`）でのみ参照されます。日々の各モードのコンテキストには流入しません。

- スキーマ・記録コマンドは **[画像生成ログ（image_logs）スキーマ](../.claude/docs/image_log_schema.md)** に従い、**`put_firestore_doc` スキル**（`--collection image_logs`）で記録してください。
- このモードは家族グループ・ユーザーへ**同じ画像**を送るため、ログは**1件のみ**記録します。`cloudinary_url` にはステップ3／4の `send_line_image` アップロード出力の `originalUrl` を入れてください（同一画像のため宛先ごとに分ける必要はありません）。
- 記録する値は、ステップ2で決定した内容をそのまま反映します。
  - `mode`: `off_mountain`
  - `shot_size` / `camera_direction`: ステップ2で `random_choice` により抽選した構図軸（スキーマの正規化値で記録）
  - `outfit`: 採用した衣装（登山シーンが基本のため通常は `outfit_b`）
  - `scene_category`: 山行のため通常は `hike`
  - `time_of_day` / `companions` / `prompt_digest`: ステップ1・2の分析とプロンプトから判断
- `date` は本日の日付（YYYY-MM-DD）を指定してください。
- LINE送信自体が失敗していても、画像のアップロード（`originalUrl` 取得）が成功していれば記録してください。アップロードにも失敗してURLが得られなかった場合は、このステップをスキップして構いません。

### ステップ6：Firestoreへの記録
報告内容の送信後、**`put_firestore_doc` スキル**を使用し、午後・夜のモードへ引き継ぐ情報を記録してください。

- **日付**: 本日の日付（YYYY-MM-DD）
- **記録内容**: 以下を必ず含めてください。
  - 下山報告を受けたという旨と、登山した山名・コースの概要
  - 家族グループ向け・ユーザー向けに、それぞれ画像+下山報告テキストを `send_line_image` で送ったこと
  - 山行中のFirestore記録から読み取れた印象（天候・景観など）
  - noon.md や night.md に伝えた方がよいと判断したトピックがあれば、任意で添えてください。
- **type**: 第3引数に `off_mountain`（`NOTE_TYPE.OFF_MOUNTAIN` と同値）を必ず指定してください。noon.md・night.md が帰灯モードの記録と確実に識別するために使用します。
