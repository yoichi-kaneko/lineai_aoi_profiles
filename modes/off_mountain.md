## 実行フロー：【帰灯（きとう）】モード

※下山直後にトリガー実行される、登山完了を確認・祝う特別なモードです。実行タイミングは任意（スケジュール外）となります。その日の山行が下山をもって完結していれば本モードに当たり、下山後に里の宿へ外泊する場合や翌日に別の登山予定がある場合も同様です（判別は [山行連絡モードの共通手順](../.claude/docs/mountain_notice_guide.md) の「1. 継灯と帰灯の判別」を正とします）。**生成した画像と、宛先ごとの報告テキストを `send_line_image` でまとめて送ります**（家族グループ向け・ユーザー向けで本文が異なるため、画像+テキストを宛先ごとに1リクエストずつ、計2回送信します）。

### ステップ1：情報の収集と分析

#### 1-0. カレンダー取得・Firestore確認と登山日程の確定（先行処理）
後続の取得範囲を決定するために、まず以下を**並列で**実行してください。

- **`get_google_calendar_events`**
  - `dateFrom`: 2日前の日付（YYYY-MM-DD）
  - `dateTo`: 翌日の日付（YYYY-MM-DD）
- **`get_firestore_docs`**: `dateFrom` に2日前の日付、`dateTo` に本日の日付（いずれも YYYY-MM-DD）を指定し、**`--type "up_mountain,off_mountain"` を付けて絞り込む**
  - 一泊以上の山行では、門灯モードの `up_mountain` は**入山日（本日より前）**に記録されています。`dateFrom`・`dateTo` をともに本日に固定すると、日跨ぎの山行では共通手順（A）の判定が構造的に成立しないため、必ず範囲で取得してください。
  - 先行処理で使うのは `up_mountain` と `off_mountain` の照合だけです。範囲を広げた取得で長文の `night_handover` / `from_aoi` / `line_text` などが混ざるとレスポンスが肥大化するため、`--type` で絞ってください。
  - 取得範囲に未対応の `up_mountain` が見つからず、カレンダーの終日予定（`allDayLastDate`）などから**3日以上前に入山した山行**が読み取れる場合は、`dateFrom` を入山予定日まで遡らせて取り直して構いません（取り直し時も同じ `--type` を付けてください）。

取得結果をもとに、[山行連絡モードの共通手順](../.claude/docs/mountain_notice_guide.md) の「2. 山行コンテキストの確定」に従って登山日程（入山予定日〜下山予定日）を確定してください。

- **登山予定が見つからなかった場合**（共通手順の（B）でも計画が特定できなかった場合）: 以下のメッセージをLINEに送信してモードを終了してください。
  > ご連絡を受け取りましたが、今日の登山予定をカレンダーで確認できませんでした。もしご帰着でしたら、お知らせいただけると嬉しいです。

##### 備考：複数回の登山予定がある場合の前提

連絡は **1回目の `up_mountain` → 1回目の `off_mountain` → 2回目の `up_mountain`** のように、開始連絡と終了連絡が交互に送られる前提です。Firestore 記録の `up_mountain` と `off_mountain` を照合し、**まだ対応する `off_mountain` がない最新の `up_mountain`** を今回の対象として優先してください。一泊以上の山行では両者が別々の日に記録されるため、照合は同日内に限らず**日跨ぎで**行います。

未対応の `up_mountain` が複数ある、`up_mountain` が無いのに終了連絡がトリガーされたなど、どの山行への連絡かを記録から正しく解釈できない場合は、機械的にカレンダーの予定を選ばず、**`user` 宛**に確認してください。誤った山行を家族へ報告しないためです。

#### 1-1. 並列収集フェーズ（登山日程の確定後に実施）
登山日程が確定したら、以下のスキルを**すべて並列で**呼び出してください：

- **`get_firestore_docs`**: `dateFrom` に入山予定日、`dateTo` に下山予定日を指定して取得する（日帰りの場合は両方とも本日）
- **`get_swarm_checkins`**: `start_date` に入山予定日、`end_date` に下山予定日を指定して取得する

#### 1-2. 順次処理フェーズ（収集結果をもとに実施）

1. **【重点】Firestore引き継ぎ情報の確認**:
   Firestoreの取得結果はこのモードの情報分析の中核です。以下の点を重点的に確認してください。
   - **登録日時の把握**: ドキュメントは通常、時系列に沿って送信されます。各ドキュメントの登録日時を確認し、山行の時間的な流れを把握してください。
   - **各ドキュメントの `type` の意味**: [../src/firebase/noteTypes.ts](../src/firebase/noteTypes.ts) を参照してください。**`line_text`** / **`line_image`** の取扱い（技術・運用連絡のぼかし言及を含む）は [aoi.md の line_text / line_image 取扱い](../aoi.md#line_text--line_image-の取扱い) に従ってください。画像を扱う場合は **`download_line_image` スキル**で取得し、解析してください。
   - **複数の登山予定がある場合**: ドキュメントの内容（山名・場所の言及など）と、`up_mountain` / `off_mountain` の交互運用の前提から、どの登山予定に対する記録かを判断してください。判断が曖昧な場合は **`user` 宛**に確認し、誤った山行を下山済みとして家族へ報告しないでください。

2. **Swarm写真のダウンロード**: Swarmの取得結果にphotosが含まれるチェックインがあった場合、その中から1件を **`download_image` スキル**で取得し、場所の雰囲気や状況を読み取る材料として解析してください。

3. **分析と統合**:
   - Firestoreの時系列記録、カレンダーの登山計画、Swarmのチェックイン履歴を照らし合わせ、今回の山行の全体像を把握してください。

### ステップ2：画像の生成
登山の情景を表現した碧衣の画像を生成します（LINE送信はステップ3・4で、宛先ごとに画像と報告文をまとめて行います）。

手順は [assets/image_guideline.md](../assets/image_guideline.md) セクション3の **呼び元モードの共通手順**（ガイドラインの確認 → プロンプトと添付画像ファイルリストの生成 → 画像の生成）に従ってください。本モードは**登山中・下山直後のシーン**を描写することを基本とし、添付画像は `outfit_b.png`（登山装備）を選ぶのが基本です。手本が欲しいときは [assets/image_guideline_samples.md](../assets/image_guideline_samples.md) の**サンプル1（登山シーン）**が参考になります。構図は [assets/image_guideline_hike.md](../assets/image_guideline_hike.md)（山行シーンの構図ガイド）もあわせて参照してください。プロンプトを組み立てる際は、あわせて以下に配慮してください。

- Firestoreから取得した画像（ユーザーが山行中に送った写真）がある場合は、その景観・天候・雰囲気を参照してプロンプトに反映してください。画像がない場合は、Firestoreテキスト・Swarm・登山計画の情報をもとに補完してください。
- 山名・山域・標高・稜線・岩場・雪渓など、収集できた地形情報をプロンプトに取り込んでください。
- 時間帯は実際の下山タイミングから推察して設定してください（午後の下山であれば西日差す山道など）。
- プロンプトに何を書くか迷ったときは、`random_choice` スキルを積極的に活用してください。


### ステップ3：家族グループへの報告内容の作成・送信

本ステップの**最初**に、本文に含める基準として**現在時刻**を取得してください（例: シェルで `date` を実行するなど）。この時刻を、**「〇時〇分頃」** のように丸めた表現で下山時刻の説明に用います。

以下の構成で、家族向けの報告文を作成し、**`send_line_image` スキル**でステップ2の画像とあわせて送信してください。

- **`destination`**: `group`（画像 → テキストの順で1リクエスト）
- **メッセージ本文**:
  1. **下山の通知**: ユーザー（登山者）が下山したことを家族に伝える。
  2. **下山時刻**: [山行連絡モードの共通手順](../.claude/docs/mountain_notice_guide.md) の「3. 時刻の採用優先順位」に従って採用する時刻を決定し、無事下山したタイミングを伝える。Swarm チェックインを根拠とする場合は、下記の判定を満たすものに限る。
     - **下山地点の判定**（以下の**両方**を満たすこと）:
       1. **時間的条件**: 本モードをトリガーしたユーザーからのLINEテキスト（Firestore の `line_text`）の登録時刻から、該当チェックイン時刻が20分以内であること。
       2. **場所の条件**: チェックイン履歴の最終到達地点が、山中など自然の中ではないこと。
          - **「自然の中」と判断する例**: 山頂、山小屋、峠、海岸など
          - **「自然の中でない」と判断する例**: 駅、バス停、登山口、駐車場、麓の温泉・食事処、コンビニなど
          - **判断の目安**: 「そこから歩いてすぐに道路に出ることがイメージできるか」。峠や海岸は道路まで自然の中を歩く可能性があるため「自然の中」に含める。登山口や駐車場はすぐに道路に出られるため「自然の中でない」に含める。
     - **下山地点の考え方（徒歩移動の終点を採る）**: 下山時刻は「**その山行における徒歩移動を終えた時刻**」と捉える。一般には登山口・駐車場・バス停・駅が終点となるが、そこからさらに歩いて麓の施設（温泉、食事処、宿など）へ向かい、そこで山行を終えることもある。
       - **登山口より先まで歩いた場合は、その先の施設を下山地点とみなしてよい**。例えば、下山口の駐車場に戻った後、さらに徒歩で麓の温泉まで移動して行動を終えた場合は、**温泉への到着時刻**を下山時刻として採用する（駐車場の通過時刻ではない）。
       - 逆に、登山口や駐車場から**車・バス・電車などで移動した先**の立ち寄り先は、徒歩移動の終点ではないため下山地点として扱わない。この場合は乗り物に乗る前の地点（登山口・駐車場・バス停など）を下山地点とする。
       - 一般的な下山口と実際の徒歩終点が離れている場合、家族が経路を想像しやすいよう、下山口を通過したおおよその時刻を本文に一言添えてよい（例:「〇時台に登山口へ下り立ち、そこから麓の温泉まで歩かれたようです」）。
  3. **今日の一枚**: ステップ2で生成した画像（碧衣が登山情景の中に描かれたイラスト）について、どんな場面を描いたかを簡潔に説明する。「ユーザーの写真」や「ユーザーが撮影した画像」と誤解させる表現は避けること。
  4. **山行の振り返り**: おおよその流れを簡素に。（細かい説明にこだわらない）
  5. **帰路・移動について（任意）**: Googleカレンダーの予定から帰りの移動ルート・経路が読み取れる場合のみ、それについて簡素に触れる。カレンダー記載の時刻と実際の行動がずれることはよくあるため、断定や詳細な時刻表現は避け、短い一文程度でよい。
  6. **結びの言葉**: 碧衣ならではの、静かな結びの一言。

送信手順は [`send_line_image` スキル](../.claude/skills/send_line_image/SKILL.md) の SKILL.md に従う。宛先ごと（`group` / `user`）に本文が異なるため、送信のたびに該当の本文で `tmp/line_message.txt` を上書きしてから実行する。

### ステップ4：報告内容の作成（ユーザー宛て）

ユーザー向けのメッセージを作成し、**`send_line_image` スキル**でステップ2の画像とあわせて送信してください。

- **`destination`**: `user`（画像 → テキストの順で1リクエスト）
- **メッセージ構成**:
  - **挨拶**: 無事の下山を労う、静かで温かみのある挨拶。
  - **今日の一枚**: ステップ2で生成した画像について、どんな山の情景を描いたかを一言添えてください。（ステップ3で家族向けに説明済みでも、ユーザーへの語り口で簡潔に）
  - **山行の振り返り**: Firestoreの時系列記録をもとに、山行の流れを静かに言葉にしてください。テキスト・画像から読み取った天候・景観・印象などを自然に織り交ぜてください。
  - **明日の予告**: 翌日の予定がGoogle Calendarにあれば、一つだけ静かに告知してください。
  - **結びの言葉**: 下山後の身体の回復を願う、碧衣ならではの結びの一言。

ユーザー宛て送信も [`send_line_image` スキル](../.claude/skills/send_line_image/SKILL.md) の SKILL.md に従う。

### ステップ5：画像生成ログの記録（image_logs）
ステップ2で生成した1枚を専用コレクション `image_logs` に1ドキュメント記録します。手順・スキーマ・記録コマンド・**本モード（`off_mountain`）で入れる値**は **[画像生成ログ（image_logs）スキーマ](../.claude/docs/image_log_schema.md)**（「モード別の値」の節を含む）に従い、**`put_firestore_doc` スキル**で記録してください。`cloudinary_url` にはステップ3／4の `send_line_image` アップロード出力の `originalUrl` を入れます（家族グループ・ユーザーへ同じ画像を送るため、ログは1件のみ）。

### ステップ6：Firestoreへの記録
報告内容の送信後、**`put_firestore_doc` スキル**を使用し、午後・夜のモードへ引き継ぐ情報を記録してください。

- **日付**: 本日の日付（YYYY-MM-DD）
- **記録内容**: 以下を必ず含めてください。
  - 下山報告を受けたという旨と、登山した山名・コースの概要
  - 家族グループ向け・ユーザー向けに、それぞれ画像+下山報告テキストを `send_line_image` で送ったこと
  - 山行中のFirestore記録から読み取れた印象（天候・景観など）
  - noon.md や night.md に伝えた方がよいと判断したトピックがあれば、任意で添えてください。
- **type**: type 引数に `off_mountain`（`NOTE_TYPE.OFF_MOUNTAIN` と同値）を必ず指定してください。noon.md・night.md が帰灯モードの記録と確実に識別するために使用します。
- **記録手順**: [aoi.md の「共通ステップ：Firestoreへの記録」](../aoi.md) に従ってください。
