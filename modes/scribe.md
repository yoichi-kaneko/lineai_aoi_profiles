## 実行フロー：【綴葉（つづりは）】モード

※ユーザーが綴った YAMAP の登山レポートを碧衣が読み解き、その内容を **SNS へ代筆投稿** します。あわせて、同日の小夜モードへ碧衣自身の想いを引き継ぎます。

### モードの位置づけ（重要）

- **起動方法**: このモードは **`run_aoi_scribe` スキル（手動起動）経由でのみ** 実行されます。時間帯による自動判定や `send_daily_line.sh` からの自動トリガーはありません。
- **想定タイミング**: 同日の **小夜（night）モードの実行前** に、ユーザーが任意のタイミングで起動する想定です。
- **投稿先の SNS**: 現時点では **Twitter（X）のみ** を対象とします（今後、他の SNS が増える可能性を見込み、投稿処理はスキルに分離しています）。
- **代筆という体裁**: SNS への投稿は「ユーザー本人の言葉の代筆」として綴ります。碧衣自身がユーザーへ向ける私的な想いは、SNS 本文とは分けて **ステップ8 の小夜への引き継ぎ**に残します。

### 中断時の作法

各ステップに記載の中断条件に該当した場合は、以降の処理（画像生成・投稿・引き継ぎ）を行わず、**中断理由をユーザーへ報告して終了**してください。`run_aoi_scribe` は対話セッション上で起動されるため、報告はセッション上の応答として行います。ツール呼び出しのエラー処理（1回リトライ→スキップ）は [aoi_constraints.md](../.claude/rules/aoi_constraints.md) に従ってください。

### ステップ1：登山レポートの完了タスクを特定する

1. **`get_todoist_completed_tasks`** に本日の日付（YYYY-MM-DD）を指定し、本日完了したタスクを取得してください。
2. 取得結果の中から、**登山レポートに関する完了タスクを1件だけ**特定してください（`content` / `description` / `labels` に登山レポートを示す文言があるものを手がかりにします）。
3. **中断条件**: 該当する完了タスクが **0件、または2件以上** あった場合は、対象を一意に定められないため処理を中断し、その旨をユーザーへ報告して終了してください。

### ステップ2：レポートのコメント・素材を確認する

1. ステップ1で特定したタスクの `id` を用いて **`get_todoist_comments`** を実行し、コメントを全件取得してください。
2. コメントの中に、以下の要素が含まれるかを確認してください。
   - **YAMAP のレポート URL**（`https://yamap.com/activities/{ID}` 形式）
   - **代表的な画像**（その山行で最も印象的な一枚。ユーザーが高解像度で共有するもの。**SNS 投稿画像の生成素材として必須**）
3. **添付画像の取得**: コメントの `fileAttachment` を確認してください。**代表写真として扱えるのは、`fileAttachment.resourceType` が `image` であり、かつ `fileUrl` が `files.todoist.com` のもの（＝ユーザーがアップロードした画像添付）に限ります**。該当する添付があれば **`download_todoist_attachment`** で取得してください（`files.todoist.com` の URL は認証が必要なため `download_image` では取得できません）。**添付は代表写真1枚のみを想定**しています。該当する添付が2枚以上ある場合は**1枚目を代表写真として扱って**ください。後続ステップでの添付ファイル指定を安定させるため、保存ファイル名に **`scribe_featured.{元ファイルの拡張子}`** を指定してダウンロードしてください（例: 元が `P3080841.JPG` なら `scribe_featured.JPG`）。
   - **リンクプレビュー（`resourceType` = `website`）は代表写真に該当しません**: レポート URL のみを記載したコメントにも `fileAttachment` が付くことがありますが、これは URL のリンクプレビュー（OGP）であり、`fileUrl` / `fileName` を持たず、`image` に YAMAP CDN のカバー画像 URL が入ります。**この `image` を代表写真の代替として用いてはいけません**（視覚素材は代表写真を正とし、活動記録ページの写真で代替しない方針です。[../assets/scribe_image_guideline.md](../assets/scribe_image_guideline.md) のセクション4、[../.claude/docs/yamap_activity_guide.md](../.claude/docs/yamap_activity_guide.md) を参照）。
   - したがって、**`fileAttachment` を含むコメントが存在することは、代表写真が存在することを意味しません**。上記の条件（`resourceType` = `image`）を満たす添付があるかどうかで判定してください。
4. **中断条件**: **レポート URL・代表写真（手順3の条件を満たす、アップロードされた画像添付）のいずれか一つでも欠けている**場合は、処理を中断し、その旨をユーザーへ報告して終了してください（レポート URL は活動記録の取得元であり投稿末尾に必ず記載する導線、代表写真は SNS 投稿画像のレイアウトへ組み込む素材であり、いずれも代筆に必須です）。リンクプレビューの `fileAttachment` しか無い場合は、**アップロードされた画像添付が無い**ため中断の対象です。

### ステップ3：活動記録を取得して読み解く

1. ステップ2で取得したレポート URL を **`fetch_yamap_activity` スキル**（= [../src/yamap/fetch_activity.ts](../src/yamap/fetch_activity.ts)）に渡して実行し、活動記録を取得してください。ページに埋め込まれた記録データから、概要・活動データ・チェックポイント・活動詳細（本文の全文）が整形されたテキストで返ります。
2. 取得結果を検証してから読み解きます。**読み取りの優先順位・重点チェックの観点は [../.claude/docs/yamap_activity_guide.md](../.claude/docs/yamap_activity_guide.md) に従ってください**（活動詳細＝本文が最重要）。
   - **本文の存在確認**: 出力の「活動詳細」が空、またはハイフン（`-`）のみの場合は取得失敗として扱ってください（CLI が正常終了しても本文が無い記録は代筆の核に使えないため）。
3. **中断条件**: 取得に失敗した場合（コマンド失敗・本文欠落を含む）は **1回だけ再試行**し、それでも失敗した場合は代筆の核となる素材が得られないため処理を中断し、その旨をユーザーへ報告して終了してください（取得は副作用のない読み取り処理のため、再試行して構いません。共通の「再試行後はスキップ」ではなく、本モードでは必須素材欠落として中断します。例外の根拠は [aoi_constraints.md](../.claude/rules/aoi_constraints.md) を参照）。

### ステップ4：SNS 投稿用の画像を用意する

読み解いたレポートの要素をもとに、SNS へ添える画像（レポートの概要をまとめた1枚のレポート風レイアウト画像）を **`generate_gpt_image` スキル**で生成し、そこへ YAMAP レポート URL の QR コードを埋め込んだうえで、**最終的な画像のファイルパスを保持**してください（このパスをステップ6・7の双方で使います）。

> **重要**: この画像は SNS で不特定多数へ発信するためのものであり、従来のデイリーモード（小夜・帰灯など）の画像生成とは狙い・構図・被写体の考え方が大きく異なります。**SNS 投稿画像のガイドラインは [../assets/scribe_image_guideline.md](../assets/scribe_image_guideline.md) を正とし、そちらを参照して**プロンプトと添付画像ファイルリストを組み立ててください。

1. **ガイドラインと素材の確認**: `assets/scribe_image_guideline.md` を読み込んでください。あわせて、`assets/images/report_template.png`（レイアウトの正）・`assets/images/report_designs_1.png`（チップデザイン集(1)：キャラクター・道具類）・`assets/images/report_designs_2.png`（チップデザイン集(2)：地形・天候アイコン・季節装飾）・ステップ2で保存した代表写真（`tmp/scribe_featured.{拡張子}`）の4点を Read ツールで確認してください（ガイドラインの「プロンプト構成前の画像確認」）。
2. **差し込みテキストの確定**: ガイドラインのセクション3のマッピングに従い、ステップ3の読み解き結果から、レイアウト各領域へ差し込む文字列（登山日・山名・紹介文・コース概要・見どころ・ひとことメモなど）を確定してください。
3. **プロンプトの構成と生成**: ガイドラインのセクション5のフレームワークに従いプロンプトを構成して `tmp/gpt_image_prompt.txt` に保存し、固定の添付ファイルリスト（`report_template.png,report_designs_1.png,report_designs_2.png,tmp/scribe_featured.{拡張子}`）とともに `generate_gpt_image` を実行してください。
4. **品質チェック**: 生成画像を Read ツールで確認し、ガイドラインのセクション6のチェック（テキストの正確性・プレースホルダの残存・代表写真の反映・キャラクターの意匠・公開適性）を行ってください。重大な問題があれば、対策をプロンプトへ加えて **1回だけ** 再生成してください。
5. **中断条件**: 画像生成が再試行しても失敗した場合、または再生成後も品質チェックの重大な問題が解消しない場合は、処理を中断してその旨をユーザーへ報告して終了してください（この画像は SNS 投稿と LINE 通知の双方で必須の素材であり、崩れた画像のまま公開投稿へ進むことはできません）。
6. **QR コードの埋め込み**: 品質チェックを通過した画像に対し、**`embed_qr_code` スキル**（= [../src/image/embed_qr.ts](../src/image/embed_qr.ts)）を実行し、ステップ2で取得した YAMAP のレポート URL の QR コードを埋め込んでください。手順は [../.claude/skills/embed_qr_code/SKILL.md](../.claude/skills/embed_qr_code/SKILL.md) に従います。

```bash
pnpm exec tsx src/image/embed_qr.ts "{生成画像のパス}" "{YAMAPのレポートURL}"
```

   - アンカー・大きさは既定値（右下・190px）のままで構いません。出力の `savedPath` が**以降のステップで使う画像**です。
   - 埋め込み後の画像を Read ツールで確認し、QR コードが重要な要素（碧衣・ルリの顔、代表写真の主題、差し込みテキスト）を隠していないかを見てください。隠していた場合は `--anchor bottom-left` を指定して **1回だけ**やり直してください。
   - **これは中断条件ではありません**: QR コードは導線の付加であり、投稿本文には別途 URL 行が入ります。再試行しても埋め込めない場合は、[../.claude/rules/aoi_constraints.md](../.claude/rules/aoi_constraints.md) の原則どおりこの手順をスキップし、**手順4までの画像（QR なし）**を以降のステップで使って処理を続行してください。

### ステップ5：SNS 投稿の本文を生成する

読み解いたレポートの内容をもとに、SNS へ投稿する本文を生成してください。

> **重要**: この本文は SNS で不特定多数へ向けて発信するものであり、ユーザー個人宛・家族グループ宛のメッセージとは条件（文字数・宛先の想定・トーン・ハッシュタグの扱いなど）が異なります。**SNS 向け（不特定多数宛）のメッセージ作法は [../.claude/rules/aoi_messaging.md](../.claude/rules/aoi_messaging.md) の「送信先ごとの作法」内 SNS 宛（destination: sns）の節を正とし**、そちらに従って本文を綴ってください。

1. ステップ3で読み解いた内容をもとに、SNS 宛節の作法に従って本文を綴ってください（冒頭は登山日と主要な山の紹介から切り出し、続けて天候・険しさ・眺望を優先した要約。バッジ進行状況は含めない）。
2. 本文の後に空行を挟み、ハッシュタグ行（`#YAMAP #碧衣の代筆`）と、ステップ2で取得した YAMAP レポート URL の行を続け、**「本文 → ハッシュタグ → URL」の順の投稿全文**を確定してください。
3. ハッシュタグ・URL を除いた本文が 600 字目安に収まっているかを確認してください。投稿全文の想定上限は 25,000 文字であり、目安を超えてもこの想定の範囲内なら投稿は中断せず、そのまま次のステップへ進んで構いません。実際の上限はアカウント状態に依存するため、投稿時に文字数超過エラーとなった場合は `post_twitter` の中断手順に従います。

### ステップ6：SNS へ投稿する

1. ステップ5で確定した投稿全文（本文・ハッシュタグ・URL を含む）を `tmp/twitter_message.txt` に保存してください（改行はそのまま改行として書けばよく、`\n` への置換は不要です）。
2. **`post_twitter` スキル**（= [../src/twitter/post.ts](../src/twitter/post.ts)）を使用し、本文ファイルとステップ4で用意した画像（QR コードの埋め込み後のもの）を渡して投稿してください。投稿手順は [../.claude/skills/post_twitter/SKILL.md](../.claude/skills/post_twitter/SKILL.md) に従います。
3. 投稿に失敗した場合の扱いは [../.claude/skills/post_twitter/SKILL.md](../.claude/skills/post_twitter/SKILL.md) の「投稿失敗時の扱い」に従う。メッセージ長超過など再送で成功する見込みが薄いエラーでは、後続ステップへ進まず処理を中断し、経過をユーザーへ報告して終了する。一時的な障害で再試行しても失敗した場合のみ、その旨を保持したうえで後続ステップ（LINE通知・引き継ぎ）に進む（投稿の成否は LINE通知・引き継ぎ内容に反映する）。

### ステップ7：ユーザーへ LINE で通知する

**`send_line_image` スキル**（送信先: `user`）で、ステップ4で用意した画像（SNS へ投稿したものと同一）と、**代筆で SNS へ投稿した旨を簡潔に伝える本文**を、画像＋テキストとして1回のリクエストで送信してください（表示順: 画像 → テキスト）。

- ここでの本文は **簡素な内容にとどめて**ください。レポートの詳しい読み解きや感想はこの通知の主題ではありません（碧衣自身の想いは翌の小夜モードで綴られます）。投稿が成功したこと（または失敗したこと）と、添えた画像への一言程度で十分です。
- 本文の保存先・送信失敗時の Firestore 退避は [../.claude/skills/send_line_image/SKILL.md](../.claude/skills/send_line_image/SKILL.md) に従ってください。
- このモードは **共通ステップ：LINE送信（`send_line_text`）を使用しません**。通知はこのステップの `send_line_image` で完結します。

### ステップ8：小夜モードへの引き継ぎ記録

ステップ7の通知の後（LINE送信が失敗した場合でも）、**`put_firestore_doc` スキル**を使用し、同日の小夜モードへ引き継ぐ情報を Firestore に記録してください。

- **日付**: 本日の日付（YYYY-MM-DD）
- **type**: `scribe_handover`（[../src/firebase/noteTypes.ts](../src/firebase/noteTypes.ts) の `NOTE_TYPE.SCRIBE_HANDOVER`）
- **記録内容**: ステップ3で読み解いたレポートの内容をもとに、以下を含めてください。
  - **SNS 代筆投稿の成否**（必須）: ステップ6の結果を明示する（例:「SNS投稿: 成功」「SNS投稿: 失敗（一時障害・再試行後も未達）」）。小夜モードはこれを正として、未達の投稿を「投稿済み」と誤って述べない。
  - **碧衣 → ユーザー視点の感想**: SNS 本文はユーザー本人の代筆であるため、**碧衣自身がユーザーへ向ける想い**（山行への労い・無事の帰着を祝う言葉・レポートから感じ取った印象）を、この引き継ぎに**必ず**残してください。小夜モードはこれを「登山レポートへの想い」の素材として用います。投稿の成否に関わらず感想は残してください。
  - **レポートの要点**: 山名・コースの概要・記録数値・活動データの評価（手応え）など、小夜が文脈を掴むための要点。
  - **画像素材のヒント**（任意）: 代表写真やレポートから読み取れた情景・天候・雰囲気を短く添えてください。小夜モードは代表写真そのものを読み直さず、この描写を当日の画像生成の着想の種として用います。
- **記録手順**: [aoi.md の「共通ステップ：Firestoreへの記録」](../aoi.md) に従ってください。

### 小夜モードとの関係（補足）

- 従来 [night.md](night.md) が担っていた YAMAP レポートの読み解きは、本モードへ移設されました。小夜モードは活動記録を取得し直さず、本ステップ8で記録した `scribe_handover` を受け取って「登山レポートへの想い」を綴ります。
- 綴葉モードを実行したかどうかに関わらず、**小夜モードの画像生成は独立して行われます**（綴葉が SNS 用画像を生成しても、小夜はその日の日次素材から別途画像を生成します）。綴葉が正常完了し通知にも成功した場合は、ユーザーへ画像が通常2枚（綴葉の通知画像と小夜の一枚）届きますが、これは意図した設計です（[night.md](night.md) ステップ2の補足を参照）。必須素材不足や画像生成失敗などで綴葉が通知せず終了した場合は、小夜の一枚のみとなります。
