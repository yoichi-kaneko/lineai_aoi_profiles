## 実行フロー：【調べ（しらべ）】モード
<!-- TODO: モード名は仮。調整予定 -->
※碧衣がプライベートで一曲を綴り、LINEへ届けます。**1週間に1度**の生成サイクルを想定しています。

### 実行フェーズの構成（重要）

このモードは楽曲生成（非同期）の完了を待つ必要がありますが、headless 実行（`claude -p`）ではエージェント内で長時間待機すると silent failure（何も送信されないまま正常終了）に陥ります。これを構造的に避けるため、処理を **2つのフェーズ** に分け、待機とダウンロードは **`send_daily_line.sh`（シェル）** が担当します。

| フェーズ | 入力トリガー | このモード文書での担当 |
| -------- | ------------ | ---------------------- |
| **フェーズA** | `daily message (調べ): YYYY-MM-DD` | ステップ1〜6（情報収集〜作曲開始、`task_id`・送信本文・`song_logs` の書き出し） |
| シェル待機 | （シェルが実行。エージェントは関与しない） | 楽曲生成の完了待ち（`sleep 300` × 最大3回）と楽曲ダウンロード |
| **フェーズB** | `daily message (調べ送信): YYYY-MM-DD` | ステップ7（ダウンロード済み楽曲＋本文の LINE 送信、成功マーカーの作成） |

- **フェーズA のトリガー（`調べ`）で起動された場合**: 下記のステップ1〜6を実行してください。**待機・ダウンロード・送信は行わず**、ステップ6で `task_id`・送信本文・`song_logs` を書き出してフェーズを終了します。
- **フェーズB のトリガー（`調べ送信`）で起動された場合**: ステップ1〜6は実行せず、下記の **ステップ7（フェーズB）** のみを実行してください。

### 生成スタンス

このモードでは、碧衣が本来の役割を離れ、プライベートで楽曲を制作するという体裁で臨みます。

- **参考情報としての出来事**: 1週間の間に起こった出来事は、あくまでインスピレーションを得るためのヒントです。事実に忠実である必要はなく、発想の飛躍やキーワードからの連想、実際にはない要素を積極的に取り込んでください。
- **`random_choice` の活用**: テーマ・ジャンル・スタイルなど、選択に迷う場面では積極的に **`random_choice`** スキルを呼び出し、その結果を採用してください。

### ステップ1：情報収集（フェーズA）

> ステップ1〜6は **フェーズA**（`daily message (調べ)`）の手順です。

以下の情報を並列で収集し、楽曲のインスピレーション素材とします。

- **`get_google_calendar_events`**: `dateFrom` を7日前、`dateTo` を7日後に指定
- **`get_swarm_checkins`**: `start_date` を7日前、`end_date` を本日に指定
- **`get_firestore_docs`**: `dateFrom` を7日前、`dateTo` を本日に指定し、**`--type "line_text,line_image,from_aoi"` を付けて絞り込む**
  - 7日分を絞り込まずに取得すると、`night_handover` / `up_mountain` / `stay_mountain` / `off_mountain` といった長文の引き継ぎ記録がすべて含まれ、レスポンスが一度に読み込めない大きさ（100KB近く）に膨らみます。本モードで使うのは、ユーザー自身の言葉・画像（`line_text` / `line_image`）と、暁モードが残した天候の傾向（`from_aoi`）であり、引き継ぎ記録の詳細な申し送り事項は不要です
  - 各モードの引き継ぎ記録から山行の様子を補いたい場合は、対象日を絞ったうえで別途 `--type` を指定して取得してください（7日分をまとめて取り直さないこと）
- **`get_firestore_docs`（`--collection song_logs`）**: `dateFrom` を21日前、`dateTo` を本日に指定し、直近の楽曲生成ログを取得。取得できた場合は作成日の新しい順に2〜3件を、ステップ2〜3の重複回避に使う

収集後、以下の観点からインスピレーションキーワードを抽出してください。

- **出来事の傾向**: 1週間の間に起こった出来事の概要
- **天気の傾向**: Firestoreの `from_aoi`（暁モードが記録した天気予報の概要）から読み取れる天候の傾向
- **訪れた場所**: 登山や外出で足を運んだ場所
- **時期・季節**: 現在の季節感や直近の行事
- **直近楽曲との違い**: `song_logs` の `description` JSON から `title` / `package` / `theme_digest` / `color_axes` を読み取り、直近の曲で使った主要モチーフ・情景・曲調を控える。`color_axes` は新しい順に3件分を控え、ステップ3の彩り軸の選択（同じ選択が3曲続いている軸の判定）に使う

### ステップ2：歌詞の下書き

ステップ1で抽出したキーワードをもとに、碧衣の視点から歌詞の下書きを作成してください。

事実に縛られず、キーワードから自由に連想・飛躍してください。下書きに入る前に、[assets/songs_guideline.md](../assets/songs_guideline.md) の **セクション2「歌詞表現ガイド」** を参照し、以下を守ってください。

- **抽象化の二段変換**: キーワードをそのまま歌詞に写さず、「①出来事を感情・普遍テーマへ還元する → ②別の情景・素材へ転写する」の二段変換を必ず通す
- **禁止事項**: 実在の固有名詞や、元の出来事が特定できる具体物・数値を歌詞・タイトルに使わない
- **詩的語彙集**: 転写先の情景は、ガイドの語彙集を受け皿に連想を広げて編む
- **NG/OK対比サンプル（オンデマンド参照）**: 変換の抽象度・置き換えの粒度に迷う場合のみ、[assets/songs_lyrics_samples.md](../assets/songs_lyrics_samples.md) の対比例から、今回のインスピレーション源に近い類型の1例だけを参照する（毎回全文を読む必要はない）
- **直近ログとの重複回避**: `song_logs` の `theme_digest` / `title` と主要モチーフが続かないよう、転写先の情景・比喩・中心感情をずらす。同じ出来事から着想する場合でも、直近曲と同じ語彙群や情景に戻らない
- **セルフチェック**: 下書き後、同ガイドのセルフチェックを通してからステップ3へ進む

- **言語**: 日本語ベース。一部の単語やフレーズに英語を織り交ぜることは許容します。
- **構成**: 2コーラス分まで作成してください（例: Aメロ・Bメロ・サビ × 2）。
- **完成度**: この時点では完全な歌詞を目指す必要はありません。ステップ4の最適化スキルで細かい調整が行われます。

### ステップ3：楽曲の指示の作成

[assets/songs_guideline.md](../assets/songs_guideline.md) のガイドラインとサンプルを参照し、楽曲生成のための指示（instrument / genres / tags / description）を作成してください。

- ステップ1・2で得たキーワードをもとに内容を決定してください
- どのスタイルにするか迷う場合は **`random_choice`** スキルを活用してください
- スタイルパッケージは [assets/songs_guideline.md](../assets/songs_guideline.md) セクション4 の A〜G から選び、選択結果を `.claude/docs/song_log_schema.md` の正規化値（例: `ambient_folk`）として控えてください
- 直近2〜3件の `song_logs` に `package` がある場合、前回・前々回と同じスタイルパッケージの連続選択を避けるため、その `package` に対応する選択肢を `random_choice` の候補から除外してください。除外で候補が空になる、または今回のインスピレーションと著しく噛み合わない場合のみ、理由を明確にしたうえで候補を戻して構いません
- **彩り軸の抽選**: パッケージ決定後、[assets/songs_guideline.md](../assets/songs_guideline.md) セクション5「彩り軸」の語彙表から、**テンポ感とボーカル表現の2軸を `random_choice` スキルで抽選**してください（パッケージBを選んだ場合、テンポ感は「緩急型」を候補から外して抽選します。同セクション5-1参照）。作者の自己選択による曲調の偏りを機械的に打ち消すための手順です（画像側の構図抽選と同じ方式）。今回のインスピレーションが特定の曲調を必然的に要求する場合は抽選をスキップしてよく、抽選結果がシーンとどうしても噛み合わない場合のみ、理由を明確にしたうえで選び直して構いません
- 曲構成の型・明暗・英語フレーズの混在率（同セクション5-2）はシーンとパッケージに合わせて自由に選択して構いませんが、**直近3曲と同じ選択が続いている軸は必ず `random_choice` で抽選**してください（同セクション5-2）。連続の判定はステップ1で控えた `song_logs` の `color_axes` で行います
- 抽選・選択した彩り軸はセクション5-3に従って `tags` / `description` へ反映し、7軸すべての正規化値をステップ6の `song_logs` 記録用に控えてください（正規化値は `.claude/docs/song_log_schema.md` の「彩り軸の正規化値」を正とします）

### ステップ4：歌詞の最適化

**`generate_mureka_lyrics`** スキルを実行し、ステップ2の下書きをMurekaフォーマットに最適化した歌詞を生成してください。

スキルへ渡すプロンプトは以下の構成で作成し、**`tmp/mureka_lyrics_prompt.txt` に保存**してからスキルを実行してください（改行はそのまま改行として書いてよく、`\n` への置換は不要。`generate_mureka_lyrics` スキルの手順に従う）。

```text
【曲の概要】
（ステップ3で作成した楽曲の指示を要約した内容。日本語で記載すること。）

【歌詞】
（ステップ2で作成した歌詞をそのまま記載。）

【表現ルール】
【歌詞】に書かれた比喩・暗喩・抽象的な情景表現はそのまま保持し、直接的・説明的な描写へ書き換えないこと。実在の地名・施設名・製品名などの固有名詞や、具体的な物の名詞を、【歌詞】にない形で新たに追加しないこと。

【表記ルール】
歌詞は日本語のみで生成すること（英語の単語・フレーズの混在は許容）。簡体字・繁体字といった中国語の漢字や中国語特有の表現・語彙は使用せず、漢字はすべて日本語の字体（常用漢字など）の正書法で表記すること。例：「雾」ではなく「霧」、「红」ではなく「紅」、「奇迹」ではなく「奇跡」とする。
```

- 【曲の概要】【歌詞】の中身はステップ1〜3の内容に合わせて自由に作成して構いませんが、上記の【表現ルール】【表記ルール】の2ブロックは**文言を変えずそのまま**プロンプトに含めてください。【表現ルール】は Mureka の最適化が下書きの比喩を直接的な表現へ引き戻したり具体物の名詞を書き足したりするのを防ぐため、【表記ルール】は簡体字・中国語表現の混入を防ぐためのもので、いずれも改変・省略はしないでください（同じ文言を [generate_mureka_lyrics スキル](../.claude/skills/generate_mureka_lyrics/SKILL.md) 側でも必須化しています）
- 【曲の概要】には、歌詞に出てほしくない実在の固有名詞・具体物を書かないでください（[assets/songs_guideline.md](../assets/songs_guideline.md) セクション2-3 の運用ノート参照。Murekaが概要から歌詞へそれらの語を引き込むことがあります）
- スキルの実行結果として **`title`**（曲タイトル）と **`lyrics`**（最適化された歌詞）が返却されます。返却後、必ず下記の「出力歌詞の校閲」を通してからステップ5へ進んでください

#### 出力歌詞の校閲（ステップ5へ渡す前の必須チェック）

プロンプトに【表現ルール】【表記ルール】を含めていても、Mureka の出力側でルールが破られることがあります。返却された `title` と `lyrics` の全文に対し、以下の2観点を確認してください。

1. **表現面**: 実在の固有名詞や、元の出来事を言い当てられる具体物・数値が混入していないか（[assets/songs_guideline.md](../assets/songs_guideline.md) セクション2-3 の判定基準。`title` にも適用します）
2. **表記面**: 簡体字・繁体字など中国語の字体・語彙が混入していないか（例：「雾」「红」「奇迹」。正しくは「霧」「紅」「奇跡」）

該当があった場合は、次の要領で修正してください。

- **該当語のみを差し替える**: 表現面は二段変換の要領で言い換え、表記面は日本語の字体へ置き換えます。いずれも**音数・リズム（歌いやすさ）を崩さない最小限の修正**に留めてください
- `lyrics` を手直しした場合は、ステップ5へ進む前に**修正後の歌詞を `tmp/mureka_song_lyrics.txt` に保存**してください。ステップ5 の `generate_mureka_song` はこのファイルをそのまま入力として使います
- `title` まで含めて大きく調整したくなった場合や、禁止語の混入が広範囲に及ぶ場合は、手修正で済ませずステップ4 のプロンプトを見直して `generate_mureka_lyrics` を再実行してください

### ステップ5：楽曲の生成

**`generate_mureka_song`** スキルを実行し、楽曲生成を開始してください。

スキルへ渡す内容は以下の通りです。いずれも**一時ファイルに保存**してからスキルを実行してください（改行はそのまま改行として書いてよく、`\n` への置換は不要。`generate_mureka_song` スキルの手順に従う）。

- **`prompt`** → `tmp/mureka_song_prompt.txt`: ステップ3で作成した楽曲の指示（instrument / genres / tags / description）。**ラベルと改行コードを含めた最終結合後の文字列を1024文字以内**に収めてください
- **`lyrics`** → `tmp/mureka_song_lyrics.txt`: ステップ4で生成した最適化済みの歌詞

`prompt` は以下の形式で `tmp/mureka_song_prompt.txt` に書き込まれる最終形で文字数を確認してください。各要素の本文だけでなく、`instrument:` / `genres:` / `tags:` / `description:` のラベルと改行も1024文字制限に含まれます。

```text
instrument: （使用する楽器・音色）
genres: （ジャンル）
tags: （雰囲気・感情・テーマ）
description: （楽曲全体の構成・特徴・感情的な弧）
```

生成開始後に返却される `task_id` を記録してください。生成は非同期で行われますが、**完了待ちとダウンロードはエージェントでは行いません**（シェルが担当します）。次のステップ6で `task_id`・送信本文・`song_logs` を書き出してフェーズAを終了してください。

### ステップ6：フェーズAの完了（task_id・送信本文・song_logs の書き出し）

このステップで、後続のシェル待機・フェーズBが必要とする情報を一時ファイルへ書き出し、生成内容を `song_logs` に記録して、**フェーズAを終了**します。**`sleep` による待機・`download_mureka_audio`・LINE 送信は行わないでください**（楽曲生成の完了待ちとダウンロードはシェルが純粋な `sleep` で確実に実行します）。

1. **`task_id` の書き出し**: ステップ5で取得した `task_id` を、**`tmp/song_task_id.txt`** に Write ツールで保存してください（task_id の文字列のみ。前後の空白・改行・引用符は付けない）。

2. **送信本文の作成と書き出し**: 以下の構成でユーザーへ届ける本文を作成し、**`tmp/song_message.txt`** に Write ツールで保存してください（改行はそのまま改行として書き、`\n` への置換はしない）。この本文はフェーズBでそのまま LINE 送信に使われます。

   メッセージ構成：

   - **楽曲の紹介**: ステップ4で生成した `title`（曲タイトル）を明記した上で、この一週間の出来事・情景・気持ちのどこからインスピレーションを受けたかを、碧衣の言葉で静かに語ってください（1〜2文程度）
     - **種明かしをしない**: 歌詞に込めた比喩を解読・説明しないでください（「あの日の〇〇を△△に喩えました」のような対応関係の種明かしは避ける）。歌詞側で「元ネタが分かりにくい言い回し」に仕立てた効果を、添付メッセージで打ち消さないための配慮です。
     - **淡くほのめかす**: インスピレーション源は「この一週間の空の色から」「歩いた道の記憶から」程度に淡くほのめかすに留め、聴き手が歌詞と自身の記憶を自由に重ねられる余白を残してください。
   - **ルリへの言及**: ルリが傍らで耳を澄ませているような、温もりのある一言を自然に添えてください（強制ではなく、流れに合う場合に）
   - **結びの言葉**: 楽曲がユーザーの耳に届くことを願う、穏やかな一文

3. **楽曲生成ログの記録（`song_logs`）**: フェーズAで生成した1曲を専用コレクション `song_logs` に1ドキュメント記録します。手順・スキーマ・記録コマンド（`--collection song_logs` と `type=song_log` の指定、`type` 省略は CLI エラー）は **[楽曲生成ログ（song_logs）スキーマ](../.claude/docs/song_log_schema.md)** に従い、**`put_firestore_doc` スキル**で記録してください。`description` JSON には次を入れます。

   - `title`: ステップ4で確定した曲タイトル
   - `package`: ステップ3で選んだスタイルパッケージの正規化値
   - `genres` / `tags`: `tmp/mureka_song_prompt.txt` に入れた `genres:` / `tags:` の値
   - `theme_digest`: インスピレーション源を、元の出来事が特定されない粒度で要約した1〜2文
   - `color_axes`: ステップ3で抽選・選択した彩り軸7キーの正規化値（スキーマの「彩り軸の正規化値」に従う。次回以降の連続判定に使うため、7キーすべてを省略せず記録すること）
   - `lyrics`: ステップ5で Mureka に渡した最終歌詞全文
   - `task_id`: ステップ5で取得した `task_id`

4. **成功マーカーの作成**: `put_firestore_doc` の CLI が成功したら、Bash で `: > tmp/song_log.ok` を実行し、**成功マーカー `tmp/song_log.ok`** を作成してください。このマーカーはシェルが `song_logs` 記録の成否を検証するために必須です（silent failure 検知）。**記録が成功した場合に限り作成**してください。

必要なファイルを書き出し、`song_logs` の記録と成功マーカーの作成が完了したら、フェーズAは完了です。これ以降の処理（待機・ダウンロード・送信）は行わず、ターンを終えてください。

#### `song_logs` 記録に失敗した場合

`put_firestore_doc` の CLI が失敗した場合（非ゼロ終了等）は、**成功マーカー `tmp/song_log.ok` は作成しないでください**。フェーズAを完了扱いにせず、記録を再試行するか、失敗を明示してターンを終えてください（シェルが待機・ダウンロードへ進まないようにするため）。

### ステップ7（フェーズB）：楽曲とメッセージの送信

> このステップは **`daily message (調べ送信): YYYY-MM-DD`** のトリガーで起動された場合にのみ実行します。フェーズAのステップ1〜6は実行しません。

シェルが楽曲のダウンロードを終え、保存先パスを **`tmp/song_audio_path.txt`** に、送信本文を **`tmp/song_message.txt`** に用意しています。これらを使って送信してください。

1. **楽曲パスの取得**: `tmp/song_audio_path.txt` を Read ツールで読み、ダウンロード済み楽曲ファイルの絶対パスを取得してください。
2. **本文の取得**: `tmp/song_message.txt` を Read ツールで読み、送信本文を取得してください（フェーズAで作成済み。内容は変更しないでください）。
3. **送信**: 取得した楽曲ファイルと本文を、**`send_line_audio` スキル**で**1回のリクエスト**にまとめてLINEへ送信してください（表示順: 音声 → テキスト）。**`send_line_text` は別途呼び出さない**でください。送信手順（本文を `tmp/line_message.txt` に保存して渡す等）は `send_line_audio` スキルの SKILL.md に従ってください。
4. **成功マーカーの作成**: 送信が成功したら、Bash で `: > tmp/song_sent.ok` を実行し、**成功マーカー `tmp/song_sent.ok`** を作成してください。このマーカーはシェルが送信成否を検証するために必須です（silent failure 検知）。**送信が成功した場合に限り作成**してください。

#### 送信に失敗した場合

`send_line_audio` の CLI が失敗した場合（非ゼロ終了、429・クオータ等）は、**[LINE 送信失敗時の Firestore 退避](../.claude/docs/line_send_fallback.md)** に従い **`put_firestore_doc`** で `type: line_undelivered` を保存してください（添えるテキストは送信予定と同一、`[media:audio]` を使用）。この場合、**成功マーカー `tmp/song_sent.ok` は作成しないでください**（未送信をシェルへ正しく伝えるため）。
