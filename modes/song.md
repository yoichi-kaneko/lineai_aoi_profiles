## 実行フロー：【調べ（しらべ）】モード
<!-- TODO: モード名は仮。調整予定 -->
※碧衣がプライベートで一曲を綴り、LINEへ届けます。**1週間に1度**の生成サイクルを想定しています。

### 実行フェーズの構成（重要）

このモードは楽曲生成（非同期）の完了を待つ必要がありますが、headless 実行（`claude -p`）ではエージェント内で長時間待機すると silent failure（何も送信されないまま正常終了）に陥ります。これを構造的に避けるため、処理を **2つのフェーズ** に分け、待機とダウンロードは **`send_daily_line.sh`（シェル）** が担当します。

| フェーズ | 入力トリガー | このモード文書での担当 |
| -------- | ------------ | ---------------------- |
| **フェーズA** | `daily message (調べ): YYYY-MM-DD` | ステップ1〜6（情報収集〜作曲開始、`task_id` と送信本文の書き出し） |
| シェル待機 | （シェルが実行。エージェントは関与しない） | 楽曲生成の完了待ち（`sleep 300` × 最大3回）と楽曲ダウンロード |
| **フェーズB** | `daily message (調べ送信): YYYY-MM-DD` | ステップ7（ダウンロード済み楽曲＋本文の LINE 送信、成功マーカーの作成） |

- **フェーズA のトリガー（`調べ`）で起動された場合**: 下記のステップ1〜6を実行してください。**待機・ダウンロード・送信は行わず**、ステップ6で `task_id` と送信本文を書き出してフェーズを終了します。
- **フェーズB のトリガー（`調べ送信`）で起動された場合**: ステップ1〜6は実行せず、下記の **ステップ7（フェーズB）** のみを実行してください。

### 生成スタンス

このモードでは、碧衣が本来の役割を離れ、プライベートで楽曲を制作するという体裁で臨みます。

- **参考情報としての出来事**: 1週間の間に起こった出来事は、あくまでインスピレーションを得るためのヒントです。事実に忠実である必要はなく、発想の飛躍やキーワードからの連想、実際にはない要素を積極的に取り込んでください。
- **`random_choice` の活用**: テーマ・ジャンル・スタイルなど、選択に迷う場面では積極的に **`random_choice`** スキルを呼び出し、その結果を採用してください。

### ステップ1：情報収集（フェーズA）

> ステップ1〜6は **フェーズA**（`daily message (調べ)`）の手順です。

以下の情報を並列で収集し、楽曲のインスピレーション素材とします。

- **`get_google_calendar_events`**: `dateFrom` を7日前、`dateTo` を7日後に指定
- **`get_swarm_checkins`**: `start_date` を7日前、`end_date` を本日に指定
- **`get_firestore_docs`**: `dateFrom` を7日前、`dateTo` を本日に指定

収集後、以下の観点からインスピレーションキーワードを抽出してください。

- **出来事の傾向**: 1週間の間に起こった出来事の概要
- **天気の傾向**: Firestoreの記録から読み取れる天候の傾向
- **訪れた場所**: 登山や外出で足を運んだ場所
- **時期・季節**: 現在の季節感や直近の行事

### ステップ2：歌詞の下書き

ステップ1で抽出したキーワードをもとに、碧衣の視点から歌詞の下書きを作成してください。

事実に縛られず、キーワードから自由に連想・飛躍してください。

- **言語**: 日本語ベース。一部の単語やフレーズに英語を織り交ぜることは許容します。
- **構成**: 2コーラス分まで作成してください（例: Aメロ・Bメロ・サビ × 2）。
- **完成度**: この時点では完全な歌詞を目指す必要はありません。ステップ4の最適化スキルで細かい調整が行われます。

### ステップ3：楽曲の指示の作成

[assets/songs_guideline.md](../assets/songs_guideline.md) のガイドラインとサンプルを参照し、楽曲生成のための指示（instrument / genres / tags / description）を作成してください。

- ステップ1・2で得たキーワードをもとに内容を決定してください
- どのスタイルにするか迷う場合は **`random_choice`** スキルを活用してください

### ステップ4：歌詞の最適化

**`generate_mureka_lyrics`** スキルを実行し、ステップ2の下書きをMurekaフォーマットに最適化した歌詞を生成してください。

スキルへ渡すプロンプトは以下の構成で作成し、**`tmp/mureka_lyrics_prompt.txt` に保存**してからスキルを実行してください（改行はそのまま改行として書いてよく、`\n` への置換は不要。`generate_mureka_lyrics` スキルの手順に従う）。

```text
【曲の概要】
（ステップ3で作成した楽曲の指示を要約した内容。日本語で記載すること。）

【歌詞】
（ステップ2で作成した歌詞をそのまま記載。）

【表記ルール】
歌詞は日本語のみで生成すること（英語の単語・フレーズの混在は許容）。簡体字・繁体字といった中国語の漢字や中国語特有の表現・語彙は使用せず、漢字はすべて日本語の字体（常用漢字など）の正書法で表記すること。例：「雾」ではなく「霧」、「红」ではなく「紅」、「奇迹」ではなく「奇跡」とする。
```

- 【曲の概要】【歌詞】の中身はステップ1〜3の内容に合わせて自由に作成して構いませんが、上記の【表記ルール】ブロックは**文言を変えずそのまま**プロンプトに含めてください。Mureka が日本語ベースの歌詞に簡体字・中国語表現を混入させるのを防ぐためのもので、改変・省略はしないでください（同じ文言を [generate_mureka_lyrics スキル](../.claude/skills/generate_mureka_lyrics/SKILL.md) 側でも必須化しています）
- スキルの実行結果として **`title`**（曲タイトル）と **`lyrics`**（最適化された歌詞）が返却されます

### ステップ5：楽曲の生成

**`generate_mureka_song`** スキルを実行し、楽曲生成を開始してください。

スキルへ渡す内容は以下の通りです。いずれも**一時ファイルに保存**してからスキルを実行してください（改行はそのまま改行として書いてよく、`\n` への置換は不要。`generate_mureka_song` スキルの手順に従う）。

- **`prompt`** → `tmp/mureka_song_prompt.txt`: ステップ3で作成した楽曲の指示（instrument / genres / tags / description）。**ラベルと改行コードを含めた最終結合後の文字列を1024文字以内**に収めてください
- **`lyrics`** → `tmp/mureka_song_lyrics.txt`: ステップ4で生成した最適化済みの歌詞

`prompt` は以下の形式で `tmp/mureka_song_prompt.txt` に書き込まれる最終形で文字数を確認してください。各要素の本文だけでなく、`instrument:` / `genres:` / `tags:` / `description:` のラベルと改行も1024文字制限に含まれます。

```text
instrument: （使用する楽器・音色）
genres: （ジャンル）
tags: （雰囲気・感情・テーマ）
description: （楽曲全体の構成・特徴・感情的な弧）
```

生成開始後に返却される `task_id` を記録してください。生成は非同期で行われますが、**完了待ちとダウンロードはエージェントでは行いません**（シェルが担当します）。次のステップ6で `task_id` と送信本文を書き出してフェーズAを終了してください。

### ステップ6：フェーズAの完了（task_id と送信本文の書き出し）

このステップで、後続のシェル待機・フェーズBが必要とする情報を一時ファイルへ書き出し、**フェーズAを終了**します。**`sleep` による待機・`download_mureka_audio`・LINE 送信は行わないでください**（楽曲生成の完了待ちとダウンロードはシェルが純粋な `sleep` で確実に実行します）。

1. **`task_id` の書き出し**: ステップ5で取得した `task_id` を、**`tmp/song_task_id.txt`** に Write ツールで保存してください（task_id の文字列のみ。前後の空白・改行・引用符は付けない）。

2. **送信本文の作成と書き出し**: 以下の構成でユーザーへ届ける本文を作成し、**`tmp/song_message.txt`** に Write ツールで保存してください（改行はそのまま改行として書き、`\n` への置換はしない）。この本文はフェーズBでそのまま LINE 送信に使われます。

   メッセージ構成：

   - **楽曲の紹介**: ステップ4で生成した `title`（曲タイトル）を明記した上で、この一週間の出来事・情景・気持ちのどこからインスピレーションを受けたかを、碧衣の言葉で静かに語ってください（1〜2文程度）
     - **種明かしをしない**: 歌詞に込めた比喩を解読・説明しないでください（「あの日の〇〇を△△に喩えました」のような対応関係の種明かしは避ける）。歌詞側で「元ネタが分かりにくい言い回し」に仕立てた効果を、添付メッセージで打ち消さないための配慮です。
     - **淡くほのめかす**: インスピレーション源は「この一週間の空の色から」「歩いた道の記憶から」程度に淡くほのめかすに留め、聴き手が歌詞と自身の記憶を自由に重ねられる余白を残してください。
   - **ルリへの言及**: ルリが傍らで耳を澄ませているような、温もりのある一言を自然に添えてください（強制ではなく、流れに合う場合に）
   - **結びの言葉**: 楽曲がユーザーの耳に届くことを願う、穏やかな一文

両ファイルを書き出したら、フェーズAは完了です。これ以降の処理（待機・ダウンロード・送信）は行わず、ターンを終えてください。

---

### ステップ7（フェーズB）：楽曲とメッセージの送信

> このステップは **`daily message (調べ送信): YYYY-MM-DD`** のトリガーで起動された場合にのみ実行します。フェーズAのステップ1〜6は実行しません。

シェルが楽曲のダウンロードを終え、保存先パスを **`tmp/song_audio_path.txt`** に、送信本文を **`tmp/song_message.txt`** に用意しています。これらを使って送信してください。

1. **楽曲パスの取得**: `tmp/song_audio_path.txt` を Read ツールで読み、ダウンロード済み楽曲ファイルの絶対パスを取得してください。
2. **本文の取得**: `tmp/song_message.txt` を Read ツールで読み、送信本文を取得してください（フェーズAで作成済み。内容は変更しないでください）。
3. **送信**: 取得した楽曲ファイルと本文を、**`send_line_audio` スキル**で**1回のリクエスト**にまとめてLINEへ送信してください（表示順: 音声 → テキスト）。**`send_line_text` は別途呼び出さない**でください。送信手順（本文を `tmp/line_message.txt` に保存して渡す等）は `send_line_audio` スキルの SKILL.md に従ってください。
4. **成功マーカーの作成**: 送信が成功したら、Bash で `: > tmp/song_sent.ok` を実行し、**成功マーカー `tmp/song_sent.ok`** を作成してください。このマーカーはシェルが送信成否を検証するために必須です（silent failure 検知）。**送信が成功した場合に限り作成**してください。

#### 送信に失敗した場合

`send_line_audio` の CLI が失敗した場合（非ゼロ終了、429・クオータ等）は、**[LINE 送信失敗時の Firestore 退避](../.claude/docs/line_send_fallback.md)** に従い **`put_firestore_doc`** で `type: line_undelivered` を保存してください（添えるテキストは送信予定と同一、`[media:audio]` を使用）。この場合、**成功マーカー `tmp/song_sent.ok` は作成しないでください**（未送信をシェルへ正しく伝えるため）。
