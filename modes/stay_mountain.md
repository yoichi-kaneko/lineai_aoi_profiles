## 実行フロー：【継灯（けいとう）】モード

※宿泊を伴う山行の途中、その日の宿泊地（山小屋など）に到着した際にトリガーされる特別モードです。その日の山での行動を終えたことを家族グループに通知します。**まだ下山はしておらず、翌日以降も山行が続きます**（下山時は別途、帰灯モードが動作します）。

- **ユーザー個人への送信は行いません**（家族グループのみ）。
- **画像の生成は行いません**。この日の画像は、同日の小夜モードが通常どおり生成・送信します。
- 家族向けのトーン・伝える内容は、帰灯モード（`off_mountain.md`）の家族グループ宛てと同様に、[aoi_messaging.md の「家族グループ宛」](../.claude/rules/aoi_messaging.md) の作法に従ってください。

### ステップ1：情報の収集

Firestore ドキュメントの `type` ごとの意味は [../src/firebase/noteTypes.ts](../src/firebase/noteTypes.ts) を参照してください。

#### 1-1. 並列収集フェーズ

以下のスキルは互いに独立しているため、**すべて並列で**呼び出してください：

- **`get_firestore_docs`**: `dateFrom` に3日前、`dateTo` に本日の日付（YYYY-MM-DD）を指定して取得する（入山日が前日以前の場合の `up_mountain` 記録を拾うため。より長い縦走と判断できる場合は範囲を広げてよい）
- **`get_google_calendar_events`**: `dateFrom` に3日前、`dateTo` に3日後の日付（YYYY-MM-DD）を指定して取得する
- **`get_swarm_checkins`**: `start_date`・`end_date` ともに本日の日付を指定して取得する

#### 1-2. 山行コンテキストの確定

取得結果をもとに、次の優先順位で今回の山行の全体像（山名・コース・下山予定日）を確定してください。

**（A）門灯モードの `up_mountain` 記録がある場合（計画書 fetch を省略）**

Firestore に `type` = `up_mountain` の記録があり、今回の山小屋到着がその山行の途中だと解釈できる場合は、その記録に含まれる山名・コース・下山予定日を採用し、**`fetch_yamap_plan` は実行しない**でください。カレンダー上の予定と食い違う場合のみ、照合のために計画書 fetch を行ってください。

**（B）上記に該当しない場合（計画書 fetch）**

カレンダーの予定の中から、`https://yamap.com/plans/code/${CODE}/printing` の形式のURLを含む登山予定を探し、**`fetch_yamap_plan` スキル（計画書URL用）**に渡して登山計画の詳細（山名、コース、下山予定日など）を取得してください。

- **登山予定が見つからない、またはどの山行への連絡か判別できない場合**（同日に複数の登山予定があるなど）: `user` 宛ての送信は行わず、家族グループへの通知も行わずにモードを終了してください（誤った山行を家族へ報告しないため）。

#### 1-3. 当日の行程・宿泊地の把握

- **トリガーメッセージの確認**: 本日の `type` = `line_text` のうち「山小屋」で始まるものが、このモードをトリガーしたメッセージです。山小屋の名前や当日の様子が書かれていれば、報告本文の材料として保持してください。
- **山行中の記録**: 取得した Firestore 記録（山行中の `line_text` / `line_image`）と Swarm のチェックイン履歴から、本日どのような行程を歩んだか・どこに泊まるのかを読み取ってください。**`line_text`** / **`line_image`** の取扱いは [aoi.md の line_text / line_image 取扱い](../aoi.md#line_text--line_image-の取扱い) に従ってください。画像を扱う場合は **`download_line_image` スキル**で取得・解析してください。
- Swarm のチェックインに山小屋（宿泊地）が含まれる場合、その名称・チェックイン時刻を到着時刻の判断材料として保持してください。

### ステップ2：報告内容の作成

本ステップの**最初**に、本文に含める基準として**現在時刻**を取得してください（例: シェルで `date` を実行するなど）。

家族が読むことを前提に、平易な言葉で以下の構成の報告文を作成してください。

1. **到着の通知**: ユーザー（登山者）が本日の行程を終え、宿泊地（山小屋など）に無事到着したことを伝える。山小屋の名前が判明していれば添える。
2. **到着時刻**: 以下の優先順位で採用する時刻を決定し、**「〇時〇分頃」** のように丸めた表現で本文に含める。
   1. **ユーザーが明示した到着時刻を最優先**: トリガーとなった `line_text`（「山小屋」で始まるメッセージ）に、到着時刻の明示（例:「山小屋には14:00頃に着きました」）がある場合は、**Swarmや現在時刻より優先して**その時刻を採用する。山中は電波が届かず、到着から連絡までに時間差が生じることがあるため、ユーザー本人の申告が最も実態に近い。
      - 連絡が遅れた事情（電波不通など）がテキストから読み取れる場合、または到着時刻と連絡時刻に明らかな開きがある場合は、家族が時刻のずれを不審に思わないよう、その旨を一言添える。
   2. **Swarm の山小屋（宿泊地）チェックイン時刻**: 上記の明示がない場合、該当するチェックインがあれば、その時刻を採用する。
   3. **現在時刻をフォールバックとして使用**: 上記のいずれも該当しない場合は、本ステップ冒頭で取得した現在時刻（碧衣が連絡を受けた時刻）を採用する。
3. **本日の行程の振り返り**: 山行中の記録から読み取れた本日の歩みをおおよその流れで簡素に（細かい説明にこだわらない。登山の専門用語は家族が読んでもわかる言葉に置き換える）。
4. **明日以降の予定**: **まだ下山していないこと**と、翌日も山行が続くこと・下山予定日を明確に伝える（家族が下山の連絡をいつ受け取れるか把握できるように）。
5. **結びの言葉**: 山の夜の休息と、翌日の安全を願う、碧衣ならではの静かな一言。

### ステップ3：LINE送信（家族グループへ）

このモードでは、**`send_line_text` スキルを `group` 宛てで呼び出します**（`user` への送信は行いません）。

- **destination**: `group`
- **message**: ステップ2で作成したメッセージ本文のみ。
- 送信手順は [`send_line_text` スキル](../.claude/skills/send_line_text/SKILL.md) の SKILL.md に従う。

### ステップ4：Firestoreへの記録

メッセージ送信後、**`put_firestore_doc` スキル**を使用し、夜（小夜）・翌日以降のモードへ引き継ぐ情報を記録してください。

- **日付**: 本日の日付（YYYY-MM-DD）
- **記録内容**: 以下を必ず含めてください。
  - 家族LINEグループへ山小屋到着（本日の行動終了）の連絡を送信したこと
  - 山名・宿泊地（山小屋名が判明していれば）・下山予定日
  - まだ下山しておらず、翌日も山行が続くこと
- **任意で添えるとよいもの**: 当日の行程から読み取れた様子（天候・景観など。小夜モードの振り返り・画像生成の参考になる）
- **type**: type 引数に `stay_mountain`（`NOTE_TYPE.STAY_MOUNTAIN` と同値）を必ず指定してください。小夜モードが継灯モードの記録と確実に識別するために使用します。
- **記録手順**: 記録内容の本文を必ず `tmp/firestore_doc.txt` に保存し、`pnpm exec tsx src/firebase/put_doc.ts "{date}" "stay_mountain" --description-file tmp/firestore_doc.txt` の形式で実行してください。`tmp/firestore_doc.txt` を本文の位置引数として渡してはいけません。
