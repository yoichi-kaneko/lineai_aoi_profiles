# テスト

ルートの `src/` に対するテストを置く。`functions/` は独立したワークスペースパッケージのため対象外。

## 構成

```text
test/
├── fixtures/
│   └── yamap/
│       ├── ocr/            # 層1フィクスチャ（OCR結果のJSON）。コミットする
│       └── images/         # 層2フィクスチャ（レポート原画像）。コミットしない
├── tools/
│   └── dump_activity_ocr.ts  # 層1フィクスチャの生成ツール
└── yamap/
    ├── fixture.ts                 # フィクスチャ読み込み・再生用 ImageProbe
    ├── activity_crop.test.ts      # 層1
    └── activity_crop.e2e.test.ts  # 層2
```

## 2つの層

crop 処理の検証は OCR に依存する。2層に分ける理由は2つ。

- **原画像をコミットしたくない**（1枚あたり約10MB。ケースが増えるほどリポジトリが重くなる）
- **OCR が遅い**。1690x11020px の1枚で約22秒（実測）。ケースが増えるほど編集→実行のループが回しにくくなる

| | 層1 | 層2 |
|---|---|---|
| ファイル | `*.test.ts` | `*.e2e.test.ts` |
| 実行 | `pnpm test`（常時） | `pnpm test:e2e`（任意） |
| 入力 | 記録済みのOCR結果（JSON） | レポート原画像（PNG） |
| 所要時間 | 1秒未満 | 1枚あたり約20秒 |
| 役割 | **回帰防止の主役** | 実画像を通した最終確認 |

層1は OCR を実行しないため結果が決定的で、境界の座標を厳密一致で検証できる。

### 層1が画像なしで動く仕組み

境界検出のうち画素を要する判定（赤背景ボタンの除外・写真グリッドの開始位置）は
`ImageProbe` インターフェースへ切り出してある。層1は実画像の代わりに、
フィクスチャへ記録済みの応答を返す probe を注入する（`test/yamap/fixture.ts`）。

記録に無い問い合わせが来た場合、probe は既定値を返さず**例外を投げる**。
実装変更で問い合わせ内容が変わったことに気づけるようにするため。その場合はフィクスチャを再生成する。

## フィクスチャの追加手順

crop に失敗するレポートが新たに見つかったときは、以下の手順で対応する。
**「テストケースとして追加 → 全ケースで通るようロジックを調整する」**というのが本テストの運用方針。

1. **原画像を配置する**

   Todoist の登山レポートタスクの添付（1枚目＝レポートのスクリーンショット）を
   `test/fixtures/yamap/images/{名前}.png` へ保存する。

2. **層1フィクスチャを生成する**

   ```bash
   pnpm exec tsx test/tools/dump_activity_ocr.ts test/fixtures/yamap/images/{名前}.png {名前}
   ```

   OCR に20秒ほどかかる。`test/fixtures/yamap/ocr/{名前}.json` が生成され、
   あわせて**生成時点の境界検出結果**が標準エラーへ出力される。

3. **期待値を書く**

   手順2の出力が妥当か（切り出し範囲が正しいか）を確認したうえで、
   `test/yamap/activity_crop.test.ts` の `FIXTURE_CASES` へ追記する。

   > 失敗ケースを追加した直後は、期待値どおりにならず**テストが落ちるのが正しい**。
   > 出力をそのまま期待値にせず、「あるべき座標」を書くこと。

4. **層2のケースを追記する**

   `test/yamap/activity_crop.e2e.test.ts` の `IMAGE_CASES` へファイル名を追記する。

5. **ロジックを修正し、全ケースが通ることを確認する**

   ```bash
   pnpm test        # 層1（既存ケースのデグレードもここで検知される）
   pnpm test:e2e    # 層2
   ```

## 原画像をコミットしない理由と、その代償

レポート原画像は1枚あたり約10MB あり、ケースが増えるほどリポジトリが重くなるためコミットしない
（`.gitignore` で `test/fixtures/yamap/images/*` を除外）。

代償として、**画素ベースの判定そのもの**（`detectPhotoGridStartY` / `isRedButtonBackground`）は
層1では検証できず、記録済みの応答を再生するだけになる。これらのロジックを変更する場合は、
層2を実行して実画像で確認すること。

原画像が手元に無い環境では、層2のテストは失敗ではなく**スキップ**される。
